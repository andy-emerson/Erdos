# Signed Integers with a Header: Specification v0.1

Nov 1, 2026, revised after review and the author's two-round decision · Small calls marked **(coordinator's call)**. Reviewed in [`review-v0.1.md`](review-v0.1.md). Nothing is built or run. **Round 1** checks correctness; **round 2**, speed and memory, follows only if it passes.

## 1. Representation

A number is an **8-bit header** and a **word**, in two parallel lists so the header is never padded.

- **Header:** bits 0–4 class code $c$; bit 5 spare, 0; bits 6–7 direction $d$, a counter mod 4 for $1, i, -1, -i$ (paper v0.7, §2.3).
- **Word:** unsigned. For $c = 0$ it is the magnitude. For $c = 1..31$ it is a **slot index** into the pool whose slots are $2^c$ words, lowest first ($2^{c+6}$ bits at $W = 64$).
- **Canonical:** the smallest class that holds the value; zero is header 0, word 0.
- **Scope:** CPU; the little-endian layout reads as 32-bit halves. No GPU (none to test on). Sums across axes are a later spec, reported as an error (zero has no axis).

## 2. Operations

Add, subtract, multiply, exact division, gcd, compare and negate.

**Header arithmetic** on 8 bits, $D = \texttt{0xC0}$, then OR in the result class:
- multiply `(h1 and D) + (h2 and D)`; divide `(h1 and D) - (h2 and D)`; negate `h xor 0x80`;
- add, equal directions: $m_1 + m_2$, direction `h1 and D`;
- add, opposite: $\lvert m_1 - m_2 \rvert$ with borrow $b$ (the value $m_1 < m_2$), direction `(h1 and D) + (b shl 7)`;
- subtract adds the negation; gcd has direction 0; a zero result is header 0.

**Compare:** if directions differ, $d = 0$ is larger; both 0, compare magnitudes; both 2, compare magnitudes and reverse. Magnitudes compare by class, then words.

**Magnitude routines:** schoolbook, carries and borrows as values ($s < x$), Hensel division, binary gcd. Each reads each operand at its real length (one word for class 0, length 0 for zero; a slot up to its top nonzero word), writes at most its bound (add max + 1, multiply $n_1 + n_2$, absolute difference max, division $n_1 - n_2 + 1$, gcd min), and returns the result's length.

**Result class.** With $L = \max(c_1, c_2)$: equal-direction add $L+1$; opposite add $L$; multiply $L+1$; division $c_1$; gcd $\min(c_1, c_2)$, or the other's class if one is zero. The routine writes into a slot of that class (for class 0, a one-word local that becomes the inline word); if the result fits a smaller class, it moves to the smallest that holds it and the slot is released. A predicted class above 31 is an error.

**Pools.** The owner releases a value explicitly (values are immutable), pushing its slot onto the pool's free list, linked through freed slots' first words and ended by all ones. Allocation pops the free list, else takes the next slot, else doubles the pool, from one slot at first use **(coordinator's call)**. Indices survive growth, pointers do not, so the result slot is allocated first. Pools never shrink.

**Structures** (rule 4): stored, the slot; temporary, the predicted slot on a move-down; local, the one-word local, or the working buffer in division and gcd. The parallel lists count as one structure, pending the author (§5).

**Special cases**, named, not built: (a) a class-0 × class-0 product in registers, taking a slot only if its high word is nonzero; (b) equal-direction add allocating class $L$, moving up only on a carry.

## 3. Round 1: correctness

**The model:** Python, a test tool like spec 12's scripts, implementing §1 and §2 word by word at word size $W$. Python's integers serve only as the reference. Every operation, every case:
- **Exhaustive at small $W$:** $W = 4$, every pair of signed values below $2^8$ (two words; 261,121 pairs), covering carries, borrows, equal magnitudes, zero and moves across classes 0 to 2. Division takes $a = bq$ for every such $b \ne 0$, $q$. **(Coordinator's call:** $W = 8$ with two-word values would be 4 billion pairs.**)**
- **Random at $W = 64$:** 100,000 pairs per operation, lengths across classes 0 to 5, random directions, with zeros and equal magnitudes forced at 1/16 each. **(Coordinator's call.)**
- **Four axes:** multiply, divide and negate on all four directions, add and subtract within one axis, against Gaussian integers (integer pairs), exhaustively at $W = 4$. Adds across axes must report an error.

**It passes** when every result equals the reference and is canonical (smallest class, zero as header 0 word 0, spare bit 0), and after all releases every slot is on its pool's free list.

## 4. Round 2: speed and memory

Details wait for round 1. Savings show only at the machine level, where the borrow of one subtraction mod $2^{64}$ is the direction rule's input.

- **Header:** §2 as portable pseudocode (algorithm design rule 6; the borrow is the value $a < b$), then x86-64 machine code for the timed build.
- **Control:** spec 12's Growing ([`../12-integers/v0.1.md`](../12-integers/v0.1.md) §1.4) with the same header list; its word points to Growing's block.
- **Jobs:** $k \in \{1, 2, 4, 8, 16\}$ words, bit lengths uniform from $32k+1$ to $64k$, 1024 operations each, random directions; division and gcd as spec 12. A growth workload ($x \leftarrow xy + z$, 64 chains of 32 steps, one-word $y \ne 0$ and $z$) exercises pool reuse.
- **Correctness:** every result against Python, Control and the round-1 model.
- **Measures:** spec 12's timing method; bytes per value and peak; Header × Control only.
- **Known costs:** rounding up (to 2× bytes per value, plus the top-word scan, at most half a slot); pool management (callgrind's share, move-downs); the extra read per pool number; the opposite-direction branches.
