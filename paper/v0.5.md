## 1. Naive rational arithmetic

A rational number is a number that can be written as a fraction $\frac{p}{q}$, where $p$ and $q$ are integers and $q \neq 0$. The integer $p$ is the *numerator* and $q$ is the *denominator*. For example, $\frac{3}{4}$, $\frac{-2}{5}$ and $\frac{7}{1}$ are rational numbers.

A rational number is made of two integers, so a program that works with rationals works with integers underneath. Section 1.1 is about integers alone. Section 1.2 returns to rationals.

### 1.1 Integers

A computer stores an integer in base 2, as a fixed number of bits called its *width*. Common widths are 8, 16, 32 and 64 bits.

An *unsigned* integer uses all of its bits for the magnitude. With $w$ bits it holds every integer from $0$ to $2^w - 1$, so a 32-bit unsigned integer runs from $0$ to $4\,294\,967\,295$.

A *signed* integer spends a bit on the sign. With $w$ bits it holds every integer from $-2^{w-1}$ to $2^{w-1} - 1$, about half the unsigned maximum, so a 32-bit signed integer runs from $-2\,147\,483\,648$ to $2\,147\,483\,647$. An unsigned integer stores larger magnitudes in the same bits; a signed integer can also store negative numbers.

Integer addition, subtraction, multiplication, negation and comparison are taken as given for the rest of this paper. We are not trying to make them faster.

Their cost is stated in big-O, for integers of $n$ digits. Adding two $n$-digit integers takes $O(n)$ steps, and multiplying them takes $O(n^2)$. Comparing two $n$-digit integers for equality, or negating one, takes $O(n)$. For fixed-width machine integers each of these is a single instruction; the big-O describes integers too long to fit in one machine word.

### 1.2 Storing a rational number

A computer stores a rational number as a pair of integers, its numerator and its denominator. The most common layout is two signed integers of the same width. The running example in this paper is a signed 32-bit numerator next to a signed 32-bit denominator:

| Field | Type |
|---|---|
| numerator | signed 32-bit integer |
| denominator | signed 32-bit integer |

Other layouts and widths exist, such as 64-bit fields, or a signed numerator over an unsigned denominator, which forces the sign into the numerator. Each layout has trade-offs, and nothing in this paper depends on the choice. In every layout the denominator is never zero, and the number zero is stored as numerator $0$ over any nonzero denominator.

In pseudocode, `numerator(x)` and `denominator(x)` read the two stored integers of a rational `x`, and `n / m` builds the rational with numerator `n` and denominator `m`. Here `/` does not divide; it only pairs two integers.

**The sign.** In arithmetic, a minus sign belongs to the whole rational number. A negative numerator can be moved outside the fraction, and so can a negative denominator:

$$
\frac{-3}{4} = -\frac{3}{4} = \frac{3}{-4}.
$$

A computer has only the two integers, so the sign must live in one of them. Either one can carry it: $-\frac{3}{4}$ can be stored as $-3$ over $4$, or as $3$ over $-4$.

If both integers are negative, the two signs cancel:

$$
\frac{-3}{-4} = \frac{3}{4}.
$$

This is the only simplification used in this section. Because of it, it does not matter which integer carries the sign, and every operation below accepts either.

### 1.3 Addition and subtraction

To add two fractions, bring them over a common denominator:

$$
\frac{a}{b} + \frac{c}{d} = \frac{a \cdot d + c \cdot b}{b \cdot d}.
$$

Subtraction is addition with the second numerator negated:

$$
\frac{a}{b} - \frac{c}{d} = \frac{a}{b} + \frac{-c}{d}.
$$

The naive algorithm applies these formulas directly. In the pseudocode, `LET` gives a new name to a value.

```text
FUNCTION add(x, y)
    LET a = numerator(x)
    LET b = denominator(x)
    LET c = numerator(y)
    LET d = denominator(y)
    RETURN (a · d + c · b) / (b · d)
END FUNCTION

FUNCTION subtract(x, y)
    RETURN add(x, (−numerator(y)) / denominator(y))
END FUNCTION
```

Since `subtract` only calls `add`, everything below about addition applies to subtraction too.

#### Special cases

The naive formula always gives the right answer, but for some inputs it does more work than it needs to. From here on we move beyond the naive approach by accounting for special cases: inputs where some stored integers are equal up to sign, or zero, and a cheaper formula gives the same answer exactly.

The most important special case for addition is a shared denominator. If $b = d$, the two fractions already have a common denominator, and the numerators simply add:

$$
\frac{a}{b} + \frac{c}{b} = \frac{a + c}{b}.
$$

This needs one addition and no multiplication, so its cost drops from $O(n^2)$ to $O(n)$. The denominator of the result is the stored $b$, copied as it is.

*Example.* In $\dfrac{1}{5} + \dfrac{2}{5}$ the denominators are equal, so the result is

$$
\frac{1 + 2}{5} = \frac{3}{5}.
$$

If the denominators are opposite, $d = -b$, the sign of $d$ moves into its numerator and the denominators become shared:

$$
\frac{a}{b} + \frac{c}{-b} = \frac{a}{b} + \frac{-c}{b} = \frac{a - c}{b}.
$$

This also costs $O(n)$.

The other special cases are briefer. If one numerator is zero, that term is zero, and the sum is the other term. If the numerators are equal, $c = a$, the common factor $a$ can be pulled out:

$$
\frac{a}{b} + \frac{a}{d} = \frac{a \cdot d + a \cdot b}{b \cdot d} = \frac{a \cdot (d + b)}{b \cdot d}.
$$

If the numerators are opposite, $c = -a$, the same idea gives

$$
\frac{a}{b} + \frac{-a}{d} = \frac{a \cdot d - a \cdot b}{b \cdot d} = \frac{a \cdot (d - b)}{b \cdot d}.
$$

In subtraction, $\frac{a}{b} - \frac{a}{d}$ takes the second form and $\frac{a}{b} - \frac{-a}{d}$ the first.

Both forms need two multiplications instead of three, so they save one multiplication but stay $O(n^2)$.

The table lists the naive formula first and then every special case. In a row with $\pm$, read the upper sign everywhere or the lower sign everywhere. The cost includes the $O(n)$ equality check.

| Case | Condition | Result | Cost |
|---|---|---|---|
| Naive | always | $\dfrac{a \cdot d + c \cdot b}{b \cdot d}$ | $O(n^2)$ |
| Zero numerator | $a = 0$ or $c = 0$ | the other term | $O(n)$ |
| Shared denominator | $d = \pm b$ | $\dfrac{a \pm c}{b}$ | $O(n)$ |
| Equal or opposite numerators | $c = \pm a$ | $\dfrac{a \cdot (d \pm b)}{b \cdot d}$ | $O(n^2)$ |

The naive path now runs only after every check has failed, so it pays for those checks: a small $O(n)$ overhead on top of its $O(n^2)$.

In the pseudocode, `IF` compares two integers with `=`, and when they are equal, the line after `THEN` returns at once and the rest of the function is skipped. The special cases come first, in table order, and the naive formula is the final line.

```text
FUNCTION add(x, y)
    LET a = numerator(x)
    LET b = denominator(x)
    LET c = numerator(y)
    LET d = denominator(y)
    IF a = 0 THEN RETURN y
    IF c = 0 THEN RETURN x
    IF d = b THEN RETURN (a + c) / b
    IF d = −b THEN RETURN (a − c) / b
    IF a = c THEN RETURN (a · (d + b)) / (b · d)
    IF a = −c THEN RETURN (a · (d − b)) / (b · d)
    RETURN (a · d + c · b) / (b · d)
END FUNCTION
```

### 1.4 Multiplication

Numerators multiply, and denominators multiply:

$$
\frac{a}{b} \cdot \frac{c}{d} = \frac{a \cdot c}{b \cdot d}.
$$

The naive algorithm applies this formula directly.

```text
FUNCTION multiply(x, y)
    LET a = numerator(x)
    LET b = denominator(x)
    LET c = numerator(y)
    LET d = denominator(y)
    RETURN (a · c) / (b · d)
END FUNCTION
```

#### Special cases

The most important special case for multiplication is a cross match: one value's numerator equals the other value's denominator. If $c = b$, the same integer $b$ appears once on top and once on the bottom, and it cancels exactly:

$$
\frac{a}{b} \cdot \frac{b}{d} = \frac{a \cdot b}{b \cdot d} = \frac{a}{d}.
$$

The result is the two outer stored integers, $a$ over $d$. The match also works the other way round, when $a = d$:

$$
\frac{a}{b} \cdot \frac{c}{a} = \frac{c}{b}.
$$

A match up to sign cancels too, and leaves a factor of $-1$ in the numerator:

$$
\frac{a}{b} \cdot \frac{-b}{d} = \frac{-a}{d},
\qquad
\frac{-d}{b} \cdot \frac{c}{d} = \frac{-c}{b}.
$$

None of these forms needs a multiplication, so the cost drops from $O(n^2)$ to $O(n)$.

*Example.* In $\dfrac{2}{3} \cdot \dfrac{3}{5}$ the second numerator equals the first denominator, so the result is

$$
\frac{2}{5}.
$$

The other special cases are briefer. If either numerator is zero, the product is zero, and that factor is itself the answer. If both cross matches hold at once, the two values are reciprocals and the product is $1$:

$$
\frac{a}{b} \cdot \frac{b}{a} = 1.
$$

Since two negative signs cancel, the reciprocal of $\frac{a}{b}$ may also be stored as $\frac{-b}{-a}$, and the product is again $1$. If one value is $1$, its numerator equals its denominator, and the product is the other value. If one value is $-1$, its numerator is the negated denominator, and the product is the other value with its numerator negated: for $a = -b$ the result is $\frac{-c}{d}$, and for $c = -d$ it is $\frac{-a}{b}$.

Not every coincidence helps: a shared denominator, the main case for addition, saves nothing here, since $\frac{a}{b} \cdot \frac{c}{b} = \frac{a \cdot c}{b \cdot b}$ still needs both multiplications, and a shared numerator saves nothing either. Neither gets a row or a check.

| Case | Condition | Result | Cost |
|---|---|---|---|
| Naive | always | $\dfrac{a \cdot c}{b \cdot d}$ | $O(n^2)$ |
| Zero numerator | $a = 0$ or $c = 0$ | the zero factor | $O(n)$ |
| Reciprocals | $a = \pm d$ and $b = \pm c$ | $\dfrac{1}{1}$ | $O(n)$ |
| Cross match | $c = \pm b$, or $a = \pm d$ | $\dfrac{\pm a}{d}$, or $\dfrac{\pm c}{b}$ | $O(n)$ |
| Factor of $\pm 1$ | $a = \pm b$, or $c = \pm d$ | $\dfrac{\pm c}{d}$, or $\dfrac{\pm a}{b}$ | $O(n)$ |

As before, the naive path pays for every failed check, a small $O(n)$ overhead.

Reciprocals come before cross matches, because a reciprocal pair is also a cross match and would otherwise be caught there.

```text
FUNCTION multiply(x, y)
    LET a = numerator(x)
    LET b = denominator(x)
    LET c = numerator(y)
    LET d = denominator(y)
    IF a = 0 THEN RETURN x
    IF c = 0 THEN RETURN y
    IF (a = d AND b = c) OR (a = −d AND b = −c) THEN RETURN 1 / 1
    IF b = c THEN RETURN a / d
    IF b = −c THEN RETURN (−a) / d
    IF a = d THEN RETURN c / b
    IF a = −d THEN RETURN (−c) / b
    IF a = b THEN RETURN y
    IF a = −b THEN RETURN (−c) / d
    IF c = d THEN RETURN x
    IF c = −d THEN RETURN (−a) / b
    RETURN (a · c) / (b · d)
END FUNCTION
```

### 1.5 Division

Dividing by $\frac{c}{d}$ is multiplying by its reciprocal $\frac{d}{c}$, which exists only when $c \neq 0$:

$$
\frac{a}{b} \div \frac{c}{d} = \frac{a}{b} \cdot \frac{d}{c} = \frac{a \cdot d}{b \cdot c}, \qquad c \neq 0.
$$

The naive algorithm first checks for a zero divisor and stops with an error, then applies the formula.

```text
FUNCTION divide(x, y)
    LET a = numerator(x)
    LET b = denominator(x)
    LET c = numerator(y)
    LET d = denominator(y)
    IF c = 0 THEN ERROR "division by zero"
    RETURN (a · d) / (b · c)
END FUNCTION
```

#### Special cases

The most important special case for division is a shared part. In $\frac{a \cdot d}{b \cdot c}$ the two numerators $a$ and $c$ sit on opposite sides of the fraction bar, and so do the two denominators $b$ and $d$. So if the inputs share a numerator or share a denominator, that shared integer cancels exactly:

$$
\frac{a}{b} \div \frac{a}{d} = \frac{a \cdot d}{b \cdot a} = \frac{d}{b},
\qquad
\frac{a}{b} \div \frac{c}{b} = \frac{a \cdot b}{b \cdot c} = \frac{a}{c}.
$$

Cancelling $a$ is allowed because the zero-divisor check has already run: if $c = a$ and $c \neq 0$, then $a \neq 0$. Numerators that are opposite, $c = -a$, cancel too, and leave a factor of $-1$:

$$
\frac{a}{b} \div \frac{-a}{d} = \frac{-d}{b}.
$$

So do opposite denominators, $d = -b$:

$$
\frac{a}{b} \div \frac{c}{-b} = \frac{a \cdot (-b)}{b \cdot c} = \frac{-a}{c}.
$$

None of these forms needs a multiplication, so the cost drops from $O(n^2)$ to $O(n)$.

*Example.* In $\dfrac{2}{3} \div \dfrac{2}{7}$ the numerators are equal, so the result is the second denominator over the first:

$$
\frac{7}{3}.
$$

The other special cases are briefer. If the dividend's numerator is zero, the quotient is zero, and the dividend itself is the answer. If the stored integers match, $a = c$ and $b = d$, the quotient is $1$. If the divisor is $1$, that is $c = d$, the quotient is the dividend; if it is $-1$, that is $c = -d$, the quotient is the dividend with its numerator negated, $\frac{-a}{b}$. If the dividend is $1$, that is $a = b$, the quotient is the reciprocal of the divisor, $\frac{d}{c}$; if it is $-1$, that is $a = -b$, the quotient is $\frac{-d}{c}$.

| Case | Condition | Result | Cost |
|---|---|---|---|
| Naive | $c \neq 0$ | $\dfrac{a \cdot d}{b \cdot c}$ | $O(n^2)$ |
| Zero dividend | $a = 0$ | $\dfrac{a}{b}$ | $O(n)$ |
| Matching integers | $a = c$ and $b = d$ | $\dfrac{1}{1}$ | $O(n)$ |
| Shared part | $c = \pm a$, or $b = \pm d$ | $\dfrac{\pm d}{b}$, or $\dfrac{\pm a}{c}$ | $O(n)$ |
| Divisor $\pm 1$ | $c = \pm d$ | $\dfrac{\pm a}{b}$ | $O(n)$ |
| Dividend $\pm 1$ | $a = \pm b$ | $\dfrac{\pm d}{c}$ | $O(n)$ |

As before, the naive path pays for every failed check, a small $O(n)$ overhead.

The zero-divisor check stays first, as in the naive algorithm. Matching integers come before a shared numerator, which would otherwise catch them.

```text
FUNCTION divide(x, y)
    LET a = numerator(x)
    LET b = denominator(x)
    LET c = numerator(y)
    LET d = denominator(y)
    IF c = 0 THEN ERROR "division by zero"
    IF a = 0 THEN RETURN x
    IF a = c AND b = d THEN RETURN 1 / 1
    IF a = c THEN RETURN d / b
    IF a = −c THEN RETURN (−d) / b
    IF b = d THEN RETURN a / c
    IF b = −d THEN RETURN (−a) / c
    IF c = d THEN RETURN x
    IF c = −d THEN RETURN (−a) / b
    IF a = b THEN RETURN d / c
    IF a = −b THEN RETURN (−d) / c
    RETURN (a · d) / (b · c)
END FUNCTION
```
