# Skeletons: Exact Rationals by Common Divisors and by a Coprime Base, Specification v0.1

Oct 28, 2026 · draft for the author's review

This specification defines three implementations of exact rational arithmetic, built to be measured against one another, and a fourth, the ceiling, used only where every value shares one denominator. The two designs are explained in the working note [`../paper/note-skeletons.md`](../paper/note-skeletons.md), which is the source of truth; the notation $\nu_q$ is explained in [`../paper/note-coprime-base.md`](../paper/note-coprime-base.md). Where this text and the note disagree, the note wins and this text is corrected, except for the plain inefficiencies removed at the author's direction and listed in [§15.1](#151-plain-inefficiencies-removed), and the result reuse ruled on by the author in [§15.2](#152-result-reuse-in-both-designs), where the note is brought into line with this text. Choices this text makes that the note leaves open are collected in [§15](#15-choices-not-settled-by-the-design-note), so that the author's changes can be folded in one item at a time.

## 1. Scope

In scope: four implementations (the control, Design 1, Design 2 and the shared-denominator ceiling); their structures, operations, integer width, errors, instrumentation and correctness checks; and the boundary that says what each build contains.

Out of scope: performance targets, the workloads and the measurement rule (in [`research/rule.md`](research/rule.md)), comparison, printing and parsing, threads, and widths other than 32 and 64 bits.

## 2. Conformance language

The key words MUST, MUST NOT, REQUIRED, SHALL, SHALL NOT, SHOULD, SHOULD NOT, RECOMMENDED, MAY and OPTIONAL are to be interpreted as described in RFC 2119 when, and only when, they appear in capitals. Sections or paragraphs marked *non-normative* state no requirement.

## 3. Terms and notation

- **Width** $w$: the number of bits of every full-width integer, 64 or 32 (§4.3).
- **Value.** A rational $m/d$ with numerator $m$ and denominator $d \ge 1$. **Lowest terms:** $\gcd(m, d) = 1$, the sign on $m$, and $d > 0$. Zero is $0/1$.
- **Class.** One set of values that share structures. A program creates a class, enters values into it, and applies operations to values of the same class.
- **Handle.** The position of a value in its class's value list: a 32-bit unsigned integer.
- **Index.** A position in a list, a 32-bit unsigned integer. Denominator index $k$ means the same denominator in every structure of a class.
- **Stored.** A value is stored when it is appended to its class. A stored value is never changed. Every result is stored as a new value.
- **Entry.** Storing a value given from outside as an integer pair $(m, d)$. **Operation:** add, subtract, multiply or divide, on two stored values, storing the result.
- **Residual** of $d$ at a divisor $c$: $d / c$.
- **Piece**, **coprime base**, **valuation** $\nu_q(d)$: as in the coprime-base note. The pieces of a coprime base are pairwise coprime integers greater than 1, and $d = \prod_q q^{\nu_q(d)}$.
- **Gcd-first method:** reduced-rational arithmetic that takes the gcd of the two denominators before forming the sum, and takes cross gcds before forming a product (§6).
- $\text{bits}(x)$ is the number of bits of $|x|$; $\text{bits}(0) = 0$.
- **Island:** in Design 1, a denominator with no set pair bit. Every new denominator starts as an island; its incidence row holds column 0 and any facts inherited from the operation that produced it (§7.4).
- **Inherited row:** in Design 1, a pair $(k, \mu)$ given by an operation that knows its result's denominator is $e = d_k \cdot \mu$, with the integer $\mu$ already in hand (§7.4).

## 4. Requirements on every implementation

### 4.1 Interface

Each of the control, Design 1 and Design 2 MUST provide:

| Call | Effect |
| --- | --- |
| `create()` | a new, empty class |
| `destroy(class)` | frees the class and everything in it |
| `enter(class, m, d)` | stores $m/d$ in lowest terms; returns its handle, or an error |
| `add`, `sub`, `mul`, `div` `(class, x, y)` | stores the result of $x \circ y$; returns its handle, or an error |
| `read(class, x)` | returns the numerator and denominator of $x$, in lowest terms |
| `size(class)` | the number of stored values |
| `memory(class, report)` | fills the memory report of §12.2 |
| `counters(class, report)` | fills the counters of §12.1 (counting build) |
| `audit(class)` | the **full audit**: checks every invariant of §13.2; returns pass or the first failure (test build) |
| `audit_changed(class)` | the **incremental audit** of §13.2: checks only what changed since the last audit; returns pass or the first failure (test build) |

The ceiling's interface is in §9.

### 4.2 Values

1. Every stored value MUST be in lowest terms, with the sign on the numerator and a positive denominator.
2. Zero MUST be stored as $0/1$, whatever operation produced it.
3. Subtraction MUST be computed as addition of the negated second operand: $x - y = x + (-y)$. Negation changes no denominator.
4. `enter` MUST move the sign of $d$ to $m$ and reduce $m/d$ by $\gcd(m, d)$ before storing.
5. A stored value MUST NOT be modified, moved to another handle, or freed before its class is destroyed.

### 4.3 Width and integer routines

1. Every full-width integer (numerators, denominators, divisors, residuals, pieces, intermediates) MUST have one width $w$, chosen by a single build setting. The default MUST be 64; 32 MUST be supported by a rebuild with no change to source.
2. Numerators MUST lie in $[-(2^{w-1} - 1),\ 2^{w-1} - 1]$ and denominators in $[1,\ 2^{w-1} - 1]$. The most negative integer is excluded, so negation and absolute value never overflow.
3. An implementation MUST NOT use an integer wider than $w$ for any full-width intermediate. The lookup hash and index arithmetic (positions in lists, rows and the pair table, and the small numbers $\nu_q$) are not full-width arithmetic: the hash MUST use unsigned 64-bit wrapping arithmetic at every width, including $w = 32$ (§5), and positions MUST use unsigned integers of at least 32 bits.
4. All implementations MUST use one shared module of integer routines, and no other full-width arithmetic:
   - **gcd**: the binary method (removing common factors of 2 by counting trailing zeros, then subtracting), on magnitudes, with $\gcd(a, 0) = |a|$;
   - **checked add, subtract and multiply**, each reporting overflow (§4.4);
   - **exact division** of $a$ by a known divisor $b$ (the hardware divide);
   - **division with remainder** (the hardware divide), used for divisibility tests;
   - **bit routines**: popcount, highest set bit and trailing zeros of a 64-bit word, and $\text{bits}(x)$.
5. In the counting build (§12.1), every routine of item 4 MUST count its calls, by the counting rules of §12.1.

### 4.4 Overflow

1. Every full-width addition, subtraction and multiplication MUST be checked. A result outside the ranges of §4.3 item 2 MUST be reported as overflow. Overflow MUST NOT wrap silently.
2. On overflow the operation MUST return the overflow error, store no value, and record where it happened: the operation, the handles of its operands, and the step (named as in the pseudocode).
3. The class MUST remain valid after an overflow: every invariant of §13.2 holds. Changes made before the overflow that change no stored value (Design 1's recorded gcds, Design 2's splits) MAY remain.
4. The harness excludes a trial that reports any overflow from the comparisons. The measurement rule's workloads make overflow impossible, so it treats such an overflow as a bug (the rule says how).

### 4.5 Errors

1. `enter` with $d = 0$, and `div` with $y = 0$, MUST return the division-by-zero error and store nothing.
2. A handle not in the class MUST return the invalid-argument error.
3. Out of memory MUST print a message and abort.
4. Exceeding the limits of §14 MUST abort with a message.

### 4.6 Language and build

1. Each implementation MUST be written in C (C11), single-threaded, with no library beyond the C standard library.
2. All implementations MUST be compiled by the same compiler with the same flags.
3. There MUST be three builds of the same source, differing only in compile-time settings:
   - the **timing build**: counters and audits compiled out;
   - the **counting build**: counters compiled in, audits out;
   - the **test build**: counters and audits compiled in.
4. Counters and audits MUST NOT change the control flow or the results of any operation.

## 5. Shared structures: the lists, the lookup and `store`

Design 1 and Design 2 MUST keep the following three structures. The control keeps only a value list (§6), and the ceiling its vectors (§9).

| Structure | Shape | Each entry stores |
| --- | --- | --- |
| Numerators | list of $N$ | the numerator ($w$ bits) and its denominator index (32 bits) |
| Denominators | list of $D$ | the denominator ($w$ bits) |
| Lookup | array of $S$ slots | a denominator index, or empty |

1. **Lists.** A list MUST only grow at its end. An index, once given, MUST refer to the same entry for the life of the class. A handle is a position in the numerator list.
2. **Lookup.** The lookup MUST be a hash table of denominator indices with linear probing:
   - $S$ is a power of two, initially 16;
   - before an insertion would make the table more than half full, $S$ MUST double and every index MUST be placed again, in index order;
   - the starting slot of a value $v$ is $\lfloor (v \cdot \phi \bmod 2^{64}) / 2^{64 - \log_2 S} \rfloor$ with $\phi = \text{9E3779B97F4A7C15}_{16}$, computed with unsigned 64-bit wrapping arithmetic at every width, including $w = 32$ (this is index arithmetic, not a full-width operation, is allowed by §4.3 item 3, and is not overflow-checked);
   - a probe reads the index in a slot and compares the denominator list's value at that index; a slot holds an index, never a value; the search moves to the next slot, wrapping at the end, until it finds the value or an empty slot.
3. **Fast path.** When two operands have equal denominator indices, an operation MUST take the same-denominator path given in its pseudocode.

The procedure `store(n over e)` appends a result:

```text
function store(n over e)
    if n is 0 then
        set e to 1
        in Design 1, set F to empty                                 §7.4
        in Design 2, set R to empty, L to empty and u to 1          §8.3
    end if
    look e up
    if e is found at index k then
        append (n, k) to the numerators
    else
        append e to the denominators as index k
        place k in the lookup
        create the structures of the new denominator k        Design 1 §7.4 from F, Design 2 §8.3 from R and L, or R and u
        append (n, k) to the numerators
    end if
    return the handle of the new numerator
end function
```

The operation passes, with $n$ and $e$, what it knows about $e$: the inherited rows $F$ in Design 1 (§7.4); in Design 2 (§8.3), the known row $R$ and either the unknown part $u$ or the list $L$ of tested pieces from which `finish` derives the rest of $R$ and $u$. When the lookup finds $e$, they are discarded, `finish` is not run, and nothing is added to the existing row; they are used only to build the structures of a new denominator.

## 6. The control

The control stores each value as a pair $(m, d)$ in one value list, with no other structure. Its operations MUST be the gcd-first method below, and nothing more.

```text
function add(m_x over d_x, m_y over d_y)
    if d_x equals d_y then
        set t to m_x + m_y
        set h to gcd(t, d_x)
        return store((t / h) over (d_x / h))
    end if
    set g to gcd(d_x, d_y)
    if g is 1 then
        return store((m_x · d_y + m_y · d_x) over (d_x · d_y))
    end if
    set t to m_x · (d_y / g) + m_y · (d_x / g)
    set h to gcd(t, g)
    return store((t / h) over ((d_x / g) · (d_y / h)))
end function

function multiply(m_x over d_x, m_y over d_y)
    if d_x equals d_y then
        return store((m_x · m_y) over (d_x · d_x))
    end if
    set g_1 to gcd(m_x, d_y)
    set g_2 to gcd(m_y, d_x)
    return store(((m_x / g_1) · (m_y / g_2)) over ((d_x / g_2) · (d_y / g_1)))
end function

function divide(m_x over d_x, m_y over d_y)
    if m_y is 0 then
        fail with division by zero
    end if
    set s to the sign of m_y and t to |m_y|
    set g_1 to gcd(m_x, t)
    if d_x equals d_y then
        return store((s · (m_x / g_1)) over (t / g_1))
    end if
    set g_2 to gcd(d_x, d_y)
    return store((s · (m_x / g_1) · (d_y / g_2)) over ((d_x / g_2) · (t / g_1)))
end function
```

Here `store` (control) appends the pair, turning a zero numerator into $0/1$. The equal-denominator tests compare values, at the cost of one comparison.

## 7. Design 1: common divisors

Design 1 MUST be built in the note's **implementation form**: seven structures, as follows.

### 7.1 Structures

| Structure | Shape | Each entry stores |
| --- | --- | --- |
| Numerators, denominators, lookup | §5 | §5 |
| Divisors | list of $C$, strictly increasing; entry 0 is $1$ | a common divisor found so far ($w$ bits) |
| Pair table | the upper triangle of $D \times D$, 1 bit per cell, packed column by column | 1 if the pair has been compared |
| Incidence bits | $D$ rows of $W = \lceil C / 64 \rceil$ 64-bit words, one contiguous array with stride $W$ | bit $c$ of row $k$ is set if divisor $c$ is known to divide $d_k$ |
| Residual rows | one array per denominator, of varying length | the residuals $d_k / c$ for the set bits of row $k$, in column order |

1. **Pair table.** The bit for the pair $(i, j)$, $i < j$, is bit number $j(j-1)/2 + i$ of one bit array. Adding denominator $j$ appends its column of $j$ zero bits. There is no bit for $i = j$.
2. **Incidence bits.** Column 0 of every row MUST be set. When $C$ grows past $64W$, $W$ MUST grow by one word and the array MUST be copied to the new stride.
3. **Residual rows.** The residual for column $c$ of row $k$ is at position $\text{popcount}(\text{bits of row } k \text{ below column } c)$. A residual row's length MUST equal the number of set bits in its incidence row.
4. A set incidence bit, a residual and a set pair bit MUST never be removed or changed, except that residuals move within their row when one is inserted before them.

### 7.2 The search

```text
function search(i, j)
    for each word position from W − 1 down to 0 do
        AND word of row i with word of row j
        if the result is not 0 then
            return 64 · position + highest set bit of the result
        end if
    end for
end function
```

The returned column $col$ is that of the largest divisor known to divide both $d_i$ and $d_j$. Column 0 always qualifies. `residual(k, col)` reads row $k$'s residual at $col$ by popcount.

### 7.3 Compare and record

`compare(i, j)` returns the column of $\gcd(d_i, d_j)$ and the residuals of $d_i$ and $d_j$ at that column, recording the gcd if the pair has not been compared.

```text
function compare(i, j)
    set col to search(i, j)
    set r_i to residual(i, col)
    set r_j to residual(j, col)
    if pair bit (i, j) is set then
        return (col, r_i, r_j)                           the gcd, by §7.6
    end if
    set c to divisor[col]
    set g' to gcd(r_i, r_j)
    if g' is 1 then
        set pair bit (i, j)
        return (col, r_i, r_j)                           g is c
    end if
    set g to c · g'
    find g in the divisors by binary search
    if g is present then
        set col_g to its column
    else
        set col_g to the number of divisors below g
        insert g at column col_g, growing the stride W if C passes 64W
        if col_g is below the old C then
            shift every incidence row up by one bit from column col_g on
        end if
    end if
    set s_i to r_i / g' and s_j to r_j / g'              the residuals at col_g
    for each row k in i, j do
        if bit (k, col_g) is not set then
            set bit (k, col_g)
            insert s_k into residual row k at the position of column col_g
        end if
    end for
    set pair bit (i, j)
    return (col_g, s_i, s_j)
end function
```

Inserting a divisor below the old $C$ MUST shift the incidence rows at once; inserting it at the end shifts nothing, since no row has a bit at or above the old $C$. Insertion MUST NOT renumber anything else.

### 7.4 New denominators: islands with inherited rows

When `store` adds a new denominator $k$ with value $e$, it MUST:
- append an incidence row and a residual row, built from the inherited rows $F$ by `new row(e, F)` below;
- append pair-table column $k$, all zero.

$F$ is a list of at most two **inherited rows** $(k', \mu)$, each meaning that the operation knows $e = d_{k'} \cdot \mu$, with $\mu$ an integer it has already computed. $F$ is empty for entry and zero results. The operations give:

| Source | $F$ | Why $e = d_{k'} \cdot \mu$ |
| --- | --- | --- |
| entry; a zero result (§5) | empty | |
| addition and subtraction, same index | empty | $e = d_i / h$ divides $d_i$; it is new only when $h > 1$ |
| addition and subtraction, different indices, $h = 1$ | $(i, r_y)$, $(j, r_x)$ | $r_x, r_y$ are the residuals at $g = \gcd(d_i, d_j)$, so $e = r_x \cdot d_j = r_x r_y g = d_i \cdot r_y$ |
| addition and subtraction, different indices, $h > 1$ | empty | |
| multiplication, same index | $(i, d_i)$ | $e = d_i \cdot d_i$ |
| multiplication, different indices | $(i, d_j / g_1)$ if $g_2 = 1$; $(j, d_i / g_2)$ if $g_1 = 1$ | $e = (d_i / g_2)(d_j / g_1)$ |
| division, same index | empty | $e = t / g_1$ is part of a numerator |
| division, different indices, $g = 1$ (column 0) | $(i, t / g_1)$ | $r_x = d_i$ when $g = 1$, so $e = d_i \cdot (t / g_1)$ |
| division, different indices, $g > 1$ | empty | |

Each $\mu$ is a number the operation's pseudocode (§7.5) already computes; forming $F$ costs no gcd, no division and no multiplication.

```text
function new row(e, F)                                   F: at most two pairs (k, μ), each with e = d_k · μ
    set the new incidence row to column 0 only
    for each (k, μ) in F do
        OR row k into the new incidence row, word by word
    end for
    set the new residual row to [e]                      the residual at column 0
    for each set column c above 0 of the new row, in increasing order do
        set (k, μ) to the first pair in F whose row k has bit c set
        append residual(k, c) · μ to the new residual row
    end for
end function
```

1. **Each inherited fact is true and its residual exact.** If divisor $c$ is known to divide $d_k$, with residual $d_k / c$, and $e = d_k \cdot \mu$, then $c$ divides $e$ and $e / c = (d_k / c) \cdot \mu$: one multiplication, no division. Where both rows of $F$ hold column $c$, both products equal $e / c$, so the first is taken. Every product is at most $e$, so none can overflow; it is checked like every multiplication (§4.4).
2. **Residuals are read in order.** The residuals of row $k$ are read by walking its residual row alongside its set bits, not by a popcount per column.
3. **Only existing columns.** `new row` sets bits only at columns already in the divisor list. It MUST NOT insert a divisor, test a divisor for divisibility, or compute a gcd. In the counting build, its words ORed and residuals walked are counted as scans, its products as multiplications, and the row as an event (§12.1), all under `store`.
4. **What is not inherited.** When $h > 1$ in addition, $e$ is the lcm divided by $h$, and a known divisor of $d_i$ or $d_j$ need not survive the division: in $\tfrac{1}{18} + \tfrac{1}{30}$, divisor $6$ is in both rows, but $e = 45$. Likewise in multiplication when $g_2 > 1$, divisors of $d_i$ need not divide $d_i / g_2$, and in division when $g > 1$, divisors of $d_i$ need not divide $r_x$: in $\tfrac{5}{12} \div \left(-\tfrac{7}{18}\right)$, divisor $6$ of $12$ does not divide $e = 14$. Such facts are not recorded (§15.2).

A pair bit MUST be set only by `compare`, and `compare` MUST be called only by addition, subtraction and division on two operand denominators with $i \ne j$. Multiplication and `new row` MUST NOT set a pair bit. So a new denominator is an island: it has no pair bit until it is compared as an operand.

*Example* (non-normative), continuing the note's example, with rows named by their denominators, divisors $[1, 6]$, rows $12{:}\{1{:}12, 6{:}2\}$, $18{:}\{1{:}18, 6{:}3\}$ and $30{:}\{1{:}30, 6{:}5\}$ (written divisor:residual):
- $\tfrac{1}{12} + \tfrac{5}{18}$: $g = 6$, $r_x = 2$, $r_y = 3$, $h = \gcd(13, 6) = 1$. $F = [(12, 3), (18, 2)]$. The new row of $36$ is the OR of the two rows, columns 0 and 1, with residuals $36$ and $2 \cdot 3 = 6$: $\{1{:}36, 6{:}6\}$. Check: $6 \cdot 6 = 36$.
- $\tfrac{1}{18} + \tfrac{1}{30}$: $h = 2$, so $F$ is empty, and $45$ is $\{1{:}45\}$.
- $\tfrac{5}{18} \cdot \tfrac{7}{30}$: the search gives $c = 6$, $r_x = 3$, $r_y = 5$; $g_1 = \gcd(5, 5) = 5$ and $g_2 = \gcd(7, 3) = 1$. $F = [(18, 30/5 = 6)]$, and $108 = 18 \cdot 6$ is $\{1{:}108, 6{:}3 \cdot 6 = 18\}$.
- $\tfrac{1}{12} \div \tfrac{7}{5}$: $g = \gcd(12, 5) = 1$, $t / g_1 = 7$. $F = [(12, 7)]$, and $84$ is $\{1{:}84, 6{:}14\}$.
- $\tfrac{5}{12} \cdot \tfrac{7}{12}$: same index, $F = [(12, 12)]$, and $144$ is $\{1{:}144, 6{:}24\}$.

### 7.5 Operations

```text
function add(m_x over d_i, m_y over d_j)
    if i is j then
        set t to m_x + m_y
        set h to gcd(t, d_i)
        return store((t / h) over (d_i / h)), with F empty
    end if
    set (col, r_x, r_y) to compare(i, j)
    set g to divisor[col]
    set t to m_x · r_y + m_y · r_x
    if g is 1 then
        set h to 1
    else
        set h to gcd(t, g)
    end if
    if h is 1 then
        set F to [(i, r_y), (j, r_x)]                    e = d_i · r_y = d_j · r_x
    else
        set F to empty
    end if
    return store((t / h) over (r_x · (d_j / h))), with F
end function

function multiply(m_x over d_i, m_y over d_j)
    if i is j then
        return store((m_x · m_y) over (d_i · d_i)), with F = [(i, d_i)]
    end if
    set col to search(i, j)                               no compare, no pair bit
    set r_x to residual(i, col)
    set r_y to residual(j, col)
    set g_1 to gcd(m_x, r_y)
    set g_2 to gcd(m_y, r_x)
    set a to d_i / g_2 and b to d_j / g_1
    set F to empty
    if g_2 is 1 then
        add (i, b) to F                                   e = d_i · b
    end if
    if g_1 is 1 then
        add (j, a) to F                                   e = d_j · a
    end if
    return store(((m_x / g_1) · (m_y / g_2)) over (a · b)), with F
end function

function divide(m_x over d_i, m_y over d_j)
    if m_y is 0 then
        fail with division by zero
    end if
    set s to the sign of m_y and t to |m_y|
    set g_1 to gcd(m_x, t)
    if i is j then
        return store((s · (m_x / g_1)) over (t / g_1)), with F empty
    end if
    set (col, r_x, r_y) to compare(i, j)                 r_x = d_i / gcd(d_i, d_j), r_y = d_j / gcd(d_i, d_j)
    set T to t / g_1
    if col is 0 then
        set F to [(i, T)]                                 g is 1, so r_x = d_i and e = d_i · T
    else
        set F to empty
    end if
    return store((s · (m_x / g_1) · r_y) over (r_x · T)), with F
end function
```

### 7.6 Why the search is exact (non-normative)

If pair bit $(i, j)$ is set, $\gcd(d_i, d_j)$ was recorded in both rows when the pair was compared, and no bit is ever cleared; no common divisor exceeds the gcd; so the search's column is the gcd's. If the bit is not set, the column found is a common divisor $c$, and $\gcd(d_i, d_j) = c \cdot \gcd(d_i/c,\ d_j/c)$. Inherited facts (§7.4) are true divisibilities with exact residuals, so both arguments hold for rows built with them; they only make the column found for an uncompared pair larger.

## 8. Design 2: the coprime base

Design 2 MUST keep five structures.

### 8.1 Structures

| Structure | Shape | Each entry stores |
| --- | --- | --- |
| Numerators, denominators, lookup | §5 | §5 |
| Base | list of $C$ | a piece ($w$ bits); pieces pairwise coprime, each greater than 1 |
| Exponent rows | one array per denominator, of varying length | (piece index, $\nu_q(d)$) pairs, 32 bits each, sorted by piece index, for the pieces $q$ that divide $d$ |

1. The product of $q^{\nu_q(d)}$ over row $k$ MUST equal $d_k$. Every $\nu$ stored MUST be at least 1. The row of $d = 1$ is empty.
2. The skeleton keeps no list of which rows use a piece. A split MUST scan every row.
3. Pieces are never removed. When a piece splits, the first new piece takes its index and the others are appended to the base.

### 8.2 Refinement

`refine(R, u)` builds the exponent row of a new denominator $e = \text{value}(R) \cdot u$, where $R$ is a row already known over the current base (possibly empty) and $u \ge 1$ is the part not yet expressed. Entry calls it with $R$ empty and $u = e$.

```text
function refine(R, u)
    set rest to u and the new row to R
    set p to 0                                           the scan position
    while rest is not 1 and p is below C do              C is read at each test: splits append pieces
        set q to piece p
        set g to gcd(rest, q)
        if g is 1 then
            set p to p + 1
        else if g is q then
            divide rest by q as many times as it goes, counting k
            add k to ν_q in the new row
        else
            split(q, g)                                  the first new piece takes index p
        end if
    end while
    if rest is not 1 then
        append rest to the base as a new piece
        add (rest, 1) to the new row
    end if
    return the new row
end function

function split(q, g)                                     g is gcd(rest, q), with 1 < g < q
    set P to the coprime base of {g, q / g}, by pair refinement
    sort P in increasing order
    for each piece s in P do
        set ν_s(q) to the number of times s divides q
    end for
    the first piece of P takes q's index; append the others to the base
    for each row, including the new row, that holds the entry (q, t) do
        replace that entry by the entries (s, t · ν_s(q)) for s in P
        keep the row sorted by piece index
    end for
end function
```

1. **Pair refinement** of a list: while two entries $a$, $b$ have $h = \gcd(a, b) > 1$, replace them by $h$, $a/h$ and $b/h$; drop entries equal to 1 and merge duplicates. It uses gcds and exact divisions only. Refinement MUST NOT factor any number.
2. **One scan.** The scan MUST NOT restart at piece 0. After a division by $q$ it stays at $q$, since `rest` may still share part of $q$ (entering $12$ when $q = 6$ leaves $2$, which then splits $6$). After a split it stays at index $p$, which now holds the first new piece; the other new pieces are appended and are reached later in the same scan. So a piece is tested a second time only right after a division by it, and only once: `rest` is then coprime to it or splits it, since $q$ no longer divides `rest`. The pieces created by a split are tested when the scan reaches them. The pieces before $p$ need no second test: each was coprime to `rest` when tested, and `rest` only loses factors. The scan stops as soon as `rest` is 1 (§15.1).
3. The gcd found by the scan is the one used; it MUST NOT be computed a second time.
4. Splitting rewrites exponent rows; it MUST NOT change any stored value.

### 8.3 New denominators

When `store` adds a new denominator $e$, its row MUST be `refine(R, u)`, with $R$ and $u$ given by the operation or by entry. Addition, subtraction and multiplication with different indices pass, instead of $u$, the list $L$ of the pieces they tested for cancellation; `store` then first sets $(R, u)$ to `finish(R, L)`, and only for a new denominator:

| Source | $R$ | $u$ |
| --- | --- | --- |
| entry | empty | $e$ |
| addition and subtraction, different indices (§8.4) | the known valuations: $\max(\nu_q(d_i), \nu_q(d_j))$ where they differ; then, by `finish`, $a - k$ at each tested piece whose cancellation is $q^k$ | by `finish`: the product of the **leftovers**, $q^a / h$ for each tested piece whose cancellation $h$ is not a power of $q$; $1$ if there is none |
| addition and subtraction, same index | empty | $e = d_i / h$ |
| multiplication, different indices (§8.5) | the known valuations: $a + b$ at the pieces in both rows; then, by `finish`, $n - k$ at each tested piece whose cancellation is $q^k$ | by `finish`: the product of the leftovers, $q^n / h$ for each tested piece whose cancellation $h$ is not a power of $q$; $1$ if there is none |
| multiplication, same index | row $i$ with every $\nu$ doubled | $1$ |
| division, different indices (§8.6) | the valuations of $d_i / \gcd(d_i, d_j)$ | $t / g_1$, the part of the old numerator |
| division, same index | empty | $t / g_1 = e$ |
| a zero result (§5) | empty | $1$ |

```text
function finish(R, L)                                   L: entries (q, n, p, h), p = q^n, h = gcd of p and the numerator
    set u to 1
    for each (q, n, p, h) in L, in piece order do
        set k to power(h, q)
        if k is not none then
            add (q, n − k) to R if n − k > 0             keeping R sorted by piece index
        else
            multiply u by p / h                          a leftover: q is composite
        end if
    end for
    return (R, u)
end function

function power(h, q)                                    k if h = q^k, otherwise none
    set k to 0
    while h is not 1 do
        divide h by q with remainder
        if the remainder is not 0 then
            return none
        end if
        set h to the quotient and k to k + 1
    end while
    return k
end function
```

1. **Lookup first.** The test "$h$ is a power of $q$" matters only for building a new row, so it MUST be made in `finish`, after the lookup, and only when the lookup does not find $e$. When the lookup finds $e$, no power test is made (§15.1).
2. **$h = 1$ costs no division.** `power(1, q)` returns $0$ without dividing: $h = 1$ is $q^0$, recognized by one comparison. For $h = q^k$ with $k \ge 1$, `power` makes exactly $k$ divisions with remainder; when $h$ is not a power of $q$, it makes one more, the failing one, after its successful ones.
3. `finish` and `power` run inside `store`, and are counted there (§12.1).

Every operation with different indices reuses the valuations it already knows, and refines only what it does not know: the counterpart of Design 1's inherited rows (§7.4), allowed under the author's ruling (§15.2). When $u = 1$, no gcd is computed. When the lookup finds the denominator, its existing row is used and $R$, $L$ and $u$ are discarded.

### 8.4 Addition and subtraction

```text
function add(m_x over d_i, m_y over d_j)
    if i is j then
        set t to m_x + m_y
        set h to gcd(t, d_i)
        return store((t / h) over (d_i / h)), with R empty and u = d_i / h
    end if
    set r_x to 1, r_y to 1, R empty, "equal" empty and L empty
    walk rows i and j together; for each piece q with a = ν_q(d_i) and b = ν_q(d_j) do
        multiply r_x by q^(a − min(a, b))
        multiply r_y by q^(b − min(a, b))
        if a equals b then
            add (q, a, q^a) to "equal"                    a is not 0: the walk visits only pieces of a row
        else
            add (q, max(a, b)) to R
        end if
    end walk
    set t to m_x · r_y + m_y · r_x
    set e to d_i · r_y
    for each (q, a, p) in "equal" do
        set h to gcd(t, p)
        if h is not 1 then
            divide t by h, and e by h
        end if
        add (q, a, p, h) to L                             the power test waits for the lookup
    end for
    return store(t over e), with R and L                  finish(R, L) runs only for a new denominator
end function
```

1. A power $q^n$ MUST be formed by repeated multiplication, once per piece and call.
2. Only the pieces with $\nu_q(d_i) = \nu_q(d_j) > 0$ are tested. When there are none, no gcd is computed.
3. "$h$ is $q^k$" is tested by `power`, inside `finish`, only after the lookup has not found $e$ (§8.3). The result's valuations are known from the walk: $\nu_q(e) = \max(a, b)$ where $a \ne b$, and $a - k$ where $a = b$ and $h = q^k$. They MUST be reused, and only the leftovers are refined (§15.2). A zero sum gives $h = p$ at every equal piece; `store` then stores $0/1$ with $R$ and $L$ empty and $u = 1$, and runs no `finish` (§5).

### 8.5 Multiplication

```text
function multiply(m_x over d_i, m_y over d_j)
    if i is j then
        return store((m_x · m_y) over (d_i · d_i)), with R = row i with every ν doubled and u = 1
    end if
    set R empty, L empty, g_1 to 1, g_2 to 1
    walk rows i and j together; for each piece q with a = ν_q(d_i) and b = ν_q(d_j) do
        if a > 0 and b > 0 then
            add (q, a + b) to R                           nothing can cancel
        else
            if b > 0 then
                set (m, n, G) to (m_x, b, g_1)            a piece of d_j only
            else
                set (m, n, G) to (m_y, a, g_2)            a piece of d_i only
            end if
            set p to q^n
            set h to gcd(m, p)
            divide m by h, and multiply G by h            in place: m_x or m_y, g_1 or g_2
            add (q, n, p, h) to L                         the power test waits for the lookup
        end if
    end walk
    set e to (d_i / g_2) · (d_j / g_1)
    return store((m_x · m_y) over e), with R and L        finish(R, L) runs only for a new denominator
end function
```

1. Here $m_x$ and $m_y$ have already been divided by $g_1$ and $g_2$.
2. "$h$ is $q^k$" MUST be tested by `power` (§8.3), inside `finish`, only after the lookup has not found $e$: $h = 1$ is $q^0$ with no division; otherwise $h$ is divided by $q$ while the remainder is 0, stopping when it reaches 1.
3. **A composite piece.** When $h$ is not a power of its piece $q$, the result's denominator splits $q$. The valuations known at every other piece are kept in $R$, and only the leftover $q^n / h$ is refined, which splits $q$ (§15.2). (Base $[6]$: in $\tfrac{2}{1} \cdot \tfrac{1}{6}$, $h = \gcd(2, 6) = 2$ is not a power of $6$; $R$ is empty, the leftover is $3$, and refining it splits $6$ into $2$ and $3$; the result is $\tfrac{1}{3}$.)

### 8.6 Division

```text
function divide(m_x over d_i, m_y over d_j)
    if m_y is 0 then
        fail with division by zero
    end if
    set s to the sign of m_y and t to |m_y|
    set g_1 to gcd(m_x, t)
    if i is j then
        return store((s · (m_x / g_1)) over (t / g_1)), with R empty and u = t / g_1
    end if
    set r_x to 1, r_y to 1, and R empty
    walk rows i and j together; for each piece q with a = ν_q(d_i) and b = ν_q(d_j) do
        multiply r_x by q^(a − min(a, b))
        multiply r_y by q^(b − min(a, b))
        if a > min(a, b) then
            add (q, a − min(a, b)) to R
        end if
    end walk
    return store((s · (m_x / g_1) · r_y) over (r_x · (t / g_1))), with R and u = t / g_1
end function
```

Only $t / g_1$, part of the old numerator, is new to the base.

## 9. The shared-denominator ceiling

The ceiling is a reference point for workloads in which every value shares one denominator. It is not a contender.

1. **Form.** A **vector** is a common denominator $E \ge 1$ and numerators $n_1, \ldots, n_L$; element $k$ is $n_k / E$. A vector is in **canonical form** when $\gcd(E, n_1, \ldots, n_L) = 1$; the all-zero vector has $E = 1$. For the ceiling, "every stored value in lowest terms" (§4.2) means: every stored vector is in canonical form, and `read` returns each element in lowest terms.
2. **Interface.** `create`, `destroy`; `enter_vector(class, m[], d)`, every element over one $d$; `gather(class, v, positions[])`, a new vector of chosen elements of $v$, used only as an operand: a **working copy**, not a stored value (§12.2); `add`, `sub`, `mul`, `div` `(class, v_x, v_y)` elementwise on vectors of equal length; `read(class, v, k)`; `memory`; `counters`.
3. **Canonical form** is restored after every operation by `content`: compute $\gcd(E, n_1, n_2, \ldots)$, stopping when it reaches 1, and divide $E$ and every $n_k$ by it.
4. **Operations:**
   - **add, subtract:** $g = \gcd(E_x, E_y)$; $E = E_x \cdot (E_y / g)$; $n_k = x_k \cdot (E / E_x) \pm y_k \cdot (E / E_y)$; then `content`.
   - **multiply:** $n_k = x_k \cdot y_k$ over $E_x \cdot E_y$; then `content`.
   - **divide:** each element's reduced quotient $p_k / q_k$ by the control's `divide` (§6); $E$ is the lcm of the $q_k$, built one element at a time with a gcd; $n_k = p_k \cdot (E / q_k)$; then `content`. A zero element of $v_y$ is a division-by-zero error for the whole operation.
   - **read:** $n_k / E$ reduced by $\gcd(n_k, E)$.
5. It MUST use the shared integer routines, width and overflow rules of §4.3–4.4. Overflow fails the whole vector operation.
6. It MUST be plain loops over the numerators, with no other structure.

## 10. The skeleton's boundary

Each build MUST be an accurate representation of the skeleton: the plainest correct form of each design. Bugs and plain inefficiencies inside the skeleton are fixed. Nothing outside it is added.

**Inside the skeleton:**
- one fixed integer width, 64 bits, set in one place, with overflow detected; schoolbook arithmetic;
- the same gcd and division routines in both designs, in the control and in the ceiling;
- the denominator lookup: a hash table of indices, with linear probing, growing when half full;
- Design 1's 1-bit pair table, packed column by column; 1-bit incidence rows with AND, highest set bit and popcount; residual rows;
- sorted insertion of divisors with immediate shifting (Design 1);
- testing every piece at entry (Design 2);
- **result reuse, in both designs:** a new result denominator's structures record what the operation already knows of it, with no new gcd: inherited rows in Design 1 (§7.4); the known valuations, with only the unknown part refined, in Design 2 (§8.3);
- lazy work only: nothing is computed until an operation needs it.

**Outside the skeleton** (possible later improvements, MUST NOT be built):
- threading, GPUs, SIMD intrinsics and batching in phases;
- background (eager) comparisons;
- linking a new divisor to every other denominator it divides (Design 1);
- recording about a result's denominator more than §7.4 and §8.3 give: divisibility tests of known divisors, new divisors formed from the operation's quantities, or facts added to an existing denominator's row (Design 1); facts added to an existing denominator's row (Design 2);
- the index-valued pair table (Design 1);
- deferred re-sorting of divisors (Design 1);
- an index that limits which pieces a new denominator is tested against (Design 2);
- caching residual products, cofactors or powers of pieces (Design 2);
- a list of the rows that use each piece (Design 2);
- caching gcds or cofactors in the control;
- cluster maintenance;
- integers wider than $w$, p-adic methods, BLAS, fast multiplication.

## 11. Instructions to builders and reviewers

These instructions MUST be given, verbatim, to every builder and every reviewer:

Fix bugs and plain inefficiencies inside the skeleton (§10); add nothing outside it: no threading, batching, background comparisons, cached cofactors, BLAS, or any other item of the "outside" list. Where the specification is unclear, ask the author; do not decide. Record every fix of a plain inefficiency in the change log, with the reason, and show that it changes no structure and no result.

## 12. Instrumentation

### 12.1 Counts

In the counting build, each implementation MUST count, separately for each **phase** (entry, add, subtract, multiply, divide) and, within an operation, separately for its **core** (everything before `store`) and its **store** (lookup, append and the new denominator's structures):

| Counter | Counts |
| --- | --- |
| gcds | calls of the shared gcd, with a histogram of $\text{bits}$ of the larger operand (bins 0 to 64) and the sum of those bits (the **gcd work**) |
| divisions | exact divisions and divisions with remainder |
| multiplications | full-width multiplications |
| additions | full-width additions and subtractions |
| lookups | lookup searches, slot probes, and pair-bit reads (Design 1) |
| scans | Design 1: words ANDed in searches, words popcounted, and words ORed and residuals walked by `new row`; Design 2: row entries walked in merges, pieces tested in `refine`, rows visited in splits; ceiling: numerators visited by `content` |
| refinements | Design 1: divisors inserted, words shifted, stride growths; Design 2: splits, pieces created, row entries rewritten |
| events | Design 1: compares (pair bit not set), pair-bit hits, new rows built with inherited rows, and facts inherited; Design 2: rows built with $u = 1$ and rows needing refinement; all: same-index fast paths, new denominators, overflows |

**Counting rules.** Every implementation MUST count the following cases in exactly this way:
1. **The sign.** Multiplying by the sign $s$ of $m_y$ in division is not counted.
2. **Repeated division.** "Divide rest by $q$ as many times as it goes" counts one division with remainder per attempt, including the final attempt that fails. `power(h, q)` (§8.3) counts one division with remainder per attempt it makes: none for $h = 1$, $k$ for $h = q^k$, and its successful attempts plus the failing one otherwise; it is counted under `store`, and only for a new denominator.
3. **The gcd.** A gcd counts as one gcd, entered in the histogram with its operand sizes. The subtractions, shifts and trailing-zero counts inside it are not counted as additions, divisions or bit routines.
4. **Index arithmetic and hashing.** Arithmetic on positions, on the pair-bit number $j(j-1)/2 + i$, on the small numbers $\nu_q$, and the lookup hash are not counted as additions or multiplications. They are counted as lookups: one lookup search per hash computed, one probe per slot read, and one pair-bit read per pair bit read.

The counters MUST be readable at any time, and MUST be reset only by `create`.

### 12.2 Memory

`memory` MUST report, for every structure, the **used bytes** (entries times entry size, plus every per-row header) and the **allocated bytes** (capacity). The structures and their entry sizes at $w = 64$:

| Implementation | Structure | Used bytes |
| --- | --- | --- |
| all but the ceiling | numerators | $12N$ ($16N$ for the control's pairs) |
| Designs 1, 2 | denominators | $8D$ |
| Designs 1, 2 | lookup | $4S$ |
| Designs 1, 2 | divisors or base | $8C$ |
| Design 1 | pair table | $8 \lceil D(D-1)/128 \rceil$ |
| Design 1 | incidence bits | $8 D W$ |
| Design 1 | residual rows | $8 \times$ (set incidence bits) + headers |
| Design 2 | exponent rows | $8 \times$ (row entries) + headers |
| ceiling | stored vectors | $8 \times$ (numerators) + $8$ per vector + headers, over entered and result vectors only |

A per-row or per-vector header MUST be counted at its real size and SHOULD be at most 16 bytes. **Bytes per rational** is the total used bytes divided by the number of stored values $N$. For the ceiling, $N$ is the number of elements of its stored vectors (entered and result vectors); a gathered working copy (§9) is not a stored value, and neither its elements nor its bytes are counted. Allocated bytes per rational is reported beside it.

### 12.3 Timing

The harness times phases; the implementations hold no timers. The harness MUST time entry, operations and read-out separately, with a monotonic clock read only between calls, never inside one.

## 13. Correctness

### 13.1 Against an exact reference

Every stored value of every run MUST be read out and compared with an exact reference computed with arbitrary-precision rationals, independently of the shared integer routines: numerator and positive denominator, both in lowest terms, must be equal. Any mismatch fails the run for that implementation.

### 13.2 Invariants

`audit` MUST check, in the test build:

- **All:** every stored value is in lowest terms with a positive denominator; zero is $0/1$.
- **Designs 1 and 2:** every denominator index is found by the lookup at its value; the lookup holds exactly $D$ indices and is at most half full; the denominator list has no duplicates.
- **Design 1:**
  - the divisors are strictly increasing, and divisor 0 is 1;
  - bit 0 of every incidence row is set, and no bit at or above column $C$ is set;
  - each residual row's length equals its row's popcount;
  - for every set bit at column $c$ of row $k$: $c \cdot \text{residual} = d_k$;
  - for every set pair bit $(i, j)$: the divisor at `search(i, j)` equals $\gcd(d_i, d_j)$.
- **Design 2:**
  - the base pieces are pairwise coprime and each greater than 1;
  - every row is sorted by piece index, with every $\nu \ge 1$ and every index below $C$;
  - the product of $q^{\nu_q(d)}$ over each row equals its denominator.
- **Ceiling:** every vector is in canonical form.

`audit_changed` MUST make the same checks, restricted to what changed since the last audit (full or incremental):
- **All:** the values stored since then.
- **Designs 1 and 2:** the denominators added since then, each found by the lookup at its value; the lookup's count and load.
- **Design 1:** each divisor inserted since then, against its two neighbours; the rows created since then, inherited facts included, and the rows that gained a bit or a residual (not rows only shifted by an insertion, which the next full audit checks), each in full; the pair bits set since then.
- **Design 2:** each piece created or rewritten since then, against every other piece (greater than 1 and coprime to each: $C$ gcds per such piece); each row created or rewritten since then, in full.
- **Ceiling:** the vectors stored since then.

The test build records what changed in a change list that only the audits read; recording it MUST NOT change any result (§4.6 item 4).

### 13.3 Tests

1. Unit tests MUST cover: every worked example of the design note, with the stated intermediate structures; zero operands and zero results in every operation; negative numerators; division by zero; equal-index fast paths; a denominator of 1; an overflow in each operation; a split of a composite piece during multiplication (the base $[6]$ case, refining only the leftover) and during addition (a leftover at a piece of equal valuation); a refinement whose scan stays at a piece after dividing by it (entering $12$ over the base $[6]$); in Design 2, a result of addition and one of multiplication whose denominator the lookup finds, checked to make no power test, and a tested piece with $h = 1$, checked to cost no division; in Design 1, every row of the table of §7.4, each case with $F$ empty checked to set no bit beyond column 0, two inherited rows sharing a column, and a result found by the lookup, whose existing row is unchanged; and the examples of §7.4.
2. **The gate.** Every job of the measurement rule MUST pass, in the test build and before any measured run, one complete run (entry, operations and read-out) audited on this schedule. Every call that stores a value counts: `enter`, `enter_vector` and the operations, so **entries are audited**, on the same schedule as operations.
   - a full audit (`audit`) after each of the first 200 calls of the job;
   - then a full audit after every 64th call (calls 256, 320, 384, …);
   - a full audit after the last call.

   Between full audits, the test build MAY run `audit_changed` after every call.

   **Large base (Design 2).** Once Design 2's base has more than **1,024 pieces** (**PROPOSED** in the rule), every scheduled full audit except the one after the last call MUST check pairwise coprimality of the base only incrementally, and `audit_changed` MUST then run after every call: each piece created or rewritten by the call is checked against every other piece (§13.2). Every other check of those full audits is made in full, and the full audit after the last call is complete, the pairwise check included. So no full audit but the last takes more than $1{,}024 \cdot 1{,}023 / 2 = 523{,}776$ coprimality gcds, and every pair of pieces is still checked, when the later of the two was created or last rewritten (pieces change only by a split, which rewrites them).
3. The 32-bit build MUST pass the unit tests.

*Non-normative: the gate's cost.* A job of $n_c$ calls gets about $200 + n_c / 64$ full audits: about 670 for the rule's 30,000-call jobs. Every full audit is linear in the structures (values, lookup, Design 1's rows and pair bits, Design 2's rows, the ceiling), a few milliseconds each, a few seconds per job, except Design 2's pairwise-coprime check, $C(C-1)/2$ gcds of pieces: 1.5 to 3 s at $C = 10^4$ (30–60 ns per gcd). Done at every full audit, it would cost 3 to 30 minutes on a job whose base reaches $10^4$ pieces or more; with the large-base rule above, it costs at most about 16–31 ms per full audit, and the incremental checks about $C^2/2$ gcds over a job, plus one complete check at the end: a few seconds per job, under 15 s at $C = 1.5 \times 10^4$. The rule's estimate gives the total over its run plan.

## 14. Limits

Fewer than $2^{32} - 1$ stored values, denominators, divisors and pieces per class; exceeding them aborts (§4.5).

## 15. Choices not settled by the design note

Each item is a choice this specification makes where the note is silent or leaves room. The author may change any of them; each is local to the sections named.

- **G-1** (§4.2, §5, §6). A zero result is stored as $0/1$ by `store`, as the note now states for addition in both designs; in Design 2, `store` then also sets $R$ to empty and $u$ to 1.
- **G-2** (§4.3). Numerators exclude $-2^{w-1}$; denominators are signed and at most $2^{w-1} - 1$.
- **G-3** (§4.3). No full-width intermediate wider than $w$; overflow of any intermediate is overflow, even when the reduced result would fit. The lookup hash is index arithmetic and uses unsigned 64-bit arithmetic at both widths.
- **G-4** (§4.3). The shared gcd is the binary method.
- **G-5** (§5). The lookup's hash multiplies the value by a fixed odd 64-bit constant (about $2^{64}$ divided by the golden ratio) and keeps the top $\log_2 S$ bits, rather than taking the value mod $S$, which clusters on denominators with many factors of 2; initial $S = 16$.
- **G-6** (§4.6). Three builds of one source; timing runs carry no counters.
- **C-1** (§6). The control tests equal denominators by value comparison in all three operations, as the note says plain rationals can.
- **D1-1** (§7.1). Incidence rows are one contiguous array, growing one word of stride at a time.
- **D1-2** (§7.3). A recorded residual is computed as the residual at $c$ divided by $g'$, as the note says.
- **D2-1** (§8.2). `refine` makes one scan of the base: it stays at a piece after dividing by it or splitting it, and never restarts at piece 0. The note's cost table agrees ("one scan of the base, at most $C + \tau$ gcds plus one per piece created by a split"); restarting at piece 0, as an earlier draft of the note did, is a plain inefficiency, removed at the author's direction (§15.1).
- **D2-2** (§8.2). A split refines $\{g, q/g\}$ by pair refinement; the new pieces are sorted increasingly, and the smallest keeps $q$'s index.
- **D2-3** (§8.3–8.6). Every operation with different indices reuses the valuations it knows and refines only the rest: multiplication (the rows added, less the cancellation), division (the valuations of $d_i / \gcd(d_i, d_j)$, $u = t/g_1$), and addition and subtraction (the maximum of the two valuations, less the cancellation). Where a cancellation is not a power of its composite piece, only the leftover $q^n/h$ is refined. Allowed under R-1, with Design 1's counterpart D1-3 (§15.2).
- **D1-3** (§7.4, §7.5). A new result denominator inherits the incidence and residual rows of an operand denominator $d_k$ whenever the operation knows $e = d_k \cdot \mu$ with $\mu$ in hand, multiplying each residual by $\mu$; only existing columns, no gcd, no division, no pair bit. Required under R-1 (§15.2).
- **R-1** (§7.4, §8.3, §10). **The author's ruling, Oct 28, 2026, refined the same day.** Reusing what an operation already knows about its result's denominator is allowed only as an optimization that **both designs can use**, and only where **a production implementation would actually use it**: cheap, generally useful facts, never ones that help only this test implementation. So both designs reuse, each from its own structures, and neither does extra gcd work: Design 2 keeps the valuations its walk computed and refines only the unknown part (D2-3); Design 1 inherits operand rows (D1-3). Facts that fail the criterion are left out (§15.2).
- **D2-4** (§8.4, §8.6). The same-index paths of addition and division refine the result's denominator from scratch, since the cancellation $h = \gcd(t, d_i)$ is not split over the pieces; that of multiplication doubles row $i$, as the note says.
- **D2-5** (§8.4, §8.5). Powers of pieces are formed by repeated multiplication; per-piece gcds in multiplication use the numerator as already divided.
- **D2-6** (§8.1). Row entries are two 32-bit fields, 8 bytes, as in the note's memory formula.
- **K-1** (§9). The ceiling's "lowest terms" is canonical form of the vector as a whole, with elements reduced on read; its division forms the lcm of the quotients' denominators.
- **M-1** (§12.2). Bytes per rational uses used bytes, with allocated bytes reported beside it; per-row headers are counted. The ceiling counts only its stored vectors, never gathered working copies.
- **I-1** (§12.1). Counts are split into entry and the four operations, and within an operation into core and store, so a result's entry cost (Design 2's refinement of a new result denominator) is visible inside the operation.
- **I-2** (§12.1). The counting rules: the sign is not counted; repeated division counts every attempt, the failing one included; a gcd counts once, its inner steps not at all; index arithmetic and the hash count as lookups, never as arithmetic.
- **T-1** (§4.1, §13.2, §13.3). The gate audits in full after each of the first 200 calls, then after every 64th call and after the last; entries count as calls. Between full audits an incremental audit MAY run after every call.
- **T-2** (§13.3). **PROPOSED.** Once Design 2's base has more than 1,024 pieces, the scheduled full audits before the last check pairwise coprimality only incrementally, with `audit_changed` after every call; the last full audit is complete.
- **B-1** (§10). The "outside" list of §10 adds to the note's list, so that builders cannot read these as allowed: SIMD intrinsics; the index-valued pair table (Design 1), deferred to a later test; caching cofactors or powers of pieces, not only residual products (Design 2); a list of the rows that use each piece (Design 2), which the note mentions only as absent from the skeleton; caching gcds or cofactors in the control; and integers wider than $w$.

### 15.1 Plain inefficiencies removed

At the author's direction, the following repeated work, found in the procedures of the design note or of the earlier draft of this text, is removed. None changes a stored value, a structure or what is recorded; each removes only computation whose result was already known within the same call, could not change, or was not used. The note is in line with every item. Result reuse, formerly D2-c here, records more than before, so it is not a plain inefficiency; it is in §15.2.

- **D2-a** (§8.2). `refine` no longer restarts at piece 0 after each division or split: one scan, staying at a piece after dividing by it or splitting it, testing again only pieces created by a split.
- **D2-b** (§8.2). `refine` stops scanning as soon as `rest` is 1, instead of testing the remaining pieces against 1.
- **D2-d** (§8.2). The gcd that the scan finds is used, not computed a second time ("find a piece with $\gcd(\text{rest}, q) \ne 1$", then "set $g$ to $\gcd(\text{rest}, q)$").
- **D2-e** (§8.4). Each power $q^a$ of an equal piece is formed once and kept with the piece, not formed again for the gcd.
- **D2-f** (§8.3–8.5). In addition, subtraction and multiplication, the test "$h$ is a power of $q$" is made after the lookup, by `finish`, and only for a new denominator, since its result serves only to build the new row; and $h = 1$ is recognized as $q^0$ with no division attempt.
- **D1-a** (§7.3, §7.5). `compare` returns the residuals at the gcd's column, which it already knows ($r_k / g'$, or the residuals it read), so addition and division do not read them again by popcount.
- **D1-b** (§7.3). When $g' = 1$, `compare` sets the pair bit and returns at once, with no binary search and no row test: $g$ is $c$, already recorded in both rows.
- **D1-c** (§7.3). A divisor inserted at the end of the list (above every divisor) shifts no row, since no row has a bit at or above the old $C$.

Nothing in the control or the ceiling was found to repeat work.

### 15.2 Result reuse, in both designs

Under the author's ruling R-1 (Oct 28, 2026), an operation's knowledge of its result's denominator is reused only as an optimization that both designs use, and only in a form that a production implementation would actually use: cheap and generally useful, not contrived for this test. Each design reuses what its own structures already hold, at a new denominator only, and neither computes a gcd to do it. The note is in line with both items.

- **D2-c** (§8.3–8.6). Addition, subtraction, multiplication and division with different indices pass the valuations their walk computed as $R$, and only the unknown part as $u$: the leftovers at composite pieces, or $t / g_1$ in division. Multiplication with the same index doubles row $i$. Passes the criterion: the valuations come out of a walk the operation makes anyway, and a production coprime-base implementation would not throw them away.
- **D1-d** (§7.4). A new result denominator $e = d_k \cdot \mu$ inherits row $k$, each residual times $\mu$: in addition with $h = 1$ (both rows), in multiplication with $g_2 = 1$ or $g_1 = 1$ (one row each) and with the same index (row $i$, $\mu = d_i$), and in division with $g = 1$. Passes the criterion: one rule, one OR per word and one multiplication per inherited fact, and it applies in the common cases (coprime pairs, sums that do not cancel, products that cancel on one side), where it makes later searches on results start from a larger common divisor.

**Left out by the criterion** (outside the skeleton, §10). Facts that would need extra work or hold only in narrow cases:
- in multiplication with $g_1 > 1$ and $g_2 > 1$, the fact that the search's divisor $c$ divides $e$, with residual $(r_x / g_2)(d_j / g_1)$: true, but it needs an exact division and covers one column in a narrow case;
- testing known divisors of the operands against $e$ when $h > 1$ (addition) or $g > 1$ (division): divisions with remainder, not knowledge;
- inserting new divisors from the operation's quantities, such as $g/h$ or $r_x$: each insertion shifts every incidence row;
- adding facts to a denominator the lookup finds, in either design.
