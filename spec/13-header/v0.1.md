# Signed Integers with a Header: Specification v0.1

Nov 1, 2026 · The author's decisions of that day; small calls marked **(coordinator's call)**. Reviewed in [`review-v0.1.md`](review-v0.1.md).

Two designs, A and B, go through **round 1** (correctness) and, if it passes, **round 2** (speed and memory), each against Control.

## 1. Shared parts

- **Magnitudes:** unsigned. A 5-bit class code $c$ says where one lives: $c = 0$, the word is the magnitude; $c = 1..31$, the word is a **slot index** into the pool whose slots are $2^c$ words, lowest first. Little-endian (readable as 32-bit halves). Zero is class 0, word 0. Canonical: the smallest class that holds it.
- **Routines:** schoolbook, carries and borrows as values ($s < x$): add; multiply-accumulate ($r \mathrel{+}= xy$); absolute difference with its borrow; compare; Hensel exact division; binary gcd. Each reads operands at their real length $n$ (up to the top nonzero word; 0 for zero), writes at most its bound and returns the result's length. Bounds: add $\max + 1$; multiply-accumulate $\max(n_r, n_1 + n_2)$, plus a carry word only when nonzero; absolute difference $\max$; division exactly $n_1 - n_2 + 1$ (it stops there; the quotient never needs more); gcd $\min$.
- **Result class:** the smallest class holding the bound; A multiply $n_1 + n_2$, and each B part $\max(n_a + n_b, n_c + n_d) + 1$ for its $ab + cd$ (a one-word local that becomes the inline word, for class 0). If the result fits a smaller class it moves to the smallest that holds it, and the slot is released. A class above 31 is an error.
- **Pools:** the owner releases a value explicitly (values are immutable), pushing its slot onto the pool's free list, linked through freed slots' first words and ended by all ones. Allocation pops the free list, else takes the next slot, else doubles the pool, from one slot at first use **(coordinator's call)**. Indices survive growth, pointers do not, so result slots are allocated first. Pools never shrink.
- **Operations:** add, subtract, negate, multiply, exact division, gcd, compare.

## 2. Design A: magnitude and direction

A number is an **8-bit header** (bits 0–4 class, bit 5 spare 0, bits 6–7 direction $d$ mod 4 for $1, i, -1, -i$) and a **word**, in two parallel lists.

**Header arithmetic** on 8 bits, $D = \texttt{0xC0}$, then OR in the result class: multiply `(h1 and D) + (h2 and D)`; divide `(h1 and D) - (h2 and D)`; negate `h xor 0x80`; equal-direction add, $m_1 + m_2$ with direction `h1 and D`; opposite add, $\lvert m_1 - m_2 \rvert$ with borrow $b$ and direction `(h1 and D) + (b shl 7)`; subtract adds the negation; gcd has direction 0; zero is header 0. Sums across axes are an error (zero has no axis).

**Compare:** directions differ, $d = 0$ is larger; both 0, compare magnitudes; both 2, compare and reverse.

## 3. Design B: one magnitude per direction

A number is a pair $(P, N)$ along $+1$ and $-1$, value $P - N$. **Header:** 16 bits, $P$'s class in the low byte and $N$'s in the high byte, 3 spare bits 0 in each; two words, $P$'s then $N$'s **(coordinator's call)**. A part's direction is its place.

- **Negate:** swap $P$ and $N$. **Subtract:** negate, then add.
- **Add:** $(P_1 + P_2, N_1 + N_2)$.
- **Multiply:** $P = P_1P_2 + N_1N_2$, $N = P_1N_2 + N_1P_2$, by multiply-accumulate.
- **Compare:** $P_1 + N_2$ against $P_2 + N_1$, magnitude additions only.
- **Collapse:** the only subtraction. $\lvert P - N \rvert$ with borrow $b$ goes to $P$ when $b = 0$, else to $N$; the other part is 0. Exact division and gcd write $\lvert P - N \rvert$ straight into their working buffer, then follow A's direction rules; output collapses too. Add and multiply never collapse.

B is canonical only after collapse (one part zero).

**Structures** (rule 4): stored, the slot (A) or up to two slots (B); temporary, a slot on a move-down; local, the one-word local, B's compare sums, or the working buffer in division and gcd.

**Special cases**, named, not built: (a) a class-0 × class-0 product in registers; (b) an add allocating the class that holds $\max$ words, moving up only on a carry.

## 4. Round 1: correctness

A Python model of each design, word by word at $W = 4$; Python's integers are only the reference. Every operation, on:
- every pair of signed values below $2^8$ (division on $a = bq$), covering carries, borrows, equal magnitudes, zero and class moves; for B also every pair of uncollapsed values with both parts below $2^4$;
- 100,000 random pairs per operation, values up to 8 words, zeros and equal magnitudes forced at 1/16 each; B's operands uncollapsed, each part drawn on its own **(coordinator's call)**.

It passes when every value equals the reference (for B, $P - N$); every A result, every part of every B result, and every collapsed B result is in canonical form; spare bits are 0; and after all releases every slot is on its pool's free list.

**Four directions**, a check of the mathematics only, on a value-only model (no headers, classes or pools) against Gaussian integers: A's four directions under multiply, divide, negate, and add and subtract within an axis; B's four slots ($1, i, -1, -i$, a product landing in slot $(d_1 + d_2) \bmod 4$) under add, subtract, negate, multiply and collapse, sums across axes included. Round 2 builds integers only.

## 5. Round 2: speed and memory

Control (spec 12's Growing, [`../12-integers/v0.1.md`](../12-integers/v0.1.md) §1.4, with A's header list), A and B, each written as portable pseudocode (algorithm design rule 6) and then x86-64 machine code, so the comparison measures designs, not hand code against compiled code. Timed on x86-64 only, with spec 12's method: A × Control and B × Control, time and bytes. Known costs: rounding up, pools, A's opposite-direction branches, B's two magnitudes, growing parts and collapse. Jobs are set after round 1.
