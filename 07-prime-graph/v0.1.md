# Prime Graph: Exact Rationals with Shared, Lazily Refined Denominators, Specification v0.1

Oct 28, 2026 · Andrew Emerson

This spec defines a representation and arithmetic for exact rational numbers in which denominators are stored once, in factored form, and shared by every value that uses them. It records the design reached in discussion and measured in the research of this folder; where a question is still open it is listed under [Open decisions](#open-decisions). Scope: exact arithmetic on the real rationals. Complex and other units are a separate spec (06).

**Relation to earlier specs.** The array form below is the vector form of [05](../05-exact/v0.1.md) (integer numerators over one shared denominator), extended with exceptions. The slash scalar of 05 is not used for computation here.

## Purpose and scope

Exact rational arithmetic is slow mainly because every value carries its own denominator, and every operation pays a gcd to keep it in lowest terms. The vector form removes that cost when values share one denominator, but loses badly when denominators are unrelated. This design keeps the vector form's speed where values share a denominator and gains speed where they share only part of one, by storing each denominator's factors once and recording which values use them.

In scope: the representation, its invariants, entering values, splitting shared factors, the arithmetic, arrays, and the scalability requirements. Out of scope: rounding and approximation, syntax and language bindings, I/O formats, and complex values.

## Notation

$\operatorname{bits}(n)$ is the length of $|n|$ in binary. A *node* is a denominator node unless stated otherwise. $\gcd$ and $\operatorname{lcm}$ are on positive integers.

## The representation

Values are stored in one weighted bipartite graph.

- **Numerator side.** One numerator per value: a signed integer in two's complement, carrying the value's sign. A program's name for a value refers to its numerator; the value is not stored anywhere else.
- **Denominator side.** Nodes are integers greater than 1. Each node is either **prime** (proved) or a **leftover** (not yet split; treated as if prime). Each node keeps the list of numerators that use it and a reference count.
- **Edges.** A numerator connects to each node in its denominator. The edge's **weight** $w \ge 1$ is the power of that node: $1/12$ connects to 2 with weight 2 and to 3 with weight 1. Each numerator keeps the list of its (node, weight) pairs.

The value of a numerator $m$ with edges $(n_1, w_1), \ldots, (n_k, w_k)$ is

$$
x = \frac{m}{\prod_i n_i^{w_i}}.
$$

An integer has no edges. Zero is the numerator 0 with no edges.

### Invariants

- **I1. Coprime nodes.** No two live nodes share a factor. The arithmetic depends on this, not on every node being prime.
- **I2. Edge symmetry.** An edge appears in the numerator's list exactly when the numerator appears in the node's list, with the same weight.
- **I3. Reference counts.** A node's reference count equals the length of its numerator list. A node whose count reaches zero is freed.
- **I4. Lowest terms.** A single value's numerator shares no factor with any node it connects to. Arrays are in lowest terms per array (see [Arrays](#arrays)).
- **I5. Determinism.** Splitting nodes, whenever it happens, changes where a value's factors are recorded, never the value. Every result is exact and in lowest terms after the operation that produces it, or at the end of the expression for arrays (see V4 below).

## Entering a value

A rational $m/d$ enters as follows ("the dictionary" is a table keyed by prime, recording the node that holds each prime seen so far):

1. **Small primes.** Divide $d$ by each prime of a table (the primes below $2^{16}$), stopping when $p^2$ exceeds what is left. Divisibility tests are branch-free, in blocks of 8 (multiply by the inverse and compare). Each prime that divides is divided out as often as it goes; the count is its weight.
2. **Known large primes.** Divide what is left by the large primes already in the dictionary.
3. **The rest.** If what is left is above 1, a deterministic Miller–Rabin test decides whether it is prime; if it is not, Pollard's rho splits it. Primes found are added to the dictionary.
4. **Sharing.** For each prime $p$ found:
   - **first sighting:** record it in the dictionary and attach it to this value's denominator without splitting anything;
   - **already held by node $N$:** split $p$ out of $N$ (below), then connect.
5. **Reduce.** Cancel $m$ against the value's nodes by divisibility tests on those nodes only, which gives lowest terms (I4).

Nodes are therefore as coarse as correctness allows: a prime gets its own node only once two denominators share it. On first sighting, a denominator's primes may stay together in one composite node (100 and 35 give nodes 4, 5 and 7; nothing else shares a 2).

### Splitting a node

To split prime $p$ (power $k$ in $N$) out of node $N$:

1. Duplicate $N$'s numerator list as the list of the new node $p$; $N$ becomes $N/p^k$ and keeps its list.
2. Add the value that caused the split to $p$'s list.
3. Loop once over $p$'s list, adding $(p, k \cdot w)$ to each numerator's edge list, where $w$ is its weight on $N$: $N^w = (N/p^k)^w \cdot p^{kw}$.

The list says exactly which numerators to update, so there is no search. A split costs one pass over the node's numerator list and happens once per new sharing; splits number at most the distinct primes found. Shared lists, forwarding links and any other history structure are excluded.

## Arithmetic

Every operation reads only its operands' numerators, their edges and those nodes.

- **Addition and subtraction.** The common denominator takes each node at the larger of the two weights, which is a lookup, not a gcd. Each numerator is scaled by its missing node powers, then the numerators are added. The sum is reduced by divisibility tests on the result's nodes only.
- **Multiplication.** Each numerator is first cancelled against the other operand's nodes by divisibility tests. Then the numerators multiply and the weights on shared nodes add.
- **Division** multiplies by the reciprocal. The divisor's numerator becomes a denominator, so its factors are found by the entry procedure. **Division by zero is an error.**
- **Comparison** cross-scales as addition does and compares integers.
- **Negation** negates the numerator.

### Arrays

An array of values is stored in the **array form** (V3):
- **A shared denominator $D$**, itself a set of edges, held once for the array.
- **Dense elements:** values whose denominator divides $D$, stored as integer numerators scaled to $D$.
- **Exceptions:** the remaining elements, each with its own edges in a sparse list.

Elementwise operations and reductions run as integer loops over the dense elements, and through the graph for the exceptions.

**Deferred reduction (V4).** Within an expression over arrays, intermediate results are not reduced. An overflow triggers a reduction and a retry, not a failure. The result is reduced once, at the end. The array form is in lowest terms per array: $D$ and the dense numerators share no common factor.

**Choosing $D$** is an open decision. The lcm of the elements' denominators won where the lcm stays small. The most frequent denominator won where the lcm made products overflow.

## Scalability requirements (normative)

The graph grows with every value stored. A conforming implementation must satisfy these:

- **S1. Local operations.** No arithmetic operation may cost more as the graph grows. An operation touches only its operands, their edges and those nodes.
- **S2. Edges on both sides,** as above, so that an operation finds its denominators without a search, and a split finds its numerators without a search.
- **S3. Splits by copy and loop,** with no history kept.
- **S4. No scan at entry.** Sharing is found by dictionary lookups, never by comparing a new denominator against every node. Large leftovers above 64 bits are refined against each other in batches (product and remainder trees) or when two values meet in an operation.
- **S5. Freed nodes.** Unused nodes are freed by reference count, so the node table is bounded by the live values.

The costs that may grow are those every system has: the size of the values, and array operations that are linear in the array.

## Precision

**Version 1 (milestone M1)** holds numerators and nodes in 64 bits, with intermediates in 128 bits. Overflow is detected, never wrapped, and is reported as an error. **Arbitrary precision is milestone M2:**
- numerators and nodes widen past 64 bits, using the limb kernels of [05](../05-exact/v0.1.md);
- large leftovers above 64 bits are refined by gcd batches (S4).

## Determinism and platform requirements

Results are bit-identical on every platform: arithmetic is exact, and the canonical form (I4) is unique. Where and when nodes are split cannot change a result (I5). An implementation needs 64-bit integer arithmetic and a 64 × 64 → 128-bit multiply.

## Evidence

All measurements are on one machine (2-core Xeon, AVX-512), each preceded by an independent review, with every result checked against Python's `fractions`.

- **[First prototype](research/light-results.md),** against GMP and FLINT: faster than GMP `mpq_t` on most workloads and faster than FLINT `fmpq` on columns and chains (1.35–4.5×); 1.5× faster than both, and 20× faster than a single shared denominator, on denominators that share some primes. It lost on single values and on unrelated denominators, mostly to grouping and entry costs that the later rounds removed.
- **[Round one](research/ablation-grouping.md):** grouping was replaced. A shared array denominator with exceptions (V3) was 3–15× faster than the base design on arrays.
- **[Round two](research/ablation-round2.md):** a near-free equality check, bucketing and shared denominator objects were dropped; the seen-prime dictionary scaled.
- **[Round three](research/ablation-round3.md),** rule fixed before the run:
  - V3 + V4 beat V3 (better on 24 of 60 comparisons, worse on 1);
  - branch-free small-prime tests (D1) beat the naive dictionary by 1.10–1.43×;
  - the dictionary was 23× faster than a gcd scan at 10,000 distinct denominators and 112× at 30,000;
  - it trails by about 10% on decimal elementwise work and by 0.68 at about 100 distinct denominators.
- **[Stress test](research/scalability-stress.md):** with every requirement above, operation and entry time stayed flat up to 10⁷ values, and memory and nodes stayed bounded under 10⁷ deletes and inserts, with no leaks and every invariant audit passing. A gcd-scan entry grew 51× over the same growth. Splitting a node shared by 10⁷ numerators took 160–236 ms.

## Prior art

Light and focused reviews are in [research](research/): [first pass](research/prior-art-light.md), [second pass](research/prior-art-2.md), [shared-factor techniques](research/prior-art-3-sharing.md). The closest prior art:
- **ALTRAN's factored rational expressions** (Brown; Hall, 1974): factored forms of rational functions, sharing factor objects, but explicitly not keeping them coprime;
- **FriCAS `Fraction Factored Integer`:** factors eagerly and shares nothing between values;
- **factor refinement** (Bach, Driscoll and Shallit 1993; Bernstein 2005): an algorithm, not a representation;
- **shared-denominator arrays** in FLINT and LinBox: the shared denominator is never factored.

The second pass judged the combination probably new (about 70% confidence). A full review is planned before v0.2.

## Open decisions

- **Choosing the array denominator $D$:** the lcm, the most frequent denominator, or a rule between them.
- **Parity on small graphs:**
  - the dictionary rows' operations cost about 10% more on decimal elementwise work; the entry times are equal, so the cost appears to be implementation;
  - entry is slower than a gcd scan with about 100 distinct denominators.
- **Rho at entry** costs about 60 µs per new denominator of two large primes, once per distinct denominator. Deferring it (D2) gained nothing in round three. A true batch method is needed before deferral can pay.
- **Edge-storage memory:** freed space is reused only within a size class, so very large splits raise memory in steps.
- **Operation set and API:** printing and parsing, conversion to and from integers, floats and 05's `Exact`, error reporting, and thread safety of the shared graph.
- **Array errors:** whether division by zero fails a whole array operation or marks elements.
