# Exact Rational Arithmetic with Shared Whole Numbers

*Draft v0.4. This is the simplest version of the paper: it states the ideas and their reasons, and leaves details to later versions.*

Throughout, three things are kept apart:
- **the arithmetic:** what the mathematics says, as identities, and why they hold;
- **the structure:** how values are stored;
- **the algorithm:** the order in which the steps are done.

The same result can come from different structures and different algorithms, and a saving in one of the three is not a saving in the others. Each section says which of the three it is discussing.

## 1. Rational arithmetic

A rational number is a quotient $a/b$ of integers with $b > 0$.

**Arithmetic.** The four operations have a direct form, read straight off the definition of a fraction:

$$
\frac{a}{b} + \frac{c}{d} = \frac{ad + cb}{bd}, \qquad
\frac{a}{b} - \frac{c}{d} = \frac{ad - cb}{bd}, \qquad
\frac{a}{b} \cdot \frac{c}{d} = \frac{ac}{bd}, \qquad
\frac{a}{b} \div \frac{c}{d} = \frac{ad}{bc} \quad (c \ne 0).
$$

**Pseudocode.** Each identity is a few lines. Writing the steps in an order makes them an algorithm, but here any order gives the same result. Division moves a negative sign of $c$ to the numerator, so that the denominator stays positive.

```text
function add(a / b, c / d)
    set numerator to a · d + c · b
    set denominator to b · d
    return numerator / denominator
end function

function subtract(a / b, c / d)
    return add(a / b, −c / d)
end function

function multiply(a / b, c / d)
    set numerator to a · c
    set denominator to b · d
    return numerator / denominator
end function

function divide(a / b, c / d)
    if c is 0 then report division by zero
    set numerator to a · d
    set denominator to b · c
    if denominator is negative then negate numerator and denominator
    return numerator / denominator
end function
```

**Cost (part of the arithmetic).** The cost of an identity is the number and size of the integer operations it calls for; it belongs to the arithmetic, not to the structure or the algorithm. On a machine, integers are stored in words of fixed width. Larger integers are stored as sequences of words, and arithmetic on them costs more as they grow. We count the cost of arithmetic on integers of $n$ bits:
- **addition and subtraction:** $O(n)$;
- **multiplication:** $M(n)$, and $M(n, u)$ for an $n$-bit number times a $u$-bit number;
- **division with remainder:** $D(n)$, and $D(n, s)$ for an $n$-bit number by an $s$-bit one;
- **greatest common divisor:** $G(n)$.

These costs depend on the method used for the integer operations themselves, so each cost below is given in three forms: **symbolically,** in terms of $M$, $D$ and $G$; **with schoolbook methods,** the simple methods taught by hand; and **with the fastest known methods,** whose bounds are listed below. The last two are worst-case bounds.

| Operation | Schoolbook | Fastest |
| --- | --- | --- |
| $M(n)$ | $O(n^2)$ | $O(n \log n)$ |
| $M(n, u)$, $u \le n$ | $O(nu)$ | $O(n \log u)$ |
| $D(n)$ | $O(n^2)$ | $O(n \log n)$ |
| $D(n, s)$, $s \le n$ | $O(ns)$ | $O(n \log s)$ |
| $G(n)$ | $O(n^2)$ | $O(n \log^2 n)$ |

Logarithms are read as at least 1, so $O(n \log u)$ is $O(n)$ when $u$ is small. $O$-notation hides constant factors, so two costs of the same order need not be close; in both columns, $G(n)$ is at least of the order of $M(n)$. We assume throughout that the input numerators and denominators all have about $n$ bits.

The direct form is cheap per operation. Addition and subtraction cost three multiplications and one addition; multiplication and division cost two multiplications. Each value is stored as its own pair of integers, so the structure adds nothing beyond reading the operands and writing the result.

| Direct form | Category | Symbolic | Schoolbook | Fastest |
| --- | --- | --- | --- | --- |
| add, subtract | arithmetic per operation | $3M(n) + O(n)$ | $O(n^2)$ | $O(n \log n)$ |
| multiply, divide | arithmetic per operation | $2M(n)$ | $O(n^2)$ | $O(n \log n)$ |
| each value its own pair | structure per operation | $O(1)$ | $O(1)$ | $O(1)$ |
| | structure, one-time | none | none | none |

**Growth.** The result is larger than its operands. Each operation produces a numerator and denominator of about $2n$ bits, and a sequence of $T$ operations produces integers of about $Tn$ bits, even when the true value is small. For example, $\tfrac{1}{6} + \tfrac{1}{10} = \tfrac{16}{60}$, which is $\tfrac{4}{15}$, and $\tfrac{2}{3} \cdot \tfrac{3}{4} = \tfrac{6}{12}$, which is $\tfrac{1}{2}$. Left alone, the integers grow without bound, every later operation pays for their size, and the computation eventually exceeds the machine.

**The problem, in cost.** Take a running sum of $T$ values. After $t$ steps the total has about $tn$ bits, so step $t$ multiplies $tn$-bit numbers by $n$-bit ones. The cost per step grows with $t$, and the total is quadratic in $T$:

| Running sum of $T$ values | Symbolic | Schoolbook | Fastest |
| --- | --- | --- | --- |
| step $t$ | $3M(tn, n) + O(tn)$ | $O(t n^2)$ | $O(t n \log n)$ |
| all $T$ steps | $\sum_{t=1}^{T} \big(3M(tn, n) + O(tn)\big)$ | $O(T^2 n^2)$ | $O(T^2 n \log n)$ |
| for comparison: $T$ steps at constant size $n$ | $T\,\big(3M(n) + O(n)\big)$ | $O(T n^2)$ | $O(T n \log n)$ |

A running product is the same with $2M(tn, n)$ per step. The extra factor of $T$ is paid entirely for the growth of the integers, not for the values they represent.

**Powers.** Exponentiation needs no gcd: if $\gcd(a, b) = 1$ then $\gcd(a^k, b^k) = 1$, since a prime dividing both would divide $a$ and $b$; so a power of a fraction in lowest terms is still in lowest terms, and we set it aside.

## 2. Lowest terms and the gcd

The standard remedy is to keep every rational in **lowest terms**: $\gcd(a, b) = 1$ and $b > 0$. Every rational then has exactly one representation, and its integers are as small as its value allows. The gcd is computed by Euclid's algorithm, repeated division with remainder, or by one of its faster descendants.

This section is about the **arithmetic**: which gcds each operation needs, and why. The structure is the plain one, each value stored as its own pair of integers. Section 2.4 writes the methods out as pseudocode, and Section 2.5 gives their costs.

### 2.1 Addition and subtraction

**The direct method.** Compute the direct form, then divide both parts by their greatest common divisor:

$$
h = \gcd(ad + cb,\ bd), \qquad \frac{a}{b} + \frac{c}{d} = \frac{(ad + cb)/h}{bd/h}.
$$

This costs $3M(n) + G(2n) + 2D(2n)$: one gcd and two divisions on numbers of $2n$ bits.

**The refined method: a chain of gcds.** The gcd in the direct method takes a sum, $ad + cb$, and a product, $bd$. A sum cannot be broken apart, but a product can. The refined method breaks the one large gcd into a chain of two smaller ones.

Let $g = \gcd(b, d)$ and write $b = g\,b'$ and $d = g\,d'$. Then

$$
\gcd(ad + cb,\ bd) = g \cdot \gcd\!\left(\tfrac{ad + cb}{g},\ g\right).
$$

Two things happen in this equation.
- **$g$ comes out once.** It divides both arguments: $ad + cb = g\,(ad' + cb')$, and $bd = g^2\, b' d'$ contains $g$ twice. So $\gcd(ad + cb,\ bd) = g \cdot \gcd(ad' + cb',\ g\, b' d')$, and the quotient $(ad + cb)/g$ is simply $ad' + cb'$, computed directly without forming $ad + cb$.
- **The residuals drop out.** $b'$ and $d'$ share nothing with $(ad + cb)/g$, so they leave the remaining gcd entirely, and only $g$ is left.

*Proof that the residuals drop out.* Modulo $b'$, the quotient $ad' + cb'$ is congruent to $a d'$. Now $a$ is coprime to $b'$, since $a/b$ is in lowest terms and $b'$ divides $b$; and $d'$ is coprime to $b'$, since $g$ took everything $b$ and $d$ share. So $\gcd(ad' + cb',\ b') = 1$, and likewise $\gcd(ad' + cb',\ d') = 1$. A number coprime to $b'$ and to $d'$ has the same gcd with $g\,b'd'$ as with $g$. $\square$

With $h = \gcd\big((ad + cb)/g,\ g\big)$, the sum in lowest terms is

$$
\frac{a}{b} + \frac{c}{d} = \frac{(ad' + cb')/h}{b' \cdot (d/h)},
$$

since $b'\,d'\,g/h = b' \cdot d/h$. Subtraction is the same with $ad' - cb'$.

**Examples.** For $\tfrac{1}{6} + \tfrac{1}{10}$: $g = 2$, $b' = 3$, $d' = 5$, the quotient is $1 \cdot 5 + 1 \cdot 3 = 8$, and $h = \gcd(8, 2) = 2$. The sum is $\tfrac{8/2}{3 \cdot (10/2)} = \tfrac{4}{15}$. For $\tfrac{1}{2} + \tfrac{1}{2}$, everything cancels: $g = 2$, $b' = d' = 1$, the quotient is $2$, $h = \gcd(2, 2) = 2$, and the sum is $\tfrac{1}{1}$.

**The gain:** one gcd on the $n$-bit denominators, then one gcd against $g$, which has at most $n$ bits and is often small, instead of one gcd on $2n$-bit numbers. When $g = 1$ the direct form is already in lowest terms and the second gcd is skipped; but finding $g = 1$ is not free, since it takes the first gcd. The first gcd, $\gcd(b, d)$, is now the largest single cost of an addition. Sections 3 and 5 avoid it when the denominators are known to be equal, and Section 5 also when they are known to be coprime.

### 2.2 Multiplication

In a product $\tfrac{a}{b} \cdot \tfrac{c}{d}$ in lowest terms, nothing can cancel between $a$ and $b$, or between $c$ and $d$. So the only possible cancellations are **across**: $a$ against $d$, and $c$ against $b$. Let

$$
g_1 = \gcd(a, d), \qquad g_2 = \gcd(c, b), \qquad
\frac{a}{b} \cdot \frac{c}{d} = \frac{(a/g_1)(c/g_2)}{(b/g_2)(d/g_1)}.
$$

*Why the result is in lowest terms.* After the cross gcds are divided out, $a/g_1$ is coprime to $b/g_2$ (it already was before) and to $d/g_1$ (the common part is gone); likewise $c/g_2$ is coprime to both parts of the denominator. A product of numbers each coprime to the denominator is coprime to it. $\square$

**Example.** For $\tfrac{4}{9} \cdot \tfrac{3}{8}$: $g_1 = \gcd(4, 8) = 4$ and $g_2 = \gcd(3, 9) = 3$, so the product is $\tfrac{1 \cdot 1}{3 \cdot 2} = \tfrac{1}{6}$, without ever forming $\tfrac{12}{72}$.

The two gcds are on $n$-bit numbers rather than one on $2n$-bit numbers, and the multiplications are of the already-reduced parts.

### 2.3 Division

**Division is multiplication by the reciprocal:** $\tfrac{a}{b} \div \tfrac{c}{d} = \tfrac{a}{b} \cdot \tfrac{d}{c}$. The reciprocal of a fraction in lowest terms is in lowest terms, since $\gcd(d, c) = \gcd(c, d) = 1$, so the cross gcds of Section 2.2 apply unchanged: $\gcd(a, c)$ and $\gcd(d, b)$.

**The sign.** The denominator must stay positive. If $c < 0$, the reciprocal is written $\tfrac{-d}{-c}$, moving the sign to the numerator.

**Division by zero.** If $c = 0$, the quotient does not exist. It must be reported as an error, not computed.

**Example.** $\tfrac{2}{9} \div \left(-\tfrac{4}{3}\right) = \tfrac{2}{9} \cdot \tfrac{-3}{4}$; the cross gcds are $\gcd(2, 4) = 2$ and $\gcd(3, 9) = 3$, giving $\tfrac{1 \cdot (-1)}{3 \cdot 2} = -\tfrac{1}{6}$.

### 2.4 Pseudocode

The gcd is Euclid's algorithm: replace the pair $(x, y)$ by $(y, x \bmod y)$ until $y$ is 0. Each step keeps the common divisors unchanged, since $x \bmod y = x - qy$, and $\gcd(x, 0) = x$. On $(0, 0)$ it returns 0, but the operations below never call it so: every call has a denominator, $g$ or a nonzero $c$ as an argument.

```text
function gcd(x, y)
    set x to the absolute value of x
    set y to the absolute value of y
    while y is not 0 do
        set (x, y) to (y, x mod y)
    end while
    return x
end function
```

With it, the four operations in lowest terms, by the refined method and the cross gcds, are hardly longer than those of Section 1. All divisions by $g$, $h$, $g_1$ and $g_2$ are exact.

```text
function add(a / b, c / d)
    set g to gcd(b, d)
    set b′ to b / g
    set d′ to d / g
    set t to a · d′ + c · b′
    set h to gcd(t, g)
    set numerator to t / h
    set denominator to b′ · (d / h)
    return numerator / denominator
end function

function subtract(a / b, c / d)
    return add(a / b, −c / d)
end function

function multiply(a / b, c / d)
    set g1 to gcd(a, d)
    set g2 to gcd(c, b)
    set numerator to (a / g1) · (c / g2)
    set denominator to (b / g2) · (d / g1)
    return numerator / denominator
end function

function divide(a / b, c / d)
    if c is 0 then report division by zero
    if c is negative then return multiply(a / b, −d / −c)
    return multiply(a / b, d / c)
end function
```

Write $\gamma$ for the size of $g = \gcd(b, d)$ in bits. The call $\gcd(t, g)$ starts with one remainder, $t \bmod g$, and then works on numbers of at most $\gamma$ bits. Zero needs no special case: it is $\tfrac{0}{1}$, and a sum that comes to zero has $b = d$, so $h = g = d$ and the result is $\tfrac{0}{1}$.

### 2.5 The trade

**Arithmetic.** Euclid's algorithm takes at most about $2 \log_2 y$ steps, since two steps at least halve the remainder; a step with quotient $q$ costs $O\big(n(1 + \log q)\big)$, and the quotients multiply to at most $x$, so the total is $O(n^2)$. That is the schoolbook $G(n)$.

| Operation | Method | Symbolic | Schoolbook | Fastest |
| --- | --- | --- | --- | --- |
| add, subtract | direct form, no gcd | $3M(n) + O(n)$ | $O(n^2)$ | $O(n \log n)$ |
| | direct method | $3M(n) + G(2n) + 2D(2n)$ | $O(n^2)$ | $O(n \log^2 n)$ |
| | refined method | $G(n) + 2D(n, \gamma) + 3M(n, u) + D(2n, \gamma) + G(\gamma)$, plus exact divisions by $h$ | $O(n^2)$ | $O(n \log^2 n)$ |
| multiply, divide | direct form, no gcd | $2M(n)$ | $O(n^2)$ | $O(n \log n)$ |
| | two cross gcds | $2G(n) + 4D(n) + 2M(n)$ | $O(n^2)$ | $O(n \log^2 n)$ |

Here $\gamma$ is the size of $g$ in bits, as in Section 2.4, and $u$ the larger size of the residuals $b'$ and $d'$, about $n - \gamma$. In the refined method the terms are grouped by kind: the first gcd, the two residuals, the three multiplications (each with one factor of only $u$ bits), and the second gcd, as one remainder and a gcd on $\gamma$ bits. In the pseudocode, the multiplication for the denominator comes after the second gcd.

**Structure.** Unchanged from Section 1: each value is its own pair, $O(1)$ per operation, nothing one-time.

**Over a run.** Lowest terms do not bound the integers by a constant; they make their size depend on the value, not on the number of steps. When the values stay at about $n$ bits, as they do when the data share a scale, a running sum costs $T$ times one addition:

| Running sum of $T$ values | Symbolic | Schoolbook | Fastest |
| --- | --- | --- | --- |
| direct form (Section 1) | $\sum_{t=1}^{T} \big(3M(tn, n) + O(tn)\big)$ | $O(T^2 n^2)$ | $O(T^2 n \log n)$ |
| refined method, values near $n$ bits | $T$ times the refined cost | $O(T n^2)$ | $O(T n \log^2 n)$ |

So, provided the values stay near $n$ bits, the gcd pays for itself after a constant number of steps in the schoolbook model, and once $T$ exceeds about $\log n$ in the fastest one.

Keeping lowest terms is *more* work per operation than the direct form alone. What the gcd buys is not speed but boundedness: the integers stay as small as their values allow, so later operations do not pay for growth, and long computations stay feasible. The gcd becomes the dominant cost of exact rational arithmetic, and the target of every further saving. The rest of this paper looks for cases where a gcd is known in advance, or known to be 1, so that it need not be computed.

## 3. Shared denominators

### 3.1 Arithmetic

When both operands have the same denominator $d$, the refined method's $g$ is $d$ itself, and the numerators simply add:

$$
\frac{a}{d} + \frac{c}{d} = \frac{a + c}{d}, \qquad \frac{a}{d} - \frac{c}{d} = \frac{a - c}{d}.
$$

That is one integer addition, with no multiplication and no first gcd. What remains is the refined method's second gcd, now $\gcd(a \pm c,\ d)$ on the full $d$. **A single shared-denominator addition still needs this one gcd if its result is to be in lowest terms:** $\tfrac{1}{6} + \tfrac{1}{6} = \tfrac{2}{6}$, and $\gcd(2, 6) = 2$ gives $\tfrac{1}{3}$.

### 3.2 Structure

A collection of values over one denominator is stored as **one denominator, stored once, with a list of numerators.** Each value then costs one numerator instead of a numerator and a denominator. For $N$ values, $N - 1$ copies of the denominator are saved: about $n/8$ bytes per value for an $n$-bit denominator, so 32 bytes per value when denominators have 256 bits.

A value in the list need not be in lowest terms on its own: over the denominator $6$, the numerator $3$ stands for $\tfrac{1}{2}$. Such a value must be reduced before the no-gcd shortcuts of Sections 4.1 and 5.2 are applied to it, since they require operands in lowest terms. Multiplication and division of two values over one denominator are among the cases of Section 5.2. Values that do not already share a denominator can be brought to one, their least common multiple, by scaling the numerators. This works when the data share a scale, such as amounts in cents over $100$. It fails when denominators are unrelated, because their least common multiple grows quickly, and every numerator is scaled up with it.

### 3.3 Algorithm: deferred reduction

Reducing after every addition has a second drawback in this structure: it takes the result off the shared denominator. $\tfrac{2}{6}$ reduced is $\tfrac{1}{3}$, which no longer sits over $6$, and the next addition with a value over $6$ needs the refined method again.

So the reduction is **deferred**: a run of numerators is added, and the total is reduced once, at the end. For example,

$$
\frac{1}{6} + \frac{1}{6} + \frac{1}{6} + \frac{3}{6} = \frac{1 + 1 + 1 + 3}{6} = \frac{6}{6} = 1.
$$

That is three integer additions and a single gcd, $\gcd(6, 6) = 6$, instead of a gcd after every addition. Deferral does not remove the gcd; it pays one gcd per run instead of one per addition. This is a choice of **algorithm**, the order of the steps: the arithmetic (numerator addition, then one reduction) and the structure (one denominator, a list of numerators) are the same either way. The cost is that, between reductions, the numerators can grow; a run of $T$ additions adds at most about $\log_2 T$ bits to them.

### 3.4 Cost

Write $n' = n + \log_2 T$ for the size of the numerators in a run of $T$ additions, and $\ell$ for the size of a common denominator built by scaling, with $n \le \ell \le Nn$ for $N$ values.

| Shared denominator | Category | Symbolic | Schoolbook | Fastest |
| --- | --- | --- | --- | --- |
| add, subtract, then reduce | arithmetic per operation | $O(n) + G(n) + 2D(n)$ | $O(n^2)$ | $O(n \log^2 n)$ |
| add, subtract, unreduced | arithmetic per operation | $O(n)$ | $O(n)$ | $O(n)$ |
| one denominator, a list of numerators | structure per operation | $O(1)$ | $O(1)$ | $O(1)$ |
| | structure, per value | one numerator, not two integers | | |
| bringing $N$ values to one denominator | structure, one-time | $N\big(G(n) + 3D(\ell, n) + 2M(\ell, n)\big)$ | $O(N \ell n)$ | $O\big(N(\ell \log n + n \log^2 n)\big)$ |
| run of $T$ additions, reduced after each | algorithm | at least $T\big(O(n) + G(n) + 2D(n)\big)$ | $O(T n^2)$ | $O(T n \log^2 n)$ |
| run of $T$ additions, deferred | algorithm | $T \cdot O(n') + G(n') + 2D(n')$ | $O(T n' + n'^2)$ | $O(T n' + n' \log^2 n')$ |

The one-time row computes the least common multiple step by step, $\text{lcm}(L, b_i) = L \cdot b_i / \gcd(L, b_i)$, with the gcd found as one remainder $L \bmod b_i$ and a gcd on $n$ bits, and then scales each numerator by $L / b_i$. The row reduced after each addition is only a lower bound: once reduced, a total leaves the shared denominator (Section 3.3), so later additions need the refined method of Section 2, which costs more.

**What the shortcut removes.** Against the refined method of Section 2, a shared denominator removes the first gcd $G(n)$, the residual divisions and the three multiplications: what is left of the arithmetic is one integer addition. It does not remove the reduction. Since $g = d$, the second gcd is now on the full $n$ bits, so an addition that is reduced at once is still $O(n^2)$ and $O(n \log^2 n)$; it saves one gcd and the multiplications, a constant factor. Deferral, an algorithm choice, removes the reduction from all but one addition per run, so the cost per addition falls to $O(n')$ in both models. The structure saves memory, one integer per value, but the one-time conversion is paid in full when the values do not already share a denominator.

## 4. Shared numerators

### 4.1 Arithmetic

This section gives multiplication and division with a shared numerator. Their mirror images, with a shared denominator, are among the further cases of Section 5.2.

**Operands in lowest terms.** The no-gcd shortcut below, $a^2/(bd)$, requires operands in lowest terms; its proof depends on it. Without it, it fails: $\tfrac{3}{6} \cdot \tfrac{3}{6} = \tfrac{9}{36}$, which is $\tfrac{1}{4}$. An unreduced value, such as the total of a deferred run (Section 3.3), must therefore be reduced before it is multiplied.

**Multiplication with a shared numerator needs no gcd at all:**

$$
\frac{a}{b} \cdot \frac{a}{d} = \frac{a^2}{bd}, \quad \text{already in lowest terms.}
$$

*Proof.* A prime dividing $a^2$ divides $a$, and $a$ is coprime to $b$ and to $d$, so the prime divides neither, and hence not $bd$. $\square$ In the terms of Section 2.2, both cross gcds are $\gcd(a, d)$ and $\gcd(a, b)$, which are known to be 1 without computing them. For example, $\tfrac{3}{4} \cdot \tfrac{3}{5} = \tfrac{9}{20}$.

**Division with a shared numerator is simplified but not free.** If $a \ne 0$, $a$ cancels entirely:

$$
\frac{a}{b} \div \frac{a}{d} = \frac{a}{b} \cdot \frac{d}{a} = \frac{d}{b} \qquad (a \ne 0),
$$

but $b$ and $d$ may share a factor, so one gcd remains: $\tfrac{1}{2} \div \tfrac{1}{4} = \tfrac{4}{2} = 2$. The condition $a \ne 0$ is needed: if $a = 0$ the divisor is zero, and cancelling anyway would give $\tfrac{0}{1} \div \tfrac{0}{1} = 1$.

### 4.2 Structure

The mirror image of Section 3.2: **one numerator, stored once, with a list of denominators.** Unit fractions $\tfrac{1}{b}$ are the simplest case. Each value costs one denominator, and $N - 1$ copies of the numerator are saved.

One limit is visible already. The product $\tfrac{a^2}{bd}$ has numerator $a^2$, not $a$, so it does not belong to the list it came from; likewise a product of two values over $d$ has denominator $d^2$ (Section 5.2), and does not belong to the shared-denominator list. A structure that commits in advance to one shared denominator, or one shared numerator, cannot hold its own products. Section 5 removes that commitment.

### 4.3 Cost

| Shared numerator | Category | Symbolic | Schoolbook | Fastest |
| --- | --- | --- | --- | --- |
| multiply | arithmetic per operation | $2M(n)$ | $O(n^2)$ | $O(n \log n)$ |
| divide, $a \ne 0$ | arithmetic per operation | $G(n) + 2D(n)$ | $O(n^2)$ | $O(n \log^2 n)$ |
| one numerator, a list of denominators | structure per operation | $O(1)$ | $O(1)$ | $O(1)$ |
| | structure, per value | one denominator, not two integers | | |
| | structure, per result | the result leaves the list: two integers | | |

**What the shortcut removes.** Against the two cross gcds of Section 2, $2G(n) + 4D(n) + 2M(n)$:
- **Multiplication** loses both gcds and all four divisions. What is left, $a^2$ and $bd$, is exactly the direct form of Section 1, but now the direct form is already in lowest terms, so it carries no growth penalty. In the fastest model the cost falls from $O(n \log^2 n)$ to $O(n \log n)$.
- **Division** loses one gcd, two divisions and both multiplications: what is left is $\gcd(d, b)$ and two exact divisions. The order is unchanged; the cost falls to less than half.

In the schoolbook model all of these are still $O(n^2)$: the gains there are in constant factors. There is no algorithm to choose: every two values in the list share their numerator, so the shortcut always applies.

## 5. The combined structure

### 5.1 Structure

The values are stored in **two lists.**
- **The whole numbers.** Each distinct whole number is stored once, unsigned, and is identified by its position in the list, its **index**.
- **The rationals.** Each rational is a pair of indices into the whole-number list, a numerator index and a denominator index, with a tag bit for the sign. The tag belongs to the numerator only: the denominator is always positive, so the tag is the sign of the numerator and of the value. This is why the whole-number list holds only unsigned values, and why $\tfrac{5}{6}$ and $-\tfrac{5}{6}$ share the index of $5$. Zero, $\tfrac{0}{1}$, always takes the $+$ tag, so it has one representation.

When an operation produces a result, each of its whole numbers is **looked up**: if the number is already stored, its index is reused; if not, it is appended. With a hash table, a lookup costs expected $O(n)$, about one pass over the number, far less than a gcd.

Because each distinct whole number is stored once, **two indices are equal exactly when the whole numbers are equal.** Comparing two indices takes constant time, while comparing two $n$-bit numbers takes $O(n)$.

**Equal indices reveal more than the two headline cases.** Sections 3 and 4 each looked for one kind of equality: a shared denominator, which helps addition, and a shared numerator, which helps multiplication. Here any whole number of one operand can be compared with any whole number of the other. Besides those two, that gives **cross matches**, where one value's numerator is the other's denominator, which help multiplication, division and even addition. Section 5.2 treats them all as one family.

**What the structure gives.**
- **It generalizes both earlier structures.** Rationals with the same denominator index are the shared-denominator list of Section 3; rationals with the same numerator index are the shared-numerator list of Section 4. A whole number may also serve as the numerator of one value and the denominator of another, which neither earlier structure can express.
- **Its memory depends on reuse.** There are two baselines. In plain per-value storage, each value holds its own numerator and denominator. In a list of Section 3 (or 4), the shared whole number is already stored once, and each value holds one whole number. Here a rational costs two indices and a sign bit, and each distinct whole number is stored once, with an entry in the lookup table. When whole numbers repeat, in both positions and across many values, this costs less than either baseline. When most whole numbers are new, it costs more than either: every number is still stored in full, and each also pays for its index and its lookup entry. Sums are the common source of new numbers, since a numerator $a \pm c$ is often stored nowhere else.

### 5.2 Arithmetic: the family of index equalities

Write the operands $\tfrac{a}{b}$ and $\tfrac{c}{d}$, both in lowest terms, with each equality below read as equal indices. A denominator is positive and the sign is a tag on the numerator, so a match is in magnitude, and the table gives magnitudes. The sign of a product or quotient is the product of the operands' tags. For a sum or difference, the second tag is first flipped if the operation is subtraction; then $\pm$ is $+$ if the two tags agree and $-$ if they differ, and the result's tag is the first operand's tag times the sign of the sum or difference of magnitudes. This holds for every sum below, including the one with a shared numerator, whose sign is that of $d' \pm b'$ times the first tag.

**The principle.** The general methods of Section 2 compute a few gcds between whole numbers of the two operands: $\gcd(b, d)$ for addition, the cross gcds $\gcd(a, d)$ and $\gcd(c, b)$ for multiplication, and $\gcd(a, c)$ and $\gcd(d, b)$ for division. An equality of indices can settle such a gcd without computing it, in one of two ways:
- **Equal arguments.** The gcd of a whole number with itself is the number: if $b = d$, then $\gcd(b, d) = d$.
- **The invariant.** Lowest terms says that each numerator is coprime to its own denominator. So if one argument equals the *partner* of the other, the gcd is 1: if $a = d$, then $\gcd(b, d) = \gcd(b, a) = 1$.

Any equality of indices that the lowest-terms invariant makes informative in this way saves gcd work. Each row below is the general method of Section 2 with the settled gcds put in, so its correctness follows from the proofs there.

| Operation | Equal indices | Gcds settled | Result | Gcds left |
| --- | --- | --- | --- | --- |
| add, subtract | same denominator, $b = d$ | $\gcd(b, d) = d$ | $(a \pm c)/d$ | one, $\gcd(a \pm c,\ d)$; or one per run, deferred |
| add, subtract | same numerator, $a = c$ | $\gcd(a, bd) = 1$ | $a(d' \pm b')/(g\,b'd')$ | two, $g = \gcd(b, d)$ and $\gcd(d' \pm b',\ g)$ |
| add, subtract | cross, $a = d$ (or $c = b$) | $\gcd(b, d) = 1$ | $(ad \pm cb)/(bd)$ | none |
| multiply | same denominator, $b = d$ | $\gcd(a, d) = \gcd(c, b) = 1$ | $ac/d^2$ | none |
| multiply | same numerator, $a = c$ | $\gcd(a, d) = \gcd(c, b) = 1$ | $a^2/(bd)$ | none |
| multiply | one cross, $a = d$ | $\gcd(a, d) = a$ | $c/b$ | one, $\gcd(c, b)$ |
| multiply | both cross, $a = d$ and $c = b$ | both, $a$ and $b$ | $\pm 1$ | none |
| divide | same numerator, $a = c \ne 0$ | $\gcd(a, c) = a$ | $d/b$ | one, $\gcd(d, b)$ |
| divide | same denominator, $b = d$, $c \ne 0$ | $\gcd(d, b) = d$ | $a/c$ | one, $\gcd(a, c)$ |
| divide | cross, $a = d$ (or $c = b$), $c \ne 0$ | $\gcd(a, c) = \gcd(d, b) = 1$ | $a^2/(bc)$ (or $ad/b^2$) | none |
| divide | both same, $a = c \ne 0$ and $b = d$ | both, $a$ and $d$ | $\pm 1$ | none |

Rows with "none" left rely on the operands being in lowest terms; a value left unreduced, such as the total of a deferred run, is reduced first. The case $c = b$ of a single cross match in multiplication is the mirror image of $a = d$: the product is $a/d$, and $\gcd(a, d)$ is left.

**The cases one by one.**
- **Same denominator.** Addition is Section 3.1. Multiplication needs no gcd, $\tfrac{3}{7} \cdot \tfrac{2}{7} = \tfrac{6}{49}$; division cancels $d$ and leaves one gcd, $\tfrac{3}{10} \div \tfrac{9}{10} = \tfrac{3}{9} = \tfrac{1}{3}$, with the sign the product of the two tags.
- **Same numerator.** Multiplication and division are Section 4.1. Adding with a shared numerator is the refined method of Section 2.1 with numerator $t = a(d' \pm b')$, and since $a$ is coprime to $bd$ the reduction is by $h = \gcd(d' \pm b',\ g)$, with $\gcd(g\,t,\ bd) = g \cdot h$ for the direct form's numerator $g\,t = a(d \pm b)$: $\tfrac{7}{6} + \tfrac{7}{10}$ has $g = 2$, $t = 7 \cdot 8$, $h = 2$ and $\gcd(56 \cdot 2,\ 60) = 4$, giving $\tfrac{28}{15}$.
- **Cross match in addition.** If $a = d$, the denominators are coprime, so the refined method's $g$ is 1 and the direct form is already in lowest terms: $\tfrac{2}{3} + \tfrac{5}{2} = \tfrac{4 + 15}{6} = \tfrac{19}{6}$. This is the case $g = 1$ of Section 2.1, now known without the first gcd.
- **Cross match in multiplication.** In $\tfrac{a}{b} \cdot \tfrac{c}{a}$, the whole of $a$ cancels, and $\gcd(c, b)$ remains: $\tfrac{4}{9} \cdot \tfrac{3}{4} = \tfrac{3}{9} = \tfrac{1}{3}$. If both cross pairs match, nothing is left to compute but the sign: $\tfrac{a}{b} \cdot \tfrac{b}{a}$ is $\pm 1$.
- **Cross match in division.** Division multiplies by the reciprocal, which swaps the divisor's numerator and denominator, so a cross match becomes a shared numerator or denominator in the product, and needs no gcd:

  $$
  \frac{a}{b} \div \frac{c}{a} = \frac{a}{b} \cdot \frac{a}{c} = \frac{a^2}{bc} \quad (c \ne 0), \qquad
  \frac{a}{b} \div \frac{b}{d} = \frac{a}{b} \cdot \frac{d}{b} = \frac{ad}{b^2}.
  $$

  For example, $\tfrac{2}{3} \div \tfrac{5}{2} = \tfrac{4}{15}$ and $\tfrac{2}{3} \div \tfrac{3}{5} = \tfrac{10}{9}$. In the same way, a shared numerator or denominator in a division becomes a cross match in the product, which is why those divisions leave one gcd. The condition $a \ne 0$ for a shared numerator excludes $\tfrac{0}{1} \div \tfrac{0}{1}$, which cancelling would otherwise give as 1.

### 5.3 Algorithm: checking indices first

**Sharing is discovered, not declared.** The earlier structures had to be chosen before the data arrived. Here no advance knowledge of which values share is needed: before applying the general method of Section 2, an operation compares the indices of its operands, $b$ with $d$, $a$ with $c$, $a$ with $d$, and $c$ with $b$, and the equal ones select a row of the table in Section 5.2. When several are equal, the row with the fewest gcds left is taken. When none are equal, the operation falls back to Section 2.

Checking indices first is a choice of **algorithm**; the identities used are those of Sections 2 to 5.2, and the **structure** is what makes the check cost constant time. Deferred reduction (Section 3.3) is a second algorithm choice, available on values with the same denominator index: the running total is kept outside the structure, and only the reduced total is looked up and stored.

### 5.4 Cost

| Case | Symbolic | Schoolbook | Fastest | Removed, against Section 2 |
| --- | --- | --- | --- | --- |
| **Arithmetic per operation** | | | | |
| add, same denominator, reduced | $O(n) + G(n) + 2D(n)$ | $O(n^2)$ | $O(n \log^2 n)$ | first gcd, residual divisions, all multiplications |
| add, same numerator | $G(n) + 2D(n, \gamma) + 2M(n, u) + D(2n, \gamma) + G(\gamma)$, plus exact divisions by $h$ | $O(n^2)$ | $O(n \log^2 n)$ | one multiplication, $M(n, u)$, against the refined method |
| add, cross match | $3M(n) + O(n)$ | $O(n^2)$ | $O(n \log n)$ | both gcds, all divisions |
| multiply, same denominator or numerator | $2M(n)$ | $O(n^2)$ | $O(n \log n)$ | both gcds, all four divisions |
| multiply, one cross match | $G(n) + 2D(n)$ | $O(n^2)$ | $O(n \log^2 n)$ | one gcd, two divisions, both multiplications |
| divide, same numerator or denominator | $G(n) + 2D(n)$ | $O(n^2)$ | $O(n \log^2 n)$ | one gcd, two divisions, both multiplications |
| divide, cross match | $2M(n)$ | $O(n^2)$ | $O(n \log n)$ | both gcds, all four divisions |
| multiply, both cross; divide, both same | $O(1)$ | $O(1)$ | $O(1)$ | everything |
| no equal indices | as Section 2.5 | $O(n^2)$ | $O(n \log^2 n)$ | nothing |
| **Structure** | | | | |
| per operation: read indices, look up the result | $O(1)$, plus expected $O(n)$ per whole number looked up | $O(n)$ | $O(n)$ | |
| per stored value | two indices and a sign bit | | | |
| per new whole number, one-time | its bits and one table entry | | | |
| **Algorithm** | | | | |
| equal-index checks, every operation | four index comparisons, $O(1)$ | $O(1)$ | $O(1)$ | |
| deferred run of $T$ additions | as in Section 3.4 | $O(T n' + n'^2)$ | $O(T n' + n' \log^2 n')$ | all but one reduction per run |

The results of the arithmetic have at most about $2n$ bits, so each lookup is expected $O(n)$, below the cost of one multiplication in both models; and the checks cost $O(1)$, so an operation that finds no equal indices pays almost nothing for having looked. In the fastest model, the cases with no gcd left fall from $O(n \log^2 n)$ to $O(n \log n)$, or to $O(1)$. In the schoolbook model every case except those with result $\pm 1$ is still $O(n^2)$, and the gain is in constant factors: one or two gcds, the dominant term, are not computed.

### 5.5 A worked example

Start with four values, $\tfrac{1}{6}$, $-\tfrac{5}{6}$, $\tfrac{5}{7}$ and $\tfrac{6}{7}$:

| Whole-number index | Whole number |
| --- | --- |
| 0 | $1$ |
| 1 | $6$ |
| 2 | $5$ |
| 3 | $7$ |

| Rational | Numerator index | Sign | Denominator index | Value |
| --- | --- | --- | --- | --- |
| $x_0$ | 0 | $+$ | 1 | $\tfrac{1}{6}$ |
| $x_1$ | 2 | $-$ | 1 | $-\tfrac{5}{6}$ |
| $x_2$ | 2 | $+$ | 3 | $\tfrac{5}{7}$ |
| $x_3$ | 1 | $+$ | 3 | $\tfrac{6}{7}$ |

The sign is the tag bit, and it belongs to the numerator.

Four whole numbers serve eight places. The $6$ at index 1 is a denominator in $x_0$ and $x_1$ and a numerator in $x_3$; the $5$ at index 2 is the numerator of $x_1$ and $x_2$, with opposite signs.

| Operation | Equal indices | Work | Result | Stored as |
| --- | --- | --- | --- | --- |
| $x_0 + x_1$ | denominators (1) | $\tfrac{1 - 5}{6} = \tfrac{-4}{6}$; $\gcd(4, 6) = 2$ | $-\tfrac{2}{3}$ | $2$, $3$ appended at 4, 5; index 4, sign $-$, over index 5 |
| $x_0 \cdot x_1$ | denominators (1) | $\tfrac{1 \cdot (-5)}{6^2}$, no gcd | $-\tfrac{5}{36}$ | $36$ appended at 6; index 2, sign $-$, over index 6 |
| $x_1 \cdot x_2$ | numerators (2) | $\tfrac{(-5) \cdot 5}{6 \cdot 7}$, no gcd | $-\tfrac{25}{42}$ | $25$, $42$ appended at 7, 8; index 7, sign $-$, over index 8 |
| $x_0 \cdot x_3$ | $x_3$'s numerator, $x_0$'s denominator (1) | $6$ cancels; $\gcd(1, 7) = 1$ | $\tfrac{1}{7}$ | index 0, sign $+$, over index 3; nothing new |
| $x_2 \div x_1$ | numerators (2) | $\tfrac{6}{7}$, sign from $x_1$; $\gcd(6, 7) = 1$ | $-\tfrac{6}{7}$ | index 1, sign $-$, over index 3; nothing new |
| $x_3 \div x_2$ | denominators (3) | $\tfrac{6}{5}$; $\gcd(6, 5) = 1$ | $\tfrac{6}{5}$ | index 1, sign $+$, over index 2; nothing new |
| $x_3 \div x_0$ | $x_3$'s numerator, $x_0$'s denominator (1) | $\tfrac{6}{7} \cdot \tfrac{6}{1} = \tfrac{6^2}{7 \cdot 1}$, no gcd | $\tfrac{36}{7}$ | $36$ found at 6; index 6, sign $+$, over index 3 |
| $x_1 + x_3$ | $x_1$'s denominator, $x_3$'s numerator (1) | $\tfrac{(-5) \cdot 7 + 6 \cdot 6}{6 \cdot 7}$, no gcd | $\tfrac{1}{42}$ | $1$ found at 0, $42$ found at 8; index 0, sign $+$, over index 8 |

Each operation is applied to the original four values, while the whole-number list grows from row to row. Two multiplications, one division and one addition need no gcd at all, and every other operation needs one gcd instead of two. The first sum and the first two products introduce new whole numbers, as Section 5.1 warned; the last five results reuse whole numbers already stored, among them 36 and 42, first produced by $x_0 \cdot x_1$ and $x_1 \cdot x_2$.

### 5.6 What is left out

Equal indices detect only exact sharing: two denominators are either the same whole number or not. Most real data lies in between, with denominators that share some factors but not all, as $12$, $18$ and $30$ do. That partial sharing is left for a later version.
