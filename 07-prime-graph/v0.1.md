# Prime Graph: Exact Rationals with Shared, Lazily Refined Denominators, Specification v0.1

Oct 28, 2026 · Andrew Emerson

This spec defines a representation and an arithmetic for exact rational numbers. Denominators are stored once, in factored form, and shared by every value that uses them. The spec records the design reached in discussion and measured in this folder's research. Where the spec needed a rule that was never decided, it says so and gives a **provisional M1 default**, listed again under [Open decisions](#open-decisions).

Scope: exact arithmetic on the real rationals. Complex and other units are a separate spec (06).

**Relation to earlier specs.** The array form here is [05](../05-exact/v0.1.md)'s vector form (integer numerators over one shared denominator), extended with exceptions. It differs in one respect: numerators here are signed, in two's complement, rather than 05's magnitudes with a separate sign column. This follows the later decision to use `i64`-style numerators: [Q v0.3](../03-q/v0.3.md#the-layout-of-the-vector-form) measured two's complement fastest of its layouts, and 04's phase-two side column measured it 2.4–7.6× faster than sign and magnitude at 128 bits on add, dot product and chains, though slower on the bit-length scan. 05's slash scalar is not used for computation here.

## Purpose and scope

Exact rational arithmetic is slow mainly because every value carries its own denominator, and every operation pays a gcd to keep it in lowest terms. The vector form removes that cost when values share a denominator, but it loses badly when denominators are unrelated. This design keeps the vector form's speed where values share a denominator, and gains speed where they share only part of one, by storing each denominator's factors once and recording which values use them.

**In scope:** the representation and its invariants; values and arrays and their lifetimes; entering values; splitting shared factors; the arithmetic; the scalability requirements.

**Out of scope:** rounding and approximation, syntax and language bindings, I/O formats, and complex values.

## Notation

$\operatorname{bits}(n)$ is the length of $|n|$ in binary. A *node* means a denominator node unless stated otherwise. A *holder* is anything that has edges: a value's numerator, or an array's shared denominator.

## The representation

Values are stored in one weighted bipartite graph.

- **Holders.** A value's numerator is a signed integer in two's complement, carrying the value's sign. An array's shared denominator $D$ is a holder too (see [Arrays](#arrays)). A program refers to a value through a handle to its holder; the value is not stored anywhere else.
- **Nodes.** A node is an integer greater than 1, stored as a list of **atoms** with exponents.
  - Atoms are pairwise coprime: each is a proved prime, or a *leftover* whose factors are not yet known.
  - The exponents are normalised to have gcd 1, so a node with a single atom is that atom itself, and any power goes on the edge weight.
  - Each node keeps the list of holders that use it, and a reference count.
- **Edges.** A holder connects to each node in its denominator. The edge's **weight** $w \ge 1$ is the power of that node: $1/12$ has edges to 2 (weight 2) and 3 (weight 1). Each holder keeps its list of (node, weight) pairs, and each edge also records its position in the node's list.

A value with numerator $m$ and edges $(n_1, w_1), \ldots, (n_k, w_k)$ is

$$
x = \frac{m}{\prod_i n_i^{w_i}}.
$$

An integer has no edges. Zero is the numerator 0 with no edges.

**The dictionary.** It maps each atom to the node holding it: a direct array for atoms below $2^{16}$, and a hash table above. Entries are removed when their node is freed.

### Invariants

- **I1. Coprime atoms.** No two live atoms share a factor, so no two nodes do. The arithmetic depends on this, not on every atom being prime.
- **I2. Edge symmetry.** An edge appears in a holder's list exactly when the holder appears in the node's list, with the same weight.
- **I3. Reference counts.** A node's reference count equals the length of its holder list. When it reaches zero the node is freed and its atoms leave the dictionary.
- **I4. Lowest terms.** A single value is in lowest terms after every operation that produces it. Its numerator shares no factor with any of its nodes, and no edge has weight 0. An array is in lowest terms per array after every array expression:
  - the shared denominator and all dense numerators share no common factor;
  - each exception is in lowest terms on its own.

  Whether single values may also defer reduction within an expression is an open decision.
- **I5. Values are unique; the internal form is not.** How a value's denominator is split into nodes depends on the history of the graph, and an array's dense/exception split depends on the choice of $D$. The rational value, and every result, never depends on either.

## Lifetimes

- **Creating** a value enters it (below) and returns a handle.
- **Releasing** a value removes its holder from each of its nodes' lists and decrements their counts, freeing nodes that reach zero (I3). Arrays release their shared denominator and their exceptions in the same way.
- **A result that cancels:** when a result's numerator is 0, or an edge's weight falls to 0, those edges are removed and the node counts decremented in the same way.

M1 is single-threaded. Thread safety of the shared graph is an open decision.

## Entering a denominator

A new denominator $d$ is processed as follows:

1. **Small primes.**
   - Strip the powers of 2 with one count-trailing-zeros.
   - Then try the odd primes below $2^{16}$, stopping when $p^2$ exceeds what is left. The divisibility tests are branch-free, in blocks of 8 (multiply by the inverse and compare).
   - Each prime that divides is divided out as often as it goes.
2. **The leftover.** If what is left, $n$, is above 1:
   - look $n$ up in the dictionary as a whole;
   - otherwise $n$ is prime if the stop fired or $n < 2^{32}$;
   - otherwise try a **bounded** list of the 16 most recently seen large primes;
   - then a deterministic Miller–Rabin test;
   - then Pollard's rho.

   A pass over every known large prime is forbidden: it grows with the graph (S1, S4). The bounded list is only a shortcut. Correctness never depends on it, because every atom found is looked up in the dictionary.
3. **Sharing.** Look each atom of $d$ up in the dictionary.
   - **Atoms seen for the first time** go together into one new node, the product of their powers, normalised as above. No split happens.
   - **Each existing node $h$ that holds some of $d$'s atoms** has its atoms grouped by the ratio (exponent in $d$) / (exponent in $h$), absent atoms counting as ratio 0. $h$ is split (below) until one class remains.

   This gives the coarsest correct graph. 30 then 45 gives nodes 2, 3, 5. 30 then 900 splits nothing, since $900 = 30^2$. 100 then 35 gives 2, 5, 7, with 100 = 2²·5² and 35 = 5·7.
4. **Edges.** $d$'s edges are then built by dictionary lookups.

### Splitting a node

To move a set $Q$ of node $N$'s atoms into a new node $P$ (copy and loop):

1. Copy $N$'s holder list as $P$'s list. $N$ keeps the remaining atoms $R$, renormalised.
2. Loop once over the list, giving each holder an edge to $P$ at the same position, with weights carried over: $N^w = R^{w g_R} \cdot P^{w g_Q}$, where $g_Q$ and $g_R$ are the gcds of the exponents moved into each part.
3. The holder that caused the split receives its own edges afterwards, from step 4 of entry. It is not part of the loop.

If either part is empty, there is nothing to split. The list says exactly which holders to update, so there is no search. A split costs one pass over the node's holder list, and happens at most once per new sharing. Shared lists, forwarding links and any other history structure are excluded.

### Entering a value

A rational $m/d$ (with $d > 0$, and the sign carried by $m$) is entered by entering $d$, then reducing (below).

## Arithmetic

Every operation reads only its operands' holders, their edges and those nodes (S1).

**Reduction.** Cancelling a numerator $m$ against a set of nodes:
- for each prime atom $p$ with weight $w$, divide $m$ by $p$ while it divides, up to $w$ times, lowering the result's edge weight each time;
- for each node $N$ with several atoms, or a leftover, take $g = \gcd(m, N)$:
  - if $g = N$, divide $m$ by $N$ while it divides, up to $w$ times, as for a prime;
  - if $g$ is a proper part, split or refine the node by $g$, then continue on the parts;
- remove edges that reach weight 0.

Reduction changes the result, never an operand. Testing only the nodes involved is sufficient: no other factor can be common to $m$ and the denominator.

- **Addition and subtraction.**
  1. The common denominator takes each node at the larger of the two weights. This is a lookup, not a gcd.
  2. Each numerator is scaled by its missing node powers, and the numerators are added.
  3. The sum is reduced against the common denominator's nodes.
- **Multiplication.**
  1. Each numerator is reduced against the other operand's nodes.
  2. The numerators multiply.
  3. The weights add on shared nodes.
- **Division** $a/b$, with $b = m_b/d_b$, multiplies $a$ by $d_b/m_b$:
  1. the sign of $m_b$ moves to the result's numerator;
  2. $|m_b|$ is entered as a new denominator;
  3. $d_b$'s node powers multiply into the result's numerator, with overflow checked;
  4. the result is reduced.

  **Division by zero is an error.**
- **Comparison** cross-scales as addition does and compares the two scaled numerators. Under M1's 64-bit bounds each scaled numerator fits in 128 bits (64 + 63 bits), so comparison never overflows.
- **Negation** negates the numerator; at the most negative value it overflows.

## Arrays

An array is created from a list of values, or as the result of an array operation. It is stored in the **array form** (V3):
- **The shared denominator $D$:** one holder with its own edges.
- **Dense elements:** values whose denominator divides $D$, stored as integer numerators scaled to $D$. They have no edges of their own.
- **Exceptions:** the remaining elements, each a holder with its own edges, in a sparse list.

An element becomes an exception when it is entered with a denominator that does not divide $D$, or when an operation's result for it overflows the dense scale.

**Choosing $D$** is an open decision. The lcm of the elements' denominators won where it stays small; the most frequent denominator won where the lcm made products overflow. **Provisional M1 default, not measured:** the lcm if it is below $2^{63}$, otherwise the most frequent denominator. (The measured V3-lcm row used the plain lcm; this hybrid was never measured, and it still misses cases where an lcm below $2^{63}$ makes products overflow, which is where the most frequent denominator won on W9.)

Elementwise operations and reductions run as integer loops over the dense elements, and through the graph for the exceptions.

**The shared denominator of a result.** An elementwise result between arrays with shared denominators $D_a$ and $D_b$ gets, for addition and subtraction, each node at the larger of its two weights ($\operatorname{lcm}(D_a, D_b)$); for multiplication, the weights added ($D_a D_b$); for division, the default rule applied to the results. A reduction (such as a sum) is a single value. The final reduction of the expression may then lower $D$ (I4).

**Deferred reduction (V4).** Within an array expression, intermediate results are not reduced. An overflow in a step triggers a reduction of that step's operands and a retry. Only an overflow that survives the retry is reported, as an error, in M1. The result is reduced once, at the end of the expression (I4).

## Scalability requirements (normative)

The graph grows with every value stored.
- **S1. Local operations.** No arithmetic operation may cost more as the graph grows. An operation touches only its operands, their edges and those nodes.
- **S2. Edges on both sides,** so that an operation finds its denominators without a search, and a split finds its holders without a search.
- **S3. Splits by copy and loop,** with no history kept.
- **S4. No scan at entry.** Sharing is found by dictionary lookups, never by comparing a new denominator with every node or every known large prime.
- **S5. Freed nodes.** Unused nodes are freed by reference count, so the node table is bounded by the live values.

The costs that may grow are those every system has: the size of the values, and array operations that are linear in the array.

## Precision

**M1** holds numerators and atoms in 64 bits, with intermediates in 128 bits. Overflow is detected, never wrapped, and reported as an error after V4's retry where that applies.

**M2** adds arbitrary precision: numerators and atoms widen past 64 bits, using the limb kernels of [05](../05-exact/v0.1.md). Large leftovers beyond 64 bits need a refinement method that respects S4; see Open decisions.

## Determinism and platform requirements

Every result is exact, and the rational value is unique (I5). Where and when nodes are split cannot change a result. An implementation needs 64-bit integer arithmetic and a 64 × 64 → 128-bit multiply.

## Evidence

The measurements were made on one machine (an Intel Xeon), each preceded by an independent review. Every result was checked against Python's `fractions`.

- **[First prototype](research/light-results.md),** against GMP and FLINT:
  - faster than GMP `mpq_t` on most workloads;
  - faster than FLINT `fmpq` by 1.35–4.5× on columns, mixed denominators, chains, and denominators built to share primes;
  - on that last workload (W7), 1.5× faster than both libraries and 20× faster than one shared denominator; W7 was constructed with shared primes;
  - slower than FLINT on single values (0.73–0.84) and on unrelated denominators (0.56).

  The current design has not yet been compared with GMP and FLINT; that is milestone M3.
- **[Round one](research/ablation-grouping.md):** grouping was replaced. Against the base design with grouping removed (V0′), a shared array denominator with exceptions (V3) was 3.3–15× faster on one-scale arrays and chains. On mixed data the result depended on the choice of $D$: 1.04–14.8 with the lcm, 0.88–8.1 with the most frequent denominator. It ran at 0.85–0.94 on single values and unrelated denominators.
- **[Round two](research/ablation-round2.md):** three ideas were dropped:
  - the equal-or-dividing denominator check (V1), which had no effect;
  - bucketing (V2), which V3 covers;
  - shared denominator objects (V5), which helped only tiny values.

  The seen-prime dictionary was 3.5× faster than a gcd scan with 3,512 nodes.
- **[Round three](research/ablation-round3.md),** with the rule fixed before the run:
  - V3 + V4 beat V3: better on 24 of 60 comparisons, worse on 1, including 1.07–1.18 on single values that share denominators;
  - branch-free small-prime tests (D1) beat the naive dictionary by 1.10–1.43×;
  - the dictionary was 23× faster than a gcd scan at 10,000 distinct denominators and 112× at 30,000;
  - it ran at 0.89–0.93 on decimal elementwise work, 0.89–0.92 on two-large-prime denominators (W7, P64), and 0.68 at about 100 distinct denominators.
- **[Stress test](research/scalability-stress.md):** S1–S5 were implemented with V3 (V4 not included), bounded large-prime list and rho at entry.
  - Operation and entry time stayed flat up to 10⁷ values.
  - Memory and nodes stayed bounded under 10⁷ deletes and inserts, with no leaks and every invariant audit passing.
  - A gcd-scan entry grew 51× over the same growth.
  - Splitting a node shared by 10⁷ holders took 160–236 ms.
  - A deferred-factoring variant with a batch idle pass grew faster than the graph, so no batch refinement method has been validated.

## Prior art

Light and focused reviews are in [research](research/): [first pass](research/prior-art-light.md), [second pass](research/prior-art-2.md), [shared-factor techniques](research/prior-art-3-sharing.md). The closest prior art:
- **ALTRAN's factored rational expressions** (Brown; Hall, 1974): factored forms of rational functions, sharing factor objects, but explicitly not keeping them coprime;
- **FriCAS `Fraction Factored Integer`:** factors eagerly and shares nothing between values;
- **factor refinement** (Bach, Driscoll and Shallit 1993; Bernstein 2005): an algorithm, not a representation;
- **shared-denominator arrays** in FLINT and LinBox, which never factor the shared denominator.

The second pass judged the combination probably new, at about 70% confidence. A full review is planned for M3.

## Open decisions

- **Choosing the array denominator $D$** (M1 default: the lcm below $2^{63}$, else the most frequent).
- **Deferred reduction for single values.** Round three found V4 helps single values that share denominators (1.07–1.18), but M1 reduces single values after every operation (I4).
- **Parity on small graphs:**
  - the dictionary rows ran about 10% slower on decimal elementwise operations; entry times were equal, so this appears to be implementation;
  - entry is slower than a gcd scan with about 100 distinct denominators.
- **Rho at entry** costs about 60 µs per new two-large-prime denominator, once per distinct denominator. Deferring it gained nothing in round three.
- **Refining leftovers beyond 64 bits (M2).** The only batch method tested grew faster than the graph. A method that respects S4 is needed, for example refining only against leftovers that meet in an operation.
- **Edge-store memory.** Freed space is reused only within a size class, so very large splits raise memory in steps.
- **Operation set and API:** printing and parsing; conversion to and from integers, floats and 05's `Exact`; error reporting.
- **Thread safety** of the shared graph. M1 is single-threaded.
- **Array errors:** whether division by zero fails the whole array operation or marks elements.
