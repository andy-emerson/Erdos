# Signed Integers with a Header: Specification v0.1

Nov 1, 2026, revised after review and the author's decisions of that day (two rounds; two designs) · Small calls marked **(coordinator's call)**. Reviewed in [`review-v0.1.md`](review-v0.1.md). Nothing is built or run.

Two designs, A and B, each go through **round 1** (correctness) and, if it passes, **round 2** (speed and memory), against Control.

## 1. Shared parts

- **Magnitudes:** unsigned. A class code $c$ (5 bits) says where one lives: $c = 0$, the word is the magnitude; $c = 1..31$, the word is a **slot index** into the pool whose slots are $2^c$ words, lowest first. Little-endian, so 64-bit words read as 32-bit halves. Zero is class 0, word 0. Canonical: the smallest class that holds it.
- **Routines:** schoolbook, carries and borrows as values ($s < x$): add; multiply-accumulate ($r \mathrel{+}= xy$); absolute difference with its borrow; compare; Hensel exact division; binary gcd. Each reads operands at their real length (a slot up to its top nonzero word, length 0 for zero), writes at most its bound (add max + 1, multiply-accumulate $n_1 + n_2 + 1$, absolute difference max, division $n_1 - n_2 + 1$, gcd min), and returns the result's length.
- **Result class:** predicted from the operands' classes (below). The routine writes into a slot of that class, or for class 0 into a one-word local that becomes the inline word; if the result fits a smaller class it moves to the smallest that holds it and the slot is released. A prediction above 31 is an error.
- **Pools:** the owner releases a value explicitly (values are immutable), pushing its slot onto the pool's free list, linked through freed slots' first words and ended by all ones. Allocation pops the free list, else takes the next slot, else doubles the pool, from one slot at first use **(coordinator's call)**. Indices survive growth, pointers do not, so result slots are allocated first. Pools never shrink.
- **Operations:** add, subtract, negate, multiply, exact division, gcd and compare. No GPU (none to test on).

## 2. Design A: magnitude and direction

A number is an **8-bit header** (bits 0–4 class, bit 5 spare 0, bits 6–7 direction $d$ mod 4 for $1, i, -1, -i$) and a **word**, in two parallel lists.

**Header arithmetic** on 8 bits, $D = \texttt{0xC0}$, then OR in the result class: multiply `(h1 and D) + (h2 and D)`; divide `(h1 and D) - (h2 and D)`; negate `h xor 0x80`; equal-direction add, $m_1 + m_2$ with direction `h1 and D`; opposite add, $\lvert m_1 - m_2 \rvert$ with borrow $b$ and direction `(h1 and D) + (b shl 7)`; subtract adds the negation; gcd has direction 0; zero is header 0. Sums across axes are reported as an error (zero has no axis).

**Compare:** directions differ, $d = 0$ is larger; both 0, compare magnitudes; both 2, compare and reverse.

**Result class**, $L = \max(c_1, c_2)$: equal add $L+1$; opposite add $L$; multiply $L+1$; division $c_1$; gcd $\min(c_1, c_2)$, or the other's class if one is zero.

## 3. Design B: one magnitude per direction

A number is a pair $(P, N)$ of magnitudes along $+1$ and $-1$, value $P - N$. **Header:** 16 bits, the low byte $P$'s class, the high byte $N$'s, 3 spare bits 0 in each; two words, $P$'s then $N$'s **(coordinator's call)**. The direction is the part's place, not a header bit.

- **Negate:** swap $P$ and $N$. **Subtract:** negate, then add.
- **Add:** $(P_1 + P_2, N_1 + N_2)$. Never a subtraction.
- **Multiply:** $P = P_1P_2 + N_1N_2$, $N = P_1N_2 + N_1P_2$, by multiply-accumulate.
- **Collapse:** the only subtraction. $\lvert P - N \rvert$ with its borrow $b$ goes to $P$ when $b = 0$, else to $N$; the other part becomes 0. Compare, exact division, gcd and output collapse their operands first; division and gcd then work on the single magnitudes, with A's direction rules. Add and multiply never collapse.
- **Result class**, per part, $L$ the largest class among the inputs: add $L+1$; multiply $L+2$; collapse $\max(c_P, c_N)$.

B is canonical only after collapse: one part zero, each in its smallest class.

**Structures** (rule 4): stored, the slot (A) or up to two slots (B, see §6); temporary, a predicted slot on a move-down; local, the one-word local or the working buffer in division and gcd. A's parallel lists count as one structure, pending the author.

**Special cases**, named, not built: (a) a class-0 × class-0 product in registers; (b) an equal-direction add (A) or part add (B) allocating class $L$, moving up only on a carry.

## 4. Round 1: correctness

A Python model of each design, a test tool like spec 12's scripts, word by word at a tiny word size. Python's integers are only the reference. Every operation, every case:

- **Exhaustive at $W = 4$:** every pair of signed values below $2^8$ (261,121 pairs), covering carries, borrows, equal magnitudes, zero and class moves 0 to 2; division on $a = bq$. For B also every pair of uncollapsed values with both parts below $2^4$ (65,536 pairs). **(Coordinator's call.)**
- **Random at $W = 4$:** 100,000 pairs per operation, values up to 8 words, zeros and equal magnitudes forced at 1/16 each. **(Coordinator's call.)**
- **Four axes, A:** multiply, divide, negate and same-axis add and subtract on all four directions; adds across axes must report an error.
- **Four slots, B (round 1 only):** one magnitude each for $1, i, -1, -i$; add slot by slot; negate moves each slot by 2; multiply puts each product in slot $(d_1 + d_2) \bmod 4$; collapse pairs slots 0 with 2 and 1 with 3. Add, subtract, negate, multiply and collapse, sums across axes included, against Gaussian integers (integer pairs): every pair with slots below 4, and 100,000 random pairs.

**It passes** when every value equals the reference (for B, $P - N$, or the Gaussian sum of the slots), every A result and every collapsed B result is canonical, the spare bits are 0, and after all releases every slot is on its pool's free list.

## 5. Round 2: speed and memory

Details wait for round 1. Savings show only at the machine level, so A and B are written as portable pseudocode (algorithm design rule 6; a borrow is the value $a < b$), then as x86-64 machine code for the timed builds. **Control** is spec 12's Growing ([`../12-integers/v0.1.md`](../12-integers/v0.1.md) §1.4) with A's header list. Integers only.

- **Jobs:** $k \in \{1, 2, 4, 8, 16\}$ words, bit lengths uniform from $32k+1$ to $64k$, 1024 operations each, random signs; division and gcd as spec 12. A growth workload ($x \leftarrow xy + z$, 64 chains of 32 steps) exercises pool reuse and, for B, growing parts.
- **Correctness:** every result against Python, Control and the round-1 model.
- **Measures:** spec 12's timing method; bytes per value and peak; A × Control and B × Control.
- **Known costs:** rounding up (to 2× bytes, and the top-word scan); pool management (callgrind's share, move-downs); the extra read per pool number; A's opposite-direction branches; B's two magnitudes per integer, parts that grow until collapsed, and collapse itself.
