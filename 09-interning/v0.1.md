This specification defines **layer 1** of Design 3: exact rational arithmetic in which every distinct whole number is stored once, each rational is a pair of indices into that store, and every operation first compares indices to find a shortcut. It is the combined structure of [`../paper/v0.4.md`](../paper/v0.4.md) §5, which is the source of truth. Where this text and the paper disagree, the paper wins and this text is corrected. Choices this text makes where the paper is silent or leaves room are collected in §16, so that the author can rule on them one item at a time.

Layer 1 is built twice: as **L1**, the baseline, exactly as §§4–15 state, and as **L1-opt**, the same design with the production tricks of §17. Both are measured against four other rows: the control of [`../08-skeletons/v0.1.md`](../08-skeletons/v0.1.md) §6 (plain reduced rationals), FLINT `fmpq`, GMP `mpq_t`, and a FLINT shared-denominator ceiling. Their use is fixed in §10; how they are measured is in the rule. "Layer 1" without qualification means L1.

## 1. Scope

In scope: layer 1's structures, operations, integer width, index width, errors, instrumentation and correctness checks; the rows it is compared with; the boundary that says what the build contains; and the optimized variant L1-opt (§17).

Out of scope: performance targets, workloads and the measurement rule (in [`research/rule.md`](research/rule.md)); comparison, printing and parsing; threads; widths other than 64 bits; and every later layer of Design 3 (§11).

## 2. Conformance language

The key words MUST, MUST NOT, REQUIRED, SHALL, SHALL NOT, SHOULD, SHOULD NOT, RECOMMENDED, MAY and OPTIONAL are to be interpreted as described in RFC 2119 when, and only when, they appear in capitals. Sections or paragraphs marked *non-normative* state no requirement.

## 3. Terms and notation

- **Width** $w = 64$: the number of bits of every full-width integer.
- **Whole number.** A nonnegative integer stored in the whole-number list. Its **index** is its position in that list.
- **Rational.** A value $\pm\, a / b$ stored as a **numerator index**, a **sign tag** and a **denominator index**. The tag belongs to the numerator; the denominator is always positive.
- **Lowest terms:** $\gcd(a, b) = 1$ and $b \ge 1$. Zero is $0/1$ with the tag $+$.
- **Class.** One set of structures. A program creates a class, enters values into it, and applies operations to values of the same class.
- **Handle.** The position of a rational in its class's rational list: a 32-bit unsigned integer.
- **Stored.** A rational is stored when it is appended to the rational list. A stored rational is never changed. Every result is stored as a new rational.
- **Entry.** Storing a value given from outside as an integer pair $(m, d)$. **Operation:** add, subtract, multiply or divide, on two stored rationals, storing the result.
- **Operands.** The first operand $x$ has tag $s_x$, numerator index $i_x$ and denominator index $j_x$, with whole numbers $a = W[i_x]$ and $b = W[j_x]$; the second, $y$, has $s_y$, $i_y$, $j_y$, $c = W[i_y]$ and $d = W[j_y]$. The signed numerators are $m_x = s_x \cdot a$ and $m_y = s_y \cdot c$.
- **Case.** One row of the paper's table of index equalities (§5.2), named as in §7, or the **general** case, when no equality is used.
- $\text{bits}(x)$ is the number of bits of $|x|$; $\text{bits}(0) = 0$.

## 4. Requirements

### 4.1 Interface

Layer 1 MUST provide:

| Call | Effect |
| --- | --- |
| `create()` | a new, empty class |
| `destroy(class)` | frees the class and everything in it |
| `enter(class, m, d)` | stores $m/d$ in lowest terms; returns its handle, or an error |
| `add`, `sub`, `mul`, `div` `(class, x, y)` | stores the result of $x \circ y$; returns its handle, or an error |
| `read(class, x)` | returns the signed numerator and the denominator of $x$, in lowest terms |
| `size(class)` | the number of stored rationals $N$ |
| `wholes(class)` | the number of stored whole numbers $W$ |
| `memory(class, report)` | fills the memory report of §13.2 |
| `counters(class, report)` | fills the counters of §13.1 (counting build) |
| `audit(class)` | the **full audit**: checks every invariant of §14.2; returns pass or the first failure (test build) |
| `audit_changed(class)` | the **incremental audit** of §14.2; returns pass or the first failure (test build) |

The calls SHOULD follow the conventions of the 08 library (`sk_status` results, out-parameters, the types of `sk_common.h`), with the prefix `l1_`.

### 4.2 Values

1. Every stored rational MUST be in lowest terms.
2. Zero MUST be stored as $0/1$ with the tag $+$, whatever produced it.
3. Subtraction MUST be computed as addition of the negated second operand: $x - y = x + (-y)$. Negation flips the tag only; it changes no index, so every index equality of $y$ holds for $-y$.
4. `enter` MUST move the sign of $d$ to $m$ and reduce $m/d$ by $\gcd(m, d)$ before storing.
5. A stored rational and a stored whole number MUST NOT be modified, moved to another position, or freed before the class is destroyed.

### 4.3 Width and integer routines

1. Every full-width integer (whole numbers, signed numerators, gcds, cofactors, intermediates) MUST have width $w = 64$. No other width is built or measured.
2. Signed numerators MUST lie in $[-(2^{63} - 1),\ 2^{63} - 1]$, and whole numbers in $[0,\ 2^{63} - 1]$: a whole number is the magnitude of a numerator or a denominator of the 08 ranges, so the most negative integer never occurs, and negation and absolute value never overflow.
3. Layer 1 MUST NOT use an integer wider than $w$ for any full-width intermediate. The lookup hash and index arithmetic are not full-width arithmetic.
4. Layer 1 MUST use the **shared integer module of the 08 library**, [`../08-skeletons/lib/src/sk_internal.h`](../08-skeletons/lib/src/sk_internal.h), with its `common.c`, **unchanged**, and no other full-width arithmetic:
   - **gcd**: the binary method, on magnitudes, with $\gcd(a, 0) = |a|$;
   - **checked add, subtract and multiply**, each reporting overflow (§4.4);
   - **exact division** by a known divisor;
   - the counting rules of 08 spec §12.1, by the same macros.
5. A change to the 08 module is a change to 08: it goes through 08's change log, and invalidates the results of every row that uses it.

### 4.4 Overflow

1. Every full-width addition, subtraction and multiplication MUST be checked. Overflow MUST NOT wrap silently.
2. On overflow the operation MUST return the overflow error, store nothing, and record the operation, the handles of its operands, and the step, named as in the pseudocode. A whole number interned before the overflow is impossible: every result is computed before `store` runs (§6).
3. The class MUST remain valid after an overflow: every invariant of §14.2 holds.
4. The rule's workloads make overflow impossible, and treat any overflow as a bug.

### 4.5 Errors

1. `enter` with $d = 0$, and `div` with $y = 0$, MUST return the division-by-zero error and store nothing.
2. A handle not in the class MUST return the invalid-argument error, before any test for division by zero.
3. An input equal to $-2^{63}$ MUST return the invalid-argument error.
4. Out of memory MUST print a message and abort.
5. Exceeding the limits of §15 MUST abort with a message.

### 4.6 Language and build

1. Layer 1 MUST be written in C (C11), single-threaded, with no library beyond the C standard library and the 08 module.
2. Layer 1, the control and the benchmark driver MUST be compiled by the same compiler with the same flags (`gcc -std=c11 -O2`).
3. There MUST be three builds of the same source, differing only in compile-time settings, as in 08 (`SK_COUNT`, `SK_AUDIT`):
   - the **timing build**: counters and audits compiled out;
   - the **counting build**: counters compiled in, audits out;
   - the **test build**: counters and audits compiled in.

   L1-opt has the same three builds (§17).
4. Counters and audits MUST NOT change the control flow or the results of any operation.

## 5. Structures

Layer 1 MUST keep exactly three structures.

| Structure | Shape | Each entry stores |
| --- | --- | --- |
| Whole numbers | list of $W$ | one whole number (64 bits) |
| Lookup | array of $S$ slots | a whole-number index, or empty (32 bits) |
| Rationals | list of $N$ | a numerator field and a denominator index (32 bits each) |

1. **Lists.** A list MUST only grow at its end, by doubling its capacity. An index or handle, once given, MUST refer to the same entry for the life of the class.
2. **Whole numbers.** Each distinct whole number MUST be stored exactly once. There is no separate list of numerators or of denominators: one whole number may be the numerator of some rationals and the denominator of others.
3. **Lookup.** The lookup MUST be the 08 lookup (08 spec §5 item 2), by the same code, over the whole-number list: a hash table of indices with linear probing; $S$ a power of two, initially 16; doubled, with every index placed again in index order, before an insertion would make it more than half full; the starting slot of a value $v$ is $\lfloor (v \cdot \phi \bmod 2^{64}) / 2^{64 - \log_2 S} \rfloor$ with $\phi = \text{9E3779B97F4A7C15}_{16}$; a slot holds an index, never a value.
4. **Rationals.** An entry is 8 bytes: two 32-bit unsigned fields.
   - The **numerator field** holds the sign tag in its top bit (0 for $+$, 1 for $-$) and the numerator index in its low 31 bits.
   - The **denominator field** holds the denominator index.
   - So a numerator index is below $2^{31}$, and the whole-number list is limited by §15.
5. Nothing is stored inline: every whole number, however small, is in the whole-number list, and every field of a rational is an index into it (§11).

## 6. Storing a result, and entry

`store` appends a result. The operations compute the result's signed numerator $n$ and denominator $e \ge 1$, in lowest terms, before calling it; `store` does no arithmetic.

```text
function store(n over e)                          n / e in lowest terms, e ≥ 1
    if n is 0 then
        set e to 1
    end if
    if n is negative then
        set the tag s to −
    else
        set the tag s to +
    end if
    set i to intern(|n|)                          the numerator first
    set j to intern(e)                            then the denominator
    append (s, i, j) to the rationals
    return the handle of the new rational
end function

function intern(v)                                v ≥ 0
    look v up
    if v is found at index k then
        return k
    end if
    append v to the whole numbers as index k
    place k in the lookup
    return k
end function
```

1. **Every whole number of every result is looked up** (paper §5.1), including one that the operation knows to be an operand's whole number (§16, L-6, the author's ruling). Skipping such lookups is a trick of L1-opt (§17, O-1), not part of L1.
2. Interning the numerator before the denominator reproduces the indices of the paper's worked example (§5.5): entering $\tfrac{1}{6}$, $-\tfrac{5}{6}$, $\tfrac{5}{7}$, $\tfrac{6}{7}$ gives $1, 6, 5, 7$ at indices $0$ to $3$.
3. No whole number is stored in advance: $0$ and $1$ are interned when first used, like any other.

Entry reduces the given pair and stores it:

```text
function enter(m, d)
    if d is 0 then
        fail with division by zero
    end if
    if d is negative then
        set m to −m and d to −d
    end if
    set g to gcd(m, d)
    return store((m / g) over (d / g))
end function
```

## 7. Index checks and the choice of case

Before its arithmetic, every operation reads the four indices and makes the paper's four index comparisons (paper §5.3), each in constant time:

| Comparison | Equal means |
| --- | --- |
| $j_x$ with $j_y$ | same denominator, $b = d$ |
| $i_x$ with $i_y$ | same numerator, $a = c$ (in magnitude) |
| $i_x$ with $j_y$ | cross, $a = d$ |
| $i_y$ with $j_x$ | cross, $c = b$ |

Because each whole number is stored once, two indices are equal exactly when the whole numbers are equal. The four comparisons MUST all be made, in this order, before any case is chosen, whatever case is then taken; only division's zero test comes before them (§8.3). The equal ones select a case. When several select cases, the case with the **fewest gcds left** MUST be taken (paper §5.3); among cases with equally few, the order below decides (§16, L-8). Each operation takes its cases in this order, the first that applies:

| Operation | Order of cases (gcds left) |
| --- | --- |
| add, subtract | `cross` (0) · `den` (1) · `num` (2, or 1 when $\gcd(b, d) = 1$) · `general` (1 or 2) |
| multiply | `both` (0) · `den` (0) · `num` (0) · `cross_ad` (1) · `cross_cb` (1) · `general` (2) |
| divide | `both` (0) · `cross_ad` (0) · `cross_cb` (0) · `num` (1) · `den` (1) · `general` (2) |

*Non-normative.* Several cases apply at once only in degenerate operands: in addition, `cross` and `den` together need $b = d = 1$; in multiplication, `den` and `num` together mean equal magnitudes, where both give $a^2/d^2$. Every case gives the same value; the order only fixes which one is counted. In addition, `num` is taken before `general` though both may leave the same gcds, because it saves one multiplication (paper §5.4). A zero operand is $0/1$, so it meets the `cross` cases only through the whole number 1, never through 0.

## 8. Operations

Each operation follows its pseudocode, in the order of gcds, divisions and multiplications written. A quantity written twice in one function is computed once (08 library DEC-18). Multiplying by a tag or a sign is not counted and cannot overflow (08 counting rule 1). The general case of each operation is the control's procedure (08 spec §6) with its equal-denominator test removed, since the index comparison has already decided it.

**The control has shortcuts of its own.** It compares the two denominators by value, $d_x = d_y$, and when they are equal it takes a shortcut in all three operations (08's `ctl.c`, and `sk_ctl_divide_pair` in 08's `common.c`):
- **addition and subtraction:** one addition and $\gcd(t, d)$, with no multiplication;
- **multiplication:** the two multiplications $m_x m_y$ and $d \cdot d$, with no gcd;
- **division:** the gcd of the numerators and its two exact divisions, with no second gcd and no multiplication.

L1's case `den` of each operation does exactly this work. **Case `den` saves no gcd, no division and no multiplication against the control**: it replaces one value comparison by one index comparison, both constant time at 64 bits. So L1 and the control differ by three things:
- the four index comparisons, in place of the control's one comparison of denominators;
- the cases `cross`, `num`, `both`, `cross_ad` and `cross_cb`, which the control does not have;
- the store, with its lookups.

Every gcd or multiplication that L1 saves against the control comes from those five cases. On operations in cases `den` and `general`, L1's gcds, gcd work, divisions, multiplications and additions MUST equal the control's exactly (§14.1 item 3); the rule reports the gcd and multiplication ratios per case (rule item 6).

### 8.1 Addition and subtraction

```text
function add(x, y)                                x = s_x · a / b,  y = s_y · c / d
    read i_x, j_x, i_y, j_y and the tags s_x, s_y
    make the four index comparisons of §7
    read a, b, c, d from the whole numbers
    set m_x to s_x · a and m_y to s_y · c
    if i_x equals j_y or i_y equals j_x then                  case cross: gcd(b, d) = 1
        return store((m_x · d + m_y · b) over (b · d))
    end if
    if j_x equals j_y then                                    case den: gcd(b, d) = d
        set t to m_x + m_y
        set h to gcd(t, d)
        return store((t / h) over (d / h))
    end if
    if i_x equals i_y then                                    case num: gcd(a, b · d) = 1
        set g to gcd(b, d)
        set b′ to b / g and d′ to d / g
        set t to s_x · d′ + s_y · b′
        if g is 1 then
            set h to 1
        else
            set h to gcd(t, g)
        end if
        return store((a · (t / h)) over (b′ · (d / h)))
    end if
    set g to gcd(b, d)                                        case general
    if g is 1 then
        return store((m_x · d + m_y · b) over (b · d))
    end if
    set b′ to b / g and d′ to d / g
    set t to m_x · d′ + m_y · b′
    set h to gcd(t, g)
    return store((t / h) over (b′ · (d / h)))
end function

function subtract(x, y)
    return add(x, y with its tag flipped)
end function
```

1. **Case `cross`.** If $a = d$, then $\gcd(b, d) = \gcd(b, a) = 1$, so the direct form is already in lowest terms (paper §5.2): three multiplications and one addition, no gcd. Likewise if $c = b$.
2. **Case `den`.** One addition and one gcd on the full $d$ (paper §3.1). No deferred reduction: the result is reduced at once (§11).
3. **Case `num`.** The refined method with numerator $a \cdot t$, where $t = s_x d' + s_y b'$: since $a$ is coprime to $b d$, only $t$ meets $g$ (paper §5.2). Two multiplications, against three in the general case. When $g = 1$ the second gcd is skipped, as in the refined method (paper §2.1) and in the control (§16, L-9).
4. **The result's tag** is that of the signed numerator passed to `store`, which is the paper's rule: the first tag times the sign of the sum or difference of magnitudes.

### 8.2 Multiplication

```text
function multiply(x, y)
    read i_x, j_x, i_y, j_y and the tags s_x, s_y
    make the four index comparisons of §7
    read a, b, c, d from the whole numbers
    set s to s_x · s_y, m_x to s_x · a and m_y to s_y · c
    if i_x equals j_y and i_y equals j_x then                 case both: a = d and c = b
        return store(s over 1)
    end if
    if j_x equals j_y then                                    case den: no gcd
        return store((m_x · m_y) over (d · d))
    end if
    if i_x equals i_y then                                    case num: no gcd
        return store((s · (a · a)) over (b · d))
    end if
    if i_x equals j_y then                                    case cross_ad: a cancels
        set h to gcd(c, b)
        return store((s · (c / h)) over (b / h))
    end if
    if i_y equals j_x then                                    case cross_cb: b cancels
        set h to gcd(a, d)
        return store((s · (a / h)) over (d / h))
    end if
    set g_1 to gcd(m_x, d)                                    case general
    set g_2 to gcd(m_y, b)
    return store(((m_x / g_1) · (m_y / g_2)) over ((b / g_2) · (d / g_1)))
end function
```

Case `both` stores $\pm 1 / 1$ with no arithmetic: $\tfrac{a}{b} \cdot \tfrac{b}{a} = 1$, with the sign the product of the tags (paper §5.2). Cases `den` and `num` need no gcd, since operands in lowest terms leave nothing to cancel (paper §4.1, §5.2).

### 8.3 Division

```text
function divide(x, y)
    read i_x, j_x, i_y, j_y and the tags s_x, s_y
    read a, b, c, d from the whole numbers
    if c is 0 then
        fail with division by zero
    end if
    make the four index comparisons of §7
    set s to s_x · s_y
    if i_x equals i_y and j_x equals j_y then                 case both: a = c ≠ 0 and b = d
        return store(s over 1)
    end if
    if i_x equals j_y then                                    case cross_ad: a²/(b · c), no gcd
        return store((s · (a · a)) over (b · c))
    end if
    if i_y equals j_x then                                    case cross_cb: a · d / b², no gcd
        return store((s · (a · d)) over (b · b))
    end if
    if i_x equals i_y then                                    case num: a cancels, gcd(d, b) left
        set h to gcd(d, b)
        return store((s · (d / h)) over (b / h))
    end if
    if j_x equals j_y then                                    case den: b cancels, gcd(a, c) left
        set h to gcd(a, c)
        return store((s · (a / h)) over (c / h))
    end if
    set g_1 to gcd(a, c)                                      case general
    set g_2 to gcd(b, d)
    return store((s · ((a / g_1) · (d / g_2))) over ((b / g_2) · (c / g_1)))
end function
```

1. The divisor's whole number $c$ is tested for zero **before** the index comparisons, by reading it (§16, L-12): this excludes $\tfrac{0}{1} \div \tfrac{0}{1}$, which cancelling would otherwise give as 1 (paper §4.1). An operation that fails stores nothing and takes no case.
2. The result's denominator is a product of magnitudes, so it is positive; the divisor's sign moves into $s$ (paper §2.3).
3. The general case is the control's divide on magnitudes, with the sign carried in $s$; it makes the same gcds, divisions and multiplications.

### 8.4 Size of intermediates (non-normative)

Every intermediate of every case is bounded as in the control: a product of a quantity at most $H(x) = \max(|m_x|, b)$ with one at most $H(y)$, or a sum of two such products. The cases add only $a \cdot (t/h) \le a(d + b) \le 2 H(x) H(y)$ (case `num` of addition), $a \cdot a$ with $a = d$, $b \cdot b$ with $b = c$, and $d \cdot d$, each at most $H(x) H(y)$. So the 08 size bound $H(x) H(y) \le (2^{31} - 1)^2$ rules out overflow in layer 1 as in the control.

## 9. The control

The control is the control of 08 spec §6: each value stored as its own pair $(m, d)$ in one value list, operations by the gcd-first method. It MUST be the 08 library's `ctl.c`, compiled **unchanged** with the 08 module, by the same compiler and flags as layer 1. Its memory report and counters are those of 08 spec §12.

## 10. The library rows

Each external library gets its **best normal use**, as in the M3 comparison (07 `research/m3-rule.md` item 8). Every library row MUST:
- run single-threaded (`flint_set_num_threads(1)`), and record the GMP and FLINT versions in every output line;
- keep **every stored value**, entered and result, as its own element of a holder array of exactly $N$ elements, allocated before the timed phases and freed after them, untimed (as in M3);
- read out every stored value as two signed 64-bit integers in lowest terms, after a fits test.

| Row | Entry | Operation | Read-out |
| --- | --- | --- | --- |
| **fmpq** (FLINT) | `fmpq_init`, `fmpq_set_si(x, m, d)` (canonicalises) | `fmpq_init(r)`, then `fmpq_add`, `fmpq_sub`, `fmpq_mul` or `fmpq_div` | `fmpz_fits_si`, `fmpz_get_si` |
| **mpq** (GMP) | `mpq_init`, `mpq_set_si(x, m, d)`, `mpq_canonicalize` | `mpq_init(r)`, then `mpq_add`, `mpq_sub`, `mpq_mul` or `mpq_div` | `mpz_fits_slong_p`, `mpz_get_si` |
| **fz** (FLINT ceiling) | $D$ = the lcm of the distinct input denominators (one `fmpz_lcm` each), computed from the data; each numerator scaled by $D/d$ (each distinct cofactor computed once) with `fmpz_mul_si` | `fmpz_init(r)`, then `fmpz_add` or `fmpz_sub` of the numerators over $D$ | `fmpq_set_fmpz_frac(q, n, D)`, then `fmpz_get_si`, timed |

1. **Forms.** Each of fmpq and mpq has two normal forms, and the rule's calibration picks the faster per job (rule item 4):
   - **form A** (M3's single-value form): each element is initialised inside the timed phase in which its value is stored;
   - **form B** (M3's array form): every element is initialised before the timed phases of a run, untimed, and cleared after it.

   Form B moves initialisation out of timing; offering it biases the time comparison toward the libraries, on purpose.
2. **The ceiling fz** holds every value as an `fmpz` numerator over one shared denominator $D$, and reduces only at read-out. It is a reference point, not a contender. It runs only on jobs in which every operation is an addition or subtraction of values over one input denominator (the rule's ceiling jobs), where every result stays over $D$.
3. **Every result is kept** in every row, the libraries included: a chain step stores a new element rather than updating the previous one in place, because every row is measured on the same stored values and the same read-out.

   **A limitation, reported with the results.** On the chain jobs this is not the libraries' normal use. A program that only needs a chain's current value would update it in place (`fmpq_add(x, x, y)`), reusing its limbs and keeping one element per chain, not one per step; that would cost the libraries fewer initialisations and far less memory. Keeping every result charges them for both. Form B (item 1) partly offsets the time: it moves every initialisation out of the timed phases. It does not offset the memory: every result is still a live element. L1 and the control keep every result too, so the comparison is like for like, but on chain jobs it is not each library's best normal use, and the report says so beside every chain verdict against fmpq, mpq and the best library.
4. Division by zero cannot occur in the rule's workloads; the driver checks every divisor before timing and refuses a workload that has one.

## 11. Layer 1's boundary

The build MUST be a **faithful baseline of the paper's combined structure** (paper §5): the plainest correct form of it. Bugs and plain inefficiencies inside it are fixed. Nothing outside it is added.

**Inside layer 1:**
- one width, 64 bits, with overflow detected by the 08 module; schoolbook arithmetic;
- one list of distinct whole numbers, each stored once, unsigned; one hash lookup from value to index (the 08 lookup);
- rationals as two 32-bit fields, the sign tag in the numerator field;
- every stored rational in lowest terms, reduced in the operation that produced it;
- the four index comparisons at the start of every operation, and the cases of the paper's §5.2 table, chosen by fewest gcds left (§7);
- the refined (gcd-first) method of the control in the general case.

**Outside layer 1** (MUST NOT be built):
- **deferred reduction** (paper §3.3, §5.3), and any unreduced stored value: no running totals kept outside the structure;
- an **inline small-value tag**: storing small whole numbers in the index fields instead of in the list (excluded by the author's decision);
- a **complex or axis tag** on rationals: a possible later extension, not part of this test;
- **partial sharing**: a coprime base, common divisors, factor rows or any record of what two whole numbers share beyond equality (paper §5.6);
- clusters, reference counts, freeing or reusing whole numbers, garbage collection;
- deduplicating rationals: two equal results are two rationals, with the same indices;
- caching gcds, cofactors, products, powers or the results of earlier operations;
- skipping the lookup of a whole number that the operation knows is an operand's (the author's ruling, §16, L-6), and every other trick of L1-opt (§17), which are built only in L1-opt;
- a numerator list or a denominator list separate from the one whole-number list;
- integers wider than 64 bits, other widths, threads, SIMD intrinsics, batching, fast multiplication.

## 13. Instrumentation

### 13.1 Counts

In the counting build, layer 1 MUST count, separately for each **phase** (entry, add, subtract, multiply, divide) and within each phase for its **core** (everything before `store`) and its **store**, every counter of 08 spec §12.1 that applies (gcds with their histogram and gcd work, exact divisions, multiplications, additions, `bitops`, lookup searches and probes), by the 08 counting rules, and also:

| Counter | Counts |
| --- | --- |
| index comparisons | the comparisons of §7, four per operation that reaches them (reported only) |
| cases | per phase, the operations that took each case of §7: add and subtract `cross`, `den`, `num`, `general`; multiply `both`, `den`, `num`, `cross_ad`, `cross_cb`, `general`; divide `both`, `cross_ad`, `cross_cb`, `num`, `den`, `general` |
| general with $g = 1$ | additions and subtractions in case `general` whose $\gcd(b, d)$ is 1, and in case `num` whose $g$ is 1 |
| interned | `intern` calls, split into **found** and **appended** (new whole numbers) |
| zero results | results stored as $0/1$ |
| overflows | as in 08 |

Counting rules, beyond those of 08 spec §12.1:
1. An index comparison is not an addition; reading a whole number or a field is not counted.
2. The tags, $s$, and every multiplication by a tag or sign are not counted.
3. Each `intern` counts one lookup search, with its probes; a growth of the lookup counts as in 08 (one search per index placed again, one probe per slot read), under `store`.

The counters MUST be readable at any time, and MUST be reset only by `create`. The control's counters are those of 08.

### 13.2 Memory

`memory` MUST report, for each structure, the **used bytes** (entries times entry size) and the **allocated bytes** (capacity):

| Structure | Used bytes |
| --- | --- |
| whole numbers | $8W$ |
| lookup | $4S$ (every slot, empty or not) |
| rationals | $8N$ |

**Bytes per rational** is the total used bytes divided by $N$, the number of stored rationals: $B = 8 + (8W + 4S)/N$. Allocated bytes per rational is reported beside it. The class header and per-call temporaries are not structures and are not counted (as 08 DEC-27). The control reports $16N$ (08 spec §12.2).

The library rows have no report of their own. The rule measures them, and every other row, by allocator hooks and by the C library's own heap statistics (rule item 6). A library's holder array is allocated at its full size $N$ before entry, but it is charged only for the elements stored so far (rule item 6): after entry, 10,000 of 30,000 elements are stored, and charging the whole array would charge the libraries about three times their holder bytes.

### 13.3 Timing

The implementations hold no timers. The driver times entry, operations and read-out separately, with a monotonic clock read only between calls.

## 14. Correctness

### 14.1 Against an exact reference

Every stored value of every run, in every row, MUST be read out and compared with an exact reference computed with arbitrary-precision rationals (Python's `fractions`), independently of the 08 module: numerator and positive denominator, both in lowest terms, must be equal. Any mismatch fails the run for that row.

Layer 1 has two further exact checks, against figures the generator computes from the reference alone:
1. the number of whole numbers $W$, after entry and at the end, MUST equal the number of distinct magnitudes among the numerators and denominators of the stored values;
2. the count of each case, per phase, MUST equal the generator's prediction, made by applying the comparisons and the order of §7 to the operands' magnitudes. The generator writes the predicted case of every operation, not only the totals.

One exact check compares L1 with the control:

3. **Cases `den` and `general` against the control.** In the counting runs, the driver reads the counters of L1 and of the control after every call, and attributes each operation's core counts to the case the generator predicted for it. Summed over the operations of case `den`, and over those of case `general`, of each operation, L1's gcds, gcd work, exact divisions, multiplications and additions MUST equal the control's (§8). A difference is a bug in L1 or in the attribution.

### 14.2 Invariants

`audit` MUST check, in the test build:
- **rationals:** every field holds an index below $W$; every denominator is at least 1; $\gcd(\text{numerator}, \text{denominator}) = 1$; a zero numerator has the denominator 1 and the tag $+$;
- **whole numbers:** each lies in $[0,\ 2^{63} - 1]$; no two are equal; each is used by at least one rational;
- **lookup:** every index is found by the lookup at its value; the lookup holds exactly $W$ indices and is at most half full.

`audit_changed` MUST make the same checks, restricted to what changed since the last audit: the rationals stored since then; the whole numbers appended since then, each found at its index and used; the lookup's count and load. The test build records what changed in a change list that only the audits read.

### 14.3 Tests

1. Unit tests MUST cover:
   - **the paper's worked example (§5.5), exactly:** the four entries and their indices; each of the eight operations applied to the original four values, in the paper's order, with the case taken, the gcds made (one or none, as the paper's table says), the result, and the indices appended or found;
   - **every case of every operation,** with the paper's examples where it gives one: $\tfrac{1}{6} + \tfrac{1}{6} = \tfrac{1}{3}$; $\tfrac{7}{6} + \tfrac{7}{10} = \tfrac{28}{15}$; $\tfrac{2}{3} + \tfrac{5}{2} = \tfrac{19}{6}$; $\tfrac{3}{7} \cdot \tfrac{2}{7} = \tfrac{6}{49}$; $\tfrac{3}{4} \cdot \tfrac{3}{5} = \tfrac{9}{20}$; $\tfrac{4}{9} \cdot \tfrac{3}{4} = \tfrac{1}{3}$; $\tfrac{a}{b} \cdot \tfrac{b}{a} = \pm 1$; $\tfrac{4}{9} \cdot \tfrac{3}{8} = \tfrac{1}{6}$; $\tfrac{1}{2} \div \tfrac{1}{4} = 2$; $\tfrac{3}{10} \div \tfrac{9}{10} = \tfrac{1}{3}$; $\tfrac{2}{3} \div \tfrac{5}{2} = \tfrac{4}{15}$; $\tfrac{2}{3} \div \tfrac{3}{5} = \tfrac{10}{9}$; $\tfrac{2}{9} \div \left(-\tfrac{4}{3}\right) = -\tfrac{1}{6}$;
   - **signs:** each case with every combination of tags, including a shared numerator of opposite tags in addition ($\tfrac{7}{6} - \tfrac{7}{10}$) and $x - x = 0$ stored with the tag $+$;
   - **zero:** zero as either operand of every operation, zero results, $0 \div y$, and $\tfrac{0}{1} \div \tfrac{0}{1}$ reported as division by zero;
   - **overlaps:** operands for which several comparisons are equal, checked to take the case that §7 names;
   - **entry:** negative denominators, unreduced input, $d = 0$, $m = -2^{63}$;
   - an overflow at each named step of each case, with nothing stored and the class valid;
   - **the store:** a result whose whole numbers are both found, both new, and one of each; a result equal to an earlier one, stored as a new rational with the same indices; growth of the lookup;
   - **shortcuts change nothing:** in the test build only, a switch that sends every operation to its general case; on random operands of every case, both settings MUST give the same stored values and the same whole-number list.
2. **The gate.** Every job of the rule MUST pass, in the test build and before any measured run, one complete run audited as in 08 spec §13.3 item 2: a full audit after each of the first 200 calls (entries count as calls), then after every 64th call, and after the last; `audit_changed` after every call between them.

## 15. Limits

Fewer than $2^{31} - 1$ whole numbers per class (a numerator index has 31 bits; the value $2^{31} - 1$ is kept free), and fewer than $2^{32} - 1$ stored rationals per class. Exceeding either aborts (§4.5). *Non-normative:* at the cap, the whole-number list alone takes 16 GiB, beyond any job of the rule.

## 16. Choices not settled by the paper

Each item is a choice this specification makes where the paper is silent or leaves room. Each is **approved by the author, Oct 29, 2026**; L-6 the author had ruled earlier the same day. The choices of L1-opt are in §17.

- **L-1** (§5, §15). **Index width and sign.** Two 32-bit fields per rational, 8 bytes; the sign tag is the top bit of the numerator field, so a numerator index has 31 bits and the whole-number list is capped below $2^{31} - 1$. The alternative, a separate tag byte with full 32-bit indices, costs 9 bytes (12 if padded) per rational.
- **L-2** (§4.3). Whole numbers are stored as 64-bit words in $[0,\ 2^{63} - 1]$, the 08 ranges, so that the 08 module's signed checks apply unchanged. The top bit of the word is unused.
- **L-3** (§5). One lookup over all whole numbers, by the 08 lookup's code: linear probing, doubling at half full, the multiplicative hash, $S = 16$ at first.
- **L-4** (§6). A result's numerator is interned before its denominator; this reproduces the paper's example.
- **L-5** (§6). Nothing is stored in advance: $0$ and $1$ are interned when first used.
- **L-6** (§6, §11). **Ruled by the author, Oct 29, 2026.** In L1, every whole number of every result is looked up, as paper §5.1 says, even when the operation knows it equals an operand's: for example, in a one-gcd case whose gcd is 1, such as $\tfrac{a}{b} \cdot \tfrac{c}{a}$ with $\gcd(c, b) = 1$, the result $c/b$ has the second operand's numerator and the first operand's denominator. Skipping those lookups is trick O-1 of L1-opt (§17). (A $\pm 1$ result is not such a case: in $\tfrac{a}{b} \cdot \tfrac{b}{a}$, the whole number 1 is usually neither operand's; L1-opt's O-2 covers it.)
- **L-7** (§11). Rationals are not deduplicated: every result is a new rational, as in 08.
- **L-8** (§7). The order among cases with equally few gcds left: in addition, `cross`, `den`, `num`, `general`; in multiplication, `both`, `den`, `num`, `cross_ad`, `cross_cb`, `general`; in division, `both`, `cross_ad`, `cross_cb`, `num`, `den`, `general`. Fewer multiplications first, then the paper's order of rows.
- **L-9** (§8.1). Case `num` of addition skips its second gcd when $g = 1$, as the refined method and the control do; the paper's table lists two gcds left.
- **L-10** (§8). The general cases are the control's procedures with their equal-denominator test removed. The control's own equal-denominator shortcuts do the work of L1's case `den`, so the two rows differ by the index comparisons, the five cases the control lacks, and the store (§8).
- **L-11** (§8). The arithmetic works on signed numerators formed from the tags; `store` splits the sign again. This gives the paper's sign rule, and tags cost nothing in the counts.
- **L-12** (§8.3). Division tests its divisor for zero by reading the whole number, before the index comparisons, rather than by comparing with the index of $0$.
- **L-13** (§7). The four comparisons are all made in every operation, in a fixed order, before a case is chosen, rather than only until the first equal one.
- **L-14** (§10). The library rows: the calls of §10; forms A and B of fmpq and mpq, calibrated per job; holder arrays of exact size allocated untimed, and charged for their stored elements only; every result kept, with no in-place form, in every row, which on chain jobs is not the libraries' normal use and is reported as a limitation (§10 item 3).
- **L-15** (§10). The ceiling is FLINT's, as in M3 (fz), and runs only on jobs whose operations are additions and subtractions over one input denominator.
- **L-16** (§13.1). New counters: index comparisons, cases per phase, general with $g = 1$, interned found and appended, zero results. Layer 1's count record extends the 08 record.
- **L-17** (§13.2). Bytes per rational counts the whole lookup array, empty slots included, as 08 does.
- **L-18** (§14.1). Two further exact checks: $W$ against the reference, and the case counts against the generator's prediction.
- **L-19** (§12). If the author cannot be reached, the builder decides by the plainest option and records it as pending review; 08 spec §11 said only "ask the author", and its builder had to resolve the conflict alone (08 library `DECISIONS.md`).
- **L-20** (§14.1 item 3). An exact check that L1's cases `den` and `general` do the control's arithmetic, operation for operation, so that every saving against the control is traced to the five cases the control lacks.

## 17. The optimized variant, L1-opt

*The row and trick O-1 are the author's requirement, Oct 29, 2026. Every other trick, and every detail below that the author did not state, is **approved by the author, Oct 29, 2026**.*

L1-opt is layer 1 with production-worthy tricks added. It is built separately from L1 and run as its own row on the same workloads, gates and checks (rule item 1). L1 stays the faithful baseline of §11; L1-opt shows how much of any gap is the baseline's plainness rather than the design.

1. **What stays.** Everything in §§4–15 holds for L1-opt unless a trick below says otherwise: the interface, with the prefix `l1o_`; the three structures (O-6 changes the lookup's slots); the values; the 08 module; the cases, chosen in the order of §7; the limits. On every workload, every stored value, and the whole-number list in order, MUST be identical to L1's.
2. **Source.** L1-opt SHOULD be built from L1's source with a compile-time setting `L1_OPT`, so that the two rows differ only by the tricks; with `L1_OPT` off, the source compiles to L1. In the test build, each trick has its own switch that turns it off (§17.3).
3. **Excluded, by the author:** inline small values; an axis or complex tag; partial sharing; clusters, reference counts, freeing or garbage collection; threads. **Excluded, as in L1:** deferred reduction and unreduced stored values; deduplicating rationals; caching gcds or results; widths other than 64 bits; any change to the 08 module.
4. **One row, every trick on.** The timed row runs with every adopted trick on. Each trick has its own counters (§17.2), so its effect on the work is seen separately; its effect on time is not timed alone.

### 17.1 The tricks

**O-1. Known indices when h = 1 (the author's requirement).** In five one-gcd cases, when the one gcd h is 1, the result's whole numbers are operands' whole numbers, whose indices the operation already holds. Their lookups are skipped:

| Operation, case | h | Result when h = 1 | Lookups skipped |
| --- | --- | --- | --- |
| add, subtract, `den` | $\gcd(t, d)$ | $t / d$ | the denominator, index $j_x$ (the numerator $t$ is looked up) |
| multiply, `cross_ad` | $\gcd(c, b)$ | $\pm c / b$ | both: $i_y$ and $j_x$ |
| multiply, `cross_cb` | $\gcd(a, d)$ | $\pm a / d$ | both: $i_x$ and $j_y$ |
| divide, `num` | $\gcd(d, b)$ | $\pm d / b$ | both: $j_y$ and $j_x$ |
| divide, `den` | $\gcd(a, c)$ | $\pm a / c$ | both: $i_x$ and $i_y$ |

The arithmetic is L1's, unchanged; only the store changes. A zero result needs no special rule: $\gcd(0, x) = x$, so a zero numerator meets h = 1 only over a denominator of 1, whose index is then the known one.

```text
function store_known(n, i, e, j)                  n / e in lowest terms, e ≥ 1
                                                  i: the index of |n|, or unknown
                                                  j: the index of e, or unknown
    if n is 0 then
        set e to 1
    end if
    if n is negative then
        set the tag s to −
    else
        set the tag s to +
    end if
    if i is unknown then
        set i to intern(|n|)
    else
        count one skipped lookup
    end if
    if j is unknown then
        set j to intern(e)
    else
        count one skipped lookup
    end if
    append (s, i, j) to the rationals
    return the handle of the new rational
end function
```

Each of the five cases ends as follows, in place of its last line in §8:

```text
    case den of add:                              h = gcd(t, d)
        if h is 1 then
            return store_known(t / h, unknown, d / h, j_x)
        end if
        return store((t / h) over (d / h))

    case cross_ad of multiply:                    h = gcd(c, b)
        if h is 1 then
            return store_known(s · (c / h), i_y, b / h, j_x)
        end if
        return store((s · (c / h)) over (b / h))

    case cross_cb of multiply:                    h = gcd(a, d)
        if h is 1 then
            return store_known(s · (a / h), i_x, d / h, j_y)
        end if
        return store((s · (a / h)) over (d / h))

    case num of divide:                           h = gcd(d, b)
        if h is 1 then
            return store_known(s · (d / h), j_y, b / h, j_x)
        end if
        return store((s · (d / h)) over (b / h))

    case den of divide:                           h = gcd(a, c)
        if h is 1 then
            return store_known(s · (a / h), i_x, c / h, i_y)
        end if
        return store((s · (a / h)) over (c / h))
```

In the test build, `store_known` MUST check that each known index holds the number it stands for, $W[i] = |n|$ and $W[j] = e$, and abort otherwise.

**O-2. The indices of 0 and 1 (approved by the author, Oct 29, 2026).** The class remembers the index of the whole number 1 and of 0, once each has been interned; both stay in the whole-number list like any other whole number, so nothing is inline. A stored value, entry included, whose denominator is 1 (an integer, the $\pm 1$ of a `both` case, a zero $0/1$), or whose numerator has magnitude 0 or 1, is then stored without looking that whole number up. Until 1 (or 0) has been interned, it is looked up as in L1. A lookup that O-1 already skips is counted under O-1 only.

**O-3. Gcds with a known 1 (approved by the author, Oct 29, 2026).** A gcd one of whose arguments is an operand's whole number at the index of 1 (known by O-2) is not computed: its value is 1. For example: a general multiplication by an integer $c/1$ skips $\gcd(m_x, d)$; a general division by an integer skips $\gcd(b, d)$; a general addition with $b = 1$ or $d = 1$ skips $\gcd(b, d)$ and takes the $g = 1$ path; case `den` over $d = 1$ skips $\gcd(t, 1)$. Rational libraries commonly make this test for integer operands.

**O-4. No arithmetic with a known 1 (approved by the author, Oct 29, 2026).** An exact division by 1, or a multiplication by 1, is skipped when the 1 is known without a comparison of values: a gcd that came out as 1 (one skipped by O-3 included, and case `num`'s $h = 1$ when $g = 1$), or a whole number at the index of 1. **Inheritance:** a value's status as a known 1 passes on exactly as follows. A quotient by a known 1 takes the dividend's status, and a product with a known 1 takes the other factor's status; a signed numerator takes its whole number's status; a sum or difference is never a known 1. Only a sign is applied where a division or multiplication is skipped. O-4 also applies in `enter`: when $\gcd(m, d) = 1$, both divisions are skipped. For example, case `den` of addition with $h = 1$ skips $t/h$ and $d/h$, and a general multiplication with $g_1 = g_2 = 1$ skips four divisions.

**O-5. Zero from equal operands (approved by the author, Oct 29, 2026).** In addition and subtraction, when case `den` is taken, $i_x = i_y$, and the effective tags differ ($x - x$, or $x + (-x)$), the result is $0/1$, stored with no addition and no gcd. In L1 it costs one addition and $\gcd(0, d)$. It is expected to be rare in the rule's workloads, and is reported for completeness.

**O-6. Fingerprints in the lookup slots (approved by the author, Oct 29, 2026).** Each lookup slot holds the index and the low 32 bits of the value's hash product $v \cdot \phi \bmod 2^{64}$ as a fingerprint (the starting slot uses the top bits), 8 bytes in all; a probe reads the whole-number list only when the fingerprint matches. This saves a read from another place in memory on nearly every probe that does not match. It costs 4 more bytes per slot: the lookup's used bytes become $8S$, and bytes per rational $8 + (8W + 8S)/N$. L1-opt then no longer shares the 08 lookup's code: it keeps its hash, probing order and growth rule, with its own slot layout.

**O-7. A reserved rational list (approved by the author, Oct 29, 2026).** Before entry, untimed, the driver calls `l1o_reserve(class, N)`, which sizes the rational list for exactly $N$ rationals: the same knowledge the library rows get for their holder arrays (§10). The whole-number list and the lookup are not reserved, since their sizes depend on the results.

*Not proposed:* deferred reduction, which would store unreduced values and break the invariant every case relies on; and caching gcds or earlier results, which adds a structure whose memory grows with the run.

### 17.2 Counters

In the counting build, L1-opt has every counter of §13.1 and, per trick, per phase, and within each phase for core and store:

| Trick | Counters |
| --- | --- |
| O-1 | lookups skipped, per case of the O-1 table |
| O-2 | lookups skipped, split into the whole numbers 0 and 1 |
| O-3 | gcds skipped, with the gcd work they would have had |
| O-4 | exact divisions skipped; multiplications skipped |
| O-5 | operations taking it; additions, gcds and exact divisions skipped (the two divisions $t/h$ and $d/h$ of case `den`, two per operation), with the gcds' gcd work |
| O-6 | whole-number reads avoided (probes rejected by fingerprint) |
| O-7 | list growths avoided, and the bytes they would have copied |

### 17.3 Checks

1. Every check of §14 holds for L1-opt, and its stored values and whole-number list MUST equal L1's.
2. **Predicted figures.** The generator predicts, per phase, from the magnitudes and the order of the whole-number list, the counters of O-1 (per case), O-2, O-3, O-4 and O-5; each MUST equal L1-opt's counter exactly. O-6 and O-7 are reported, not predicted.
3. **Against L1.** L1-opt's found lookups plus its skipped lookups MUST equal L1's found lookups; its appended lookups MUST equal L1's; its gcds, gcd work, divisions, multiplications and additions MUST equal L1's minus the skips counted by O-3, O-4 and O-5.
4. **Switches.** In the test build, the unit tests run with every trick on, with each trick off alone, and with all off. Every setting MUST give the same stored values and whole-number list; with all off, the counters MUST equal L1's.
5. **Unit tests** also cover each O-1 case with $h = 1$ and with $h \ne 1$, including a zero result; a $\pm 1$ result and an integer result before and after 1 is interned (O-2); integer operands in every operation (O-3, O-4); $x - x$ and $x + (-x)$ (O-5); probes rejected by fingerprint (O-6).
