# Signed Integers with a Header: Specification v0.1

Nov 1, 2026 · The author's decisions of that day; small calls marked **(coordinator's call)**. Reviewed in [`review-v0.1.md`](review-v0.1.md).

Two designs, A and B, go through **round 1** (correctness) and, if it passes, **round 2** (speed and memory), each against Control.

## 1. Shared parts

- **Magnitudes:** unsigned. A 5-bit class code $c$ says where one lives: $c = 0$, the word is the magnitude; $c = 1..31$, the word is a **slot index** into the pool whose slots are $2^c$ words, lowest first. Little-endian (readable as 32-bit halves). Zero is class 0, word 0. Canonical: the smallest class that holds it.
- **Routines:** schoolbook, carries and borrows as values ($s < x$): add; multiply-accumulate ($r \mathrel{+}= xy$); absolute difference with its borrow; compare; Hensel exact division; binary gcd. Each reads operands at their real length $n$ (up to the top nonzero word; 0 for zero), writes at most its bound, zeroes the rest of its slot, and returns the result's length; so words above a length are always 0, at a cost of at most one slot width of writes per result. Bounds: add $\max + 1$; multiply-accumulate $\max(n_r, n_1 + n_2)$, plus a carry word only when nonzero; absolute difference $\max$; division exactly $n_1 - n_2 + 1$, the last possibly an extra zero word, reading dividend words past its current length as 0; gcd $\min(n_1, n_2)$, or the nonzero operand's length if one is zero; $\gcd(0, 0)$ is an error.
- **Result class:** the smallest class holding the bound; A multiply $n_1 + n_2$, and each B part $\max(n_a + n_b, n_c + n_d) + 1$ for its $ab + cd$ (a one-word local that becomes the inline word, for class 0). If the result fits a smaller class it moves (zero-filled) to the smallest that holds it, and the slot is released. A class above 31 is an error.
- **Pools:** the owner releases a value explicitly (values are immutable), pushing its slot onto the pool's free list, linked through freed slots' first words and ended by all ones; a slot index is $W$ bits, so a pool holds at most $2^W - 1$ slots (15 at $W = 4$). Allocation pops the free list, else takes the next slot, else doubles the pool, from one slot at first use **(coordinator's call)**. Indices survive growth, pointers do not, so result slots are allocated first. Pools never shrink.
- **Operations:** add, subtract, negate, multiply, exact division, gcd, compare. Negating a pool number copies its words into a new slot, so no two numbers share a slot; an inline number copies its word.

## 2. Design A: magnitude and direction

A number is an **8-bit header** (bits 0–4 class, bit 5 spare 0, bits 6–7 direction $d$ mod 4 for $1, i, -1, -i$) and a **word**, in two parallel lists.

Its mathematics is [`../../book/notes-designs-a-b.md`](../../book/notes-designs-a-b.md), Design A. **Canonical:** the smallest class and spare bit 0; a zero keeps whatever direction its operation gives, and no step sets it.

**Header arithmetic** on 8 bits, $D = \texttt{0xC0}$, then OR in the result class: multiply `(h1 and D) + (h2 and D)`; divide `(h1 and D) - (h2 and D)`; negate `h xor 0x80`; gcd direction 0.

**Add:** direction check `t = (h1 xor h2) and D`.
- Same ($t = 0$): $m_1 + m_2$, direction `h1 and D`.
- Opposite ($t = \texttt{0x80}$): $m_1 - m_2$ with borrow $b$, negated when $b = 1$ (the absolute-difference routine); direction `(h1 and D) + (b shl 7)`.
- Different axes ($t$ = `0x40` or `0xC0`): if $m_1 = 0$ it takes h2's direction, if $m_2 = 0$ h1's stays, and the add runs as same-direction; otherwise it is an expression, an error in this spec.

There is no other zero test. **Subtract** runs add with `h2 xor 0x80`, copying nothing.

**Compare:** two zeros are equal in any directions. Ordering tests zero first: both zero, equal; one zero, the other's sign decides (1 and $i$ positive; zero lies on both axes). Then opposite directions: the positive one is larger; same direction: compare magnitudes, reversed when negative. Different axes are not ordered (an error).

## 3. Design B: one magnitude per direction

A number is a pair $(P, N)$ along $+1$ and $-1$, value $P - N$. **Header:** 16 bits, $P$'s class in the low byte and $N$'s in the high byte, 3 spare bits 0 in each; two words, $P$'s then $N$'s **(coordinator's call)**. A part's direction is its place.

- **Negate:** swap $P$ and $N$. **Subtract:** add the crossed parts, $P_1 + N_2$ and $N_1 + P_2$, copying nothing.
- **Add:** $(P_1 + P_2, N_1 + N_2)$.
- **Multiply:** $P = P_1P_2 + N_1N_2$, $N = P_1N_2 + N_1P_2$, by multiply-accumulate.
- **Compare:** $P_1 + N_2$ against $P_2 + N_1$, magnitude additions only.
- **Collapse:** the only subtraction. $\lvert P - N \rvert$ with borrow $b$ goes to $P$ when $b = 0$, else to $N$; the other part is 0. Exact division and gcd write $\lvert P - N \rvert$ straight into their working buffer, then follow A's direction rules. Output collapses only when a single value is needed. Add and multiply never collapse.

B is canonical only after collapse (one part zero).

**Structures** (rule 4): stored, the slot (A) or up to two slots (B); temporary, a slot on a move-down; local, the one-word local, B's compare sums, or the working buffer in division and gcd.

**Special cases**, named, not built: (a) a class-0 × class-0 product in registers; (b) an add allocating the class that holds $\max$ words, moving up only on a carry.

## 4. Round 1: correctness

Anything countable or provable is proved rather than tested.

- **Proved in Lean 4** ([`lean/`](lean/)): the mathematics of A and B for all values. Each rule of §2 and §3 gives the true result for add, subtract, negate, multiply, exact division, gcd, compare and collapse: for A the value $m \cdot i^d$ (any zero equal to any zero, the different-axes zero rule included); for B the value $P - N$, and the four-slot form (a product in slot $(d_1 + d_2) \bmod 4$, collapse per axis) against Gaussian integers, sums across axes included.
- **Tested in Python** (the model in [`test/`](test/), word by word at $W = 4$): the bookkeeping, which is not mathematics: headers, classes, pools, slots, free lists, write bounds and canonical form. Sets: every pair of signed values below $2^8$, with zero in directions 0 and 2; for B, every pair of uncollapsed values with parts below $2^4$; 100,000 random pairs per operation, up to 8 words, zeros and equal magnitudes at 1/16 each **(coordinator's call)**. It passes when every value matches Python's, every result is canonical, spare bits are 0, and after all releases every slot is on its pool's free list.

## 5. Round 2: speed and memory

Control (spec 12's Growing, [`../12-integers/v0.1.md`](../12-integers/v0.1.md) §1.4, with A's header list), A and B, each written as portable pseudocode (algorithm design rule 6), then x86-64 machine code. Integers only.

- **(a) Proved in Lean:** for each build, every path through each operation at the machine level, with its instruction, branch, load and store counts, and a proof that the listed paths cover every input. For example, A's one-word add takes 3 instructions in the same direction, 6 opposite and 8 when it borrows, the same on x86-64, ARM64 and RISC-V. Cycle predictions under a stated cost model (published per-instruction costs) are claims about that model.
- **(b) Branch inventory** (written): every branch each design uses, the condition it tests, and when it is predictable. For example, same against opposite direction is predictable when signs mostly agree; the borrow, when the first magnitude is usually larger.
- **(c) Timed trials**, to measure the branches: workloads that push each branch from predictable to unpredictable (all positive, mostly one sign, random signs; likewise for which magnitude is larger), with spec 12's method, against Control, plus a branch-free row per design (masks only (AND, XOR and the borrow as a value), since rule 6 rules out conditional moves, which base RISC-V lacks). Time beyond what the counts predict is read as branch and cache cost; a large or consistent residual is a finding. Bytes per value are measured beside. Other known costs: rounding up, pools, B's two magnitudes, growing parts and collapse.

## 6. Decided (author, Nov 1, 2026)

- **(a)** No Inline build.
- **(b)** Pools never shrink in this round. To revisit later with the release of unused memory, as part of garbage collection.
- **(c)** A's parallel lists count as one stored structure under rule 4.
- **(d)** No mixed job.
- **(e)** B's two slots per number are allowed, for testing. The author doubts B, since it doubles the magnitude arithmetic, and tests it in case it wins.
- **(f)** B collapses only at the required points.
