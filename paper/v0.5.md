## 1. Naive rational arithmetic

A rational number is a number that can be written as a fraction $\frac{p}{q}$, where $p$ and $q$ are integers and $q \neq 0$. The integer $p$ is the *numerator* and $q$ is the *denominator*. For example, $\frac{3}{4}$, $\frac{-2}{5}$ and $\frac{7}{1}$ are rational numbers.

A rational number is made of two integers, so a program that works with rationals works with integers underneath. Section 1.1 is about integers alone. Section 1.2 returns to rationals.

### 1.1 Integers

A computer stores an integer in base 2, as a fixed number of bits called its *width*. Common widths are 8, 16, 32 and 64 bits.

An *unsigned* integer uses all of its bits for the magnitude. With $w$ bits it holds every integer from $0$ to $2^w - 1$, so a 32-bit unsigned integer runs from $0$ to $4\,294\,967\,295$.

A *signed* integer spends a bit on the sign. With $w$ bits it holds every integer from $-2^{w-1}$ to $2^{w-1} - 1$, about half the unsigned maximum, so a 32-bit signed integer runs from $-2\,147\,483\,648$ to $2\,147\,483\,647$. An unsigned integer stores larger magnitudes in the same bits; a signed integer can also store negative numbers.

Integer addition, subtraction, multiplication, negation and comparison are taken as given for the rest of this paper. We are not trying to make them faster.

Their cost is stated in big-O, for integers of $n$ digits. Adding two $n$-digit integers takes $O(n)$ steps, and multiplying them takes $O(n^2)$. Comparing two $n$-digit integers for equality, or negating one, takes $O(n)$. For fixed-width machine integers each of these is a single instruction; the big-O describes integers too long to fit in one machine word.

### 1.2 Storing a rational number

A computer stores a rational number as a pair of integers, its numerator and its denominator. The most common layout is two signed integers of the same width. The running example in this paper is a signed 32-bit numerator next to a signed 32-bit denominator:

| Field | Type |
|---|---|
| numerator | signed 32-bit integer |
| denominator | signed 32-bit integer |

Other layouts and widths exist, such as 64-bit fields, or a signed numerator over an unsigned denominator, which forces the sign into the numerator. Each layout has trade-offs, and nothing in this paper depends on the choice. In every layout the denominator is never zero, and the number zero is stored as numerator $0$ over any nonzero denominator.

In pseudocode, `numerator(x)` and `denominator(x)` read the two stored integers of a rational `x`, and `n / m` builds the rational with numerator `n` and denominator `m`. Here `/` does not divide; it only pairs two integers.

**The sign.** In arithmetic, a minus sign belongs to the whole rational number. A negative numerator can be moved outside the fraction, and so can a negative denominator:

$$
\frac{-3}{4} = -\frac{3}{4} = \frac{3}{-4}.
$$

A computer has only the two integers, so the sign must live in one of them. Either one can carry it: $-\frac{3}{4}$ can be stored as $-3$ over $4$, or as $3$ over $-4$.

If both integers are negative, the two signs cancel:

$$
\frac{-3}{-4} = \frac{3}{4}.
$$

This is the only simplification used in this section. Because of it, it does not matter which integer carries the sign, and every operation below accepts either.

### 1.3 Addition and subtraction

To add two fractions, bring them over a common denominator:

$$
\frac{a}{b} + \frac{c}{d} = \frac{a \cdot d + c \cdot b}{b \cdot d}.
$$

Subtraction is addition with the second numerator negated:

$$
\frac{a}{b} - \frac{c}{d} = \frac{a}{b} + \frac{-c}{d}.
$$

The naive algorithm applies these formulas directly. In the pseudocode, `LET` gives a new name to a value.

```text
FUNCTION add(x, y)
    LET a = numerator(x)
    LET b = denominator(x)
    LET c = numerator(y)
    LET d = denominator(y)
    RETURN (a · d + c · b) / (b · d)
END FUNCTION

FUNCTION subtract(x, y)
    RETURN add(x, (−numerator(y)) / denominator(y))
END FUNCTION
```

Since `subtract` only calls `add`, everything below about addition applies to subtraction too.

#### Special cases

The naive formula always gives the right answer, but for some inputs it does more work than it needs to. From here on we move beyond the naive approach by accounting for special cases: inputs where some stored integers are equal up to sign, or zero, and a cheaper formula gives the same answer exactly.

The most important special case for addition is a shared denominator. If $b = d$, the two fractions already have a common denominator, and the numerators simply add:

$$
\frac{a}{b} + \frac{c}{b} = \frac{a + c}{b}.
$$

This needs one addition and no multiplication, so its cost drops from $O(n^2)$ to $O(n)$. The denominator of the result is the stored $b$, copied as it is.

*Example.* In $\dfrac{1}{5} + \dfrac{2}{5}$ the denominators are equal, so the result is

$$
\frac{1 + 2}{5} = \frac{3}{5}.
$$

If the denominators are opposite, $d = -b$, the sign of $d$ moves into its numerator and the denominators become shared:

$$
\frac{a}{b} + \frac{c}{-b} = \frac{a}{b} + \frac{-c}{b} = \frac{a - c}{b}.
$$

This also costs $O(n)$.

The other special cases are briefer. If one numerator is zero, that term is zero, and the sum is the other term. If the numerators are equal, $c = a$, the common factor $a$ can be pulled out:

$$
\frac{a}{b} + \frac{a}{d} = \frac{a \cdot d + a \cdot b}{b \cdot d} = \frac{a \cdot (d + b)}{b \cdot d}.
$$

If the numerators are opposite, $c = -a$, the same idea gives

$$
\frac{a}{b} + \frac{-a}{d} = \frac{a \cdot d - a \cdot b}{b \cdot d} = \frac{a \cdot (d - b)}{b \cdot d}.
$$

In subtraction, $\frac{a}{b} - \frac{a}{d}$ takes the second form and $\frac{a}{b} - \frac{-a}{d}$ the first.

Both forms need two multiplications instead of three, so they save one multiplication but stay $O(n^2)$.

The table lists the naive formula first and then every special case. In a row with $\pm$, read the upper sign everywhere or the lower sign everywhere. The cost includes the $O(n)$ equality check.

| Case | Condition | Result | Cost |
|---|---|---|---|
| Naive | always | $\dfrac{a \cdot d + c \cdot b}{b \cdot d}$ | $O(n^2)$ |
| Zero numerator | $a = 0$ or $c = 0$ | the other term | $O(n)$ |
| Shared denominator | $d = \pm b$ | $\dfrac{a \pm c}{b}$ | $O(n)$ |
| Equal or opposite numerators | $c = \pm a$ | $\dfrac{a \cdot (d \pm b)}{b \cdot d}$ | $O(n^2)$ |

The naive path now runs only after every check has failed, so it pays for those checks: a small $O(n)$ overhead on top of its $O(n^2)$.

In the pseudocode, `IF` compares two integers with `=`, and when they are equal, the line after `THEN` returns at once and the rest of the function is skipped. The special cases come first, in table order, and the naive formula is the final line.

```text
FUNCTION add(x, y)
    LET a = numerator(x)
    LET b = denominator(x)
    LET c = numerator(y)
    LET d = denominator(y)
    IF a = 0 THEN RETURN y
    IF c = 0 THEN RETURN x
    IF d = b THEN RETURN (a + c) / b
    IF d = −b THEN RETURN (a − c) / b
    IF a = c THEN RETURN (a · (d + b)) / (b · d)
    IF a = −c THEN RETURN (a · (d − b)) / (b · d)
    RETURN (a · d + c · b) / (b · d)
END FUNCTION
```

### 1.4 Multiplication

Numerators multiply, and denominators multiply:

$$
\frac{a}{b} \cdot \frac{c}{d} = \frac{a \cdot c}{b \cdot d}.
$$

The naive algorithm applies this formula directly.

```text
FUNCTION multiply(x, y)
    LET a = numerator(x)
    LET b = denominator(x)
    LET c = numerator(y)
    LET d = denominator(y)
    RETURN (a · c) / (b · d)
END FUNCTION
```

#### Special cases

The most important special case for multiplication is a cross match: one value's numerator equals the other value's denominator. If $c = b$, the same integer $b$ appears once on top and once on the bottom, and it cancels exactly:

$$
\frac{a}{b} \cdot \frac{b}{d} = \frac{a \cdot b}{b \cdot d} = \frac{a}{d}.
$$

The result is the two outer stored integers, $a$ over $d$. The match also works the other way round, when $a = d$:

$$
\frac{a}{b} \cdot \frac{c}{a} = \frac{c}{b}.
$$

A match up to sign cancels too, and leaves a factor of $-1$ in the numerator:

$$
\frac{a}{b} \cdot \frac{-b}{d} = \frac{-a}{d},
\qquad
\frac{-d}{b} \cdot \frac{c}{d} = \frac{-c}{b}.
$$

None of these forms needs a multiplication, so the cost drops from $O(n^2)$ to $O(n)$.

*Example.* In $\dfrac{2}{3} \cdot \dfrac{3}{5}$ the second numerator equals the first denominator, so the result is

$$
\frac{2}{5}.
$$

The other special cases are briefer. If either numerator is zero, the product is zero, and that factor is itself the answer. If both cross matches hold at once, the two values are reciprocals and the product is $1$:

$$
\frac{a}{b} \cdot \frac{b}{a} = 1.
$$

Since two negative signs cancel, the reciprocal of $\frac{a}{b}$ may also be stored as $\frac{-b}{-a}$, and the product is again $1$. If one value is $1$, its numerator equals its denominator, and the product is the other value. If one value is $-1$, its numerator is the negated denominator, and the product is the other value with its numerator negated: for $a = -b$ the result is $\frac{-c}{d}$, and for $c = -d$ it is $\frac{-a}{b}$.

Not every coincidence helps: a shared denominator, the main case for addition, saves nothing here, since $\frac{a}{b} \cdot \frac{c}{b} = \frac{a \cdot c}{b \cdot b}$ still needs both multiplications, and a shared numerator saves nothing either. Neither gets a row or a check.

| Case | Condition | Result | Cost |
|---|---|---|---|
| Naive | always | $\dfrac{a \cdot c}{b \cdot d}$ | $O(n^2)$ |
| Zero numerator | $a = 0$ or $c = 0$ | the zero factor | $O(n)$ |
| Reciprocals | $a = \pm d$ and $b = \pm c$ | $\dfrac{1}{1}$ | $O(n)$ |
| Cross match | $c = \pm b$, or $a = \pm d$ | $\dfrac{\pm a}{d}$, or $\dfrac{\pm c}{b}$ | $O(n)$ |
| Factor of $\pm 1$ | $a = \pm b$, or $c = \pm d$ | $\dfrac{\pm c}{d}$, or $\dfrac{\pm a}{b}$ | $O(n)$ |

As before, the naive path pays for every failed check, a small $O(n)$ overhead.

Reciprocals come before cross matches, because a reciprocal pair is also a cross match and would otherwise be caught there.

```text
FUNCTION multiply(x, y)
    LET a = numerator(x)
    LET b = denominator(x)
    LET c = numerator(y)
    LET d = denominator(y)
    IF a = 0 THEN RETURN x
    IF c = 0 THEN RETURN y
    IF (a = d AND b = c) OR (a = −d AND b = −c) THEN RETURN 1 / 1
    IF b = c THEN RETURN a / d
    IF b = −c THEN RETURN (−a) / d
    IF a = d THEN RETURN c / b
    IF a = −d THEN RETURN (−c) / b
    IF a = b THEN RETURN y
    IF a = −b THEN RETURN (−c) / d
    IF c = d THEN RETURN x
    IF c = −d THEN RETURN (−a) / b
    RETURN (a · c) / (b · d)
END FUNCTION
```

### 1.5 Division

Dividing by $\frac{c}{d}$ is multiplying by its reciprocal $\frac{d}{c}$, which exists only when $c \neq 0$:

$$
\frac{a}{b} \div \frac{c}{d} = \frac{a}{b} \cdot \frac{d}{c} = \frac{a \cdot d}{b \cdot c}, \qquad c \neq 0.
$$

The naive algorithm first checks for a zero divisor and stops with an error, then applies the formula.

```text
FUNCTION divide(x, y)
    LET a = numerator(x)
    LET b = denominator(x)
    LET c = numerator(y)
    LET d = denominator(y)
    IF c = 0 THEN ERROR "division by zero"
    RETURN (a · d) / (b · c)
END FUNCTION
```

#### Special cases

The most important special case for division is a shared part. In $\frac{a \cdot d}{b \cdot c}$ the two numerators $a$ and $c$ sit on opposite sides of the fraction bar, and so do the two denominators $b$ and $d$. So if the inputs share a numerator or share a denominator, that shared integer cancels exactly:

$$
\frac{a}{b} \div \frac{a}{d} = \frac{a \cdot d}{b \cdot a} = \frac{d}{b},
\qquad
\frac{a}{b} \div \frac{c}{b} = \frac{a \cdot b}{b \cdot c} = \frac{a}{c}.
$$

Cancelling $a$ is allowed because the zero-divisor check has already run: if $c = a$ and $c \neq 0$, then $a \neq 0$. Numerators that are opposite, $c = -a$, cancel too, and leave a factor of $-1$:

$$
\frac{a}{b} \div \frac{-a}{d} = \frac{-d}{b}.
$$

So do opposite denominators, $d = -b$:

$$
\frac{a}{b} \div \frac{c}{-b} = \frac{a \cdot (-b)}{b \cdot c} = \frac{-a}{c}.
$$

None of these forms needs a multiplication, so the cost drops from $O(n^2)$ to $O(n)$.

*Example.* In $\dfrac{2}{3} \div \dfrac{2}{7}$ the numerators are equal, so the result is the second denominator over the first:

$$
\frac{7}{3}.
$$

The other special cases are briefer. If the dividend's numerator is zero, the quotient is zero, and the dividend itself is the answer. If the stored integers match, $a = c$ and $b = d$, the quotient is $1$. If the divisor is $1$, that is $c = d$, the quotient is the dividend; if it is $-1$, that is $c = -d$, the quotient is the dividend with its numerator negated, $\frac{-a}{b}$. If the dividend is $1$, that is $a = b$, the quotient is the reciprocal of the divisor, $\frac{d}{c}$; if it is $-1$, that is $a = -b$, the quotient is $\frac{-d}{c}$.

| Case | Condition | Result | Cost |
|---|---|---|---|
| Naive | $c \neq 0$ | $\dfrac{a \cdot d}{b \cdot c}$ | $O(n^2)$ |
| Zero dividend | $a = 0$ | $\dfrac{a}{b}$ | $O(n)$ |
| Matching integers | $a = c$ and $b = d$ | $\dfrac{1}{1}$ | $O(n)$ |
| Shared part | $c = \pm a$, or $b = \pm d$ | $\dfrac{\pm d}{b}$, or $\dfrac{\pm a}{c}$ | $O(n)$ |
| Divisor $\pm 1$ | $c = \pm d$ | $\dfrac{\pm a}{b}$ | $O(n)$ |
| Dividend $\pm 1$ | $a = \pm b$ | $\dfrac{\pm d}{c}$ | $O(n)$ |

As before, the naive path pays for every failed check, a small $O(n)$ overhead.

The zero-divisor check stays first, as in the naive algorithm. Matching integers come before a shared numerator, which would otherwise catch them.

```text
FUNCTION divide(x, y)
    LET a = numerator(x)
    LET b = denominator(x)
    LET c = numerator(y)
    LET d = denominator(y)
    IF c = 0 THEN ERROR "division by zero"
    IF a = 0 THEN RETURN x
    IF a = c AND b = d THEN RETURN 1 / 1
    IF a = c THEN RETURN d / b
    IF a = −c THEN RETURN (−d) / b
    IF b = d THEN RETURN a / c
    IF b = −d THEN RETURN (−a) / c
    IF c = d THEN RETURN x
    IF c = −d THEN RETURN (−a) / b
    IF a = b THEN RETURN d / c
    IF a = −b THEN RETURN (−d) / c
    RETURN (a · d) / (b · c)
END FUNCTION
```

## 2. Rational arithmetic in lowest terms

### 2.1 Growing integers

The formulas of section 1 always give the right value, but they let the stored integers grow. In addition and multiplication the denominators multiply, so the denominator of a result has about as many digits as the two input denominators together.

*Example.* Add $\frac{1}{2} + \frac{1}{3} + \frac{1}{4} + \frac{1}{5} + \frac{1}{6}$ one term at a time with the `add` function of section 1. The running results are

$$
\frac{5}{6}, \qquad \frac{26}{24}, \qquad \frac{154}{120}, \qquad \frac{1044}{720}.
$$

The last denominator is $720 = 2 \cdot 3 \cdot 4 \cdot 5 \cdot 6$, yet the same value can also be written $\frac{29}{20}$. Carried on up to $\frac{1}{13}$, the sum is stored as $13\,575\,738\,240$ over $6\,227\,020\,800$. Both integers are past the 32-bit signed maximum of $2\,147\,483\,647$, while the same value can be written $\frac{785\,633}{360\,360}$, which fits easily.

So after a few operations the integers no longer fit in a fixed width. With integers of unlimited length the problem shows up as cost instead: every operation is $O(n^2)$ in the number of digits, and $n$ keeps growing.

### 2.2 Lowest terms

Section 1 used one simplification: two negative signs cancel, so $\frac{-3}{-4}$ and $\frac{3}{4}$ are the same number. A fuller simplification cancels common factors too. In $\frac{26}{24}$ both integers are even, and dividing both by $2$ gives $\frac{13}{12}$, the same value with smaller integers.

The *greatest common divisor* of two integers $u$ and $v$, written $\gcd(u, v)$, is the largest positive integer that divides both of them exactly. For example, $\gcd(12, 18) = 6$. Signs do not matter: $\gcd(-12, 18) = 6$ as well. Every positive integer divides $0$, so $\gcd(u, 0) = |u|$ for any $u \neq 0$.

Dividing the numerator and the denominator by their gcd gives the same value. Here $\gcd(12, 18) = 6$, and $12 = 2 \cdot 6$ and $18 = 3 \cdot 6$:

$$
\frac{12}{18} = \frac{2 \cdot 6}{3 \cdot 6} = \frac{2}{3}.
$$

After this division the numerator and denominator have gcd $1$, so nothing is left to cancel. Such a fraction is in *lowest terms*. Every other fraction with the same value has a numerator and denominator that are the same whole multiple of these two, as $\frac{4}{6}$ and $\frac{10}{15}$ are of $\frac{2}{3}$. So lowest terms keeps the integers as small as the value allows.

Lowest terms fixes the integers only up to sign: $\frac{2}{3}$ and $\frac{-2}{-3}$ are both in lowest terms. From here on the sign is settled by keeping the denominator positive. The value is the same either way, as in section 1; fixing the place makes the stored form unique. A stored rational is *reduced* when its denominator is positive and the gcd of its numerator and denominator is $1$. Every rational number has exactly one reduced form. Zero's reduced form is $\frac{0}{1}$, since $\gcd(0, d) = d$ for a positive $d$.

### 2.3 Euclid's algorithm

Computing a gcd needs division with a remainder. For integers $u \geq 0$ and $v > 0$ there is exactly one way to write

$$
u = q \cdot v + r, \qquad 0 \leq r < v.
$$

The integer $q$ is the *quotient* and $r$ is the *remainder*. Dividing an $n$-digit integer by another, by long division, takes $O(n^2)$, the same as multiplying them.

The remainder is written $u \bmod v$, in formulas and in pseudocode alike. For example, $84 \bmod 36 = 12$, since $84 = 2 \cdot 36 + 12$.

The remainder has the same common divisors with $v$ as $u$ does. Any integer that divides $u$ and $v$ also divides $r = u - q \cdot v$, and any integer that divides $v$ and $r$ also divides $u = q \cdot v + r$. So

$$
\gcd(u, v) = \gcd(v, u \bmod v).
$$

Euclid's algorithm applies this rule until the second integer is $0$, and then $\gcd(u, 0) = u$ gives the answer. In the pseudocode the function calls itself on the new pair; each call works on a smaller pair, so the calls come to an end.

```text
FUNCTION gcd(u, v)
    IF v = 0 THEN RETURN u
    RETURN gcd(v, u mod v)
END FUNCTION
```

*Example.* Since $84 \bmod 36 = 12$ and $36 \bmod 12 = 0$,

$$
\gcd(84, 36) = \gcd(36, 12) = \gcd(12, 0) = 12.
$$

This version assumes that neither input is negative. Signs do not change the gcd, so negative inputs can simply be made positive first. From here on, `IF` can also compare two integers with `<` or `>`, as in `u < 0`.

```text
FUNCTION gcd(u, v)
    IF u < 0 THEN RETURN gcd(−u, v)
    IF v < 0 THEN RETURN gcd(u, −v)
    IF v = 0 THEN RETURN u
    RETURN gcd(v, u mod v)
END FUNCTION
```

Each remainder is smaller than the integer before it, and every two steps the larger integer at least halves, so for $n$-digit inputs there are at most $O(n)$ steps. Each step is a division, which can cost $O(n^2)$ on its own and suggests $O(n^3)$ in total. A closer count gives less. Long division of $u$ by $v$ costs about (digits of $v$) $\times$ (digits of $q$ $+ 1$): one pass over $v$ for each digit of the quotient. The divisor never has more than $n$ digits. The quotient has about as many digits as $u$ has more than $v$, and the next step divides $v$, so over all steps these differences add up to at most about $n$, the digits of the first input. The extra $1$ per step adds at most the number of steps, $O(n)$. So the total is $O(n \cdot n) = O(n^2)$.

When the remainder is $0$, $v$ divides $u$ *exactly*, and the quotient is written $u \div v$. This is the only use of `÷` between integers: in formulas and in pseudocode alike, `÷` between two integers is their exact quotient, and `/` builds a fraction from two integers, as in section 1. Between two fractions, $\div$ still means division of rational numbers, as in section 1, which agrees with the exact quotient when both are whole numbers. An exact quotient may be negative: whenever $u = q \cdot v$ for integers $q$ and $v \neq 0$, $u \div v = q$, so $-12 \div 6 = -2$ and $12 \div (-6) = -2$.

### 2.4 Storing reduced values

To reduce a pair of integers $p$ and $q$, with $q \neq 0$, divide both by $\gcd(p, q)$ and then, if the denominator is negative, negate both. The pseudocode below calls this `reduce`. It returns a reduced value.

```text
FUNCTION reduce(p, q)
    IF q = 0 THEN ERROR "zero denominator"
    LET g = gcd(p, q)
    IF q < 0 THEN RETURN (−(p ÷ g)) / (−(q ÷ g))
    RETURN (p ÷ g) / (q ÷ g)
END FUNCTION
```

Reducing costs one gcd and two exact divisions, $O(n^2)$ in all. That is the same order as the naive operations of section 1. So naive arithmetic followed by a reduction is the naive method plus more work, and no faster per operation. Over many operations, the smaller integers keep $n$ small, so that every later operation works on shorter integers, as section 2.1 showed.

From here on, values are stored reduced. A value is reduced once, when it is created, for example from two integers that a user supplies, and every operation returns a reduced result. So every function below may assume that its inputs are reduced. In particular the denominators $b$ and $d$ are positive, so the conditions of section 1 with opposite denominators, such as $d = -b$, can no longer hold.

In the tables, "reduced" after a result means that the result is passed through `reduce`, and "sign settled" means that if its denominator is negative, both integers are negated.

### 2.5 Addition and subtraction

#### Reducing the naive result

The simplest way to keep sums reduced is to reduce the result of the naive formula:

$$
\frac{a}{b} + \frac{c}{d} = \frac{(a \cdot d + c \cdot b) \div k}{(b \cdot d) \div k}, \qquad k = \gcd(a \cdot d + c \cdot b,\ b \cdot d).
$$

```text
FUNCTION add(x, y)
    LET a = numerator(x)
    LET b = denominator(x)
    LET c = numerator(y)
    LET d = denominator(y)
    RETURN reduce(a · d + c · b, b · d)
END FUNCTION
```

*Example.* The naive formula gives $\frac{1}{6} + \frac{1}{10} = \frac{16}{60}$, and $\gcd(16, 60) = 4$, so the result is $\frac{4}{15}$.

The products have up to $2n$ digits, and the gcd runs on them, but the cost is still $O(n^2)$.

#### Dividing out first

The two denominators often share a factor already, as $6$ and $10$ share $2$. Let $g = \gcd(b, d)$, and write $b' = b \div g$ and $d' = d \div g$. Then $b' \cdot d$ is a common denominator, smaller than $b \cdot d$ by the factor $g$:

$$
\frac{a}{b} + \frac{c}{d} = \frac{a \cdot d'}{b' \cdot d} + \frac{c \cdot b'}{b' \cdot d} = \frac{t}{b' \cdot d}, \qquad t = a \cdot d' + c \cdot b'.
$$

This result can still have a common factor, but less of one. Because both inputs are reduced, $t$ shares no factor with $b'$ or with $d'$, so whatever $t$ shares with the denominator $b' \cdot d = b' \cdot d' \cdot g$ divides $g$. Let $h = \gcd(t, g)$. Then

$$
\frac{a}{b} + \frac{c}{d} = \frac{t \div h}{b' \cdot (d \div h)}.
$$

The denominator is positive, so the sign is already settled.

```text
FUNCTION add(x, y)
    LET a = numerator(x)
    LET b = denominator(x)
    LET c = numerator(y)
    LET d = denominator(y)
    LET g = gcd(b, d)
    LET b′ = b ÷ g
    LET d′ = d ÷ g
    LET t = a · d′ + c · b′
    LET h = gcd(t, g)
    RETURN (t ÷ h) / (b′ · (d ÷ h))
END FUNCTION
```

*Example.* In $\frac{1}{6} + \frac{1}{10}$, $g = 2$, $b' = 3$ and $d' = 5$, so $t = 5 + 3 = 8$ and $h = \gcd(8, 2) = 2$. The result is

$$
\frac{8 \div 2}{3 \cdot (10 \div 2)} = \frac{4}{15}.
$$

The two gcds run on $6$ and $10$ and on $8$ and $2$, instead of on $16$ and $60$.

This method does more steps than reducing the naive result, but every step works on smaller integers: the gcds run on the input denominators and on $g$, and the products are smaller by the factor $g$. Its cost is $O(n^2)$, the same order.

Subtraction stays defined through `add`, as in section 1. Negating the numerator of a reduced value leaves it reduced, so `subtract` still passes `add` a reduced value.

#### Special cases

With reduced inputs, some coincidences between the stored integers show that a gcd would come out as $1$, so it never has to be computed.

If one numerator is zero, that term is $\frac{0}{1}$, and the sum is the other term, as in section 1.

If the denominators are equal, $d = b$, then $g = b$ and $b' = d' = 1$. The numerators simply add, and only the reduction is left:

$$
\frac{a}{b} + \frac{c}{b} = \frac{a + c}{b}, \text{ reduced}.
$$

This needs one gcd, $\gcd(a + c, b)$, and no multiplication. In section 1 this case cost $O(n)$; the reduction raises it to $O(n^2)$.

*Example.* $\dfrac{1}{6} + \dfrac{1}{6} = \dfrac{2}{6}$, and $\gcd(2, 6) = 2$, so the result is $\dfrac{1}{3}$.

If both values are whole numbers, $b = d = 1$, even that gcd is known: $\gcd(a + c, 1) = 1$. The result is $\frac{a + c}{1}$, with one addition and no gcd.

The most useful new case is a cross match: one value's numerator equals the other value's denominator up to sign, $d = \pm a$ or $b = \pm c$. Since $\frac{a}{b}$ is reduced, $a$ and $b$ share no factor, so $g = \gcd(b, d) = 1$, and then $h = 1$ too. The naive result is already reduced:

$$
\frac{a}{b} + \frac{c}{\pm a} = \frac{a \cdot d + c \cdot b}{b \cdot d}.
$$

This needs no gcd at all.

*Example.* In $\dfrac{2}{3} + \dfrac{5}{2}$ the second denominator equals the first numerator, so the result is

$$
\frac{2 \cdot 2 + 5 \cdot 3}{3 \cdot 2} = \frac{19}{6}.
$$

If the numerators are equal or opposite, $c = \pm a$, then $t = a \cdot (d' \pm b')$. The factor $a$ shares nothing with $g$, because $g$ divides $b$, so only $s = d' \pm b'$ needs to be reduced against $g$. Let $h = \gcd(s, g)$:

$$
\frac{a}{b} + \frac{\pm a}{d} = \frac{a \cdot (s \div h)}{b' \cdot (d \div h)}, \qquad s = d' \pm b'.
$$

This saves one multiplication, and the last gcd runs on $s$ instead of $t$. For example, $\frac{3}{4} + \frac{3}{10}$ has $g = 2$, $b' = 2$, $d' = 5$ and $s = 7$, so $h = 1$ and the result is $\frac{3 \cdot 7}{2 \cdot 10} = \frac{21}{20}$.

The table lists the general method first. In a row with $\pm$, read the upper sign everywhere or the lower sign everywhere. The cost includes the $O(n)$ equality checks.

| Case | Condition | Result | Cost |
|---|---|---|---|
| General | always | $\dfrac{t \div h}{b' \cdot (d \div h)}$ | $O(n^2)$ |
| Zero numerator | $a = 0$ or $c = 0$ | the other term | $O(n)$ |
| Whole numbers | $b = d = 1$ | $\dfrac{a + c}{1}$ | $O(n)$ |
| Shared denominator | $d = b$ | $\dfrac{a + c}{b}$, reduced | $O(n^2)$ |
| Cross match | $d = \pm a$, or $b = \pm c$ | $\dfrac{a \cdot d + c \cdot b}{b \cdot d}$ | $O(n^2)$ |
| Shared numerator | $c = \pm a$ | $\dfrac{a \cdot (s \div h)}{b' \cdot (d \div h)}$, with $s = d' \pm b'$ and $h = \gcd(s, g)$ | $O(n^2)$ |

Whole numbers come before a shared denominator, which would otherwise catch them with a needless gcd. The shared-numerator case needs $g$, $b'$ and $d'$, so in the pseudocode it comes after they are computed. Each of its two signs takes three lines, so each sits in an `IF` block that runs to `END IF`. The names $s$ and $h$ are those of the formula; each block returns, so only one of them runs.

```text
FUNCTION add(x, y)
    LET a = numerator(x)
    LET b = denominator(x)
    LET c = numerator(y)
    LET d = denominator(y)
    IF a = 0 THEN RETURN y
    IF c = 0 THEN RETURN x
    IF b = 1 AND d = 1 THEN RETURN (a + c) / 1
    IF d = b THEN RETURN reduce(a + c, b)
    IF d = a OR d = −a OR b = c OR b = −c THEN RETURN (a · d + c · b) / (b · d)
    LET g = gcd(b, d)
    LET b′ = b ÷ g
    LET d′ = d ÷ g
    IF c = a THEN
        LET s = d′ + b′
        LET h = gcd(s, g)
        RETURN (a · (s ÷ h)) / (b′ · (d ÷ h))
    END IF
    IF c = −a THEN
        LET s = d′ − b′
        LET h = gcd(s, g)
        RETURN (a · (s ÷ h)) / (b′ · (d ÷ h))
    END IF
    LET t = a · d′ + c · b′
    LET h = gcd(t, g)
    RETURN (t ÷ h) / (b′ · (d ÷ h))
END FUNCTION
```

### 2.6 Multiplication

#### Reducing the naive result

As for addition, the simplest way is to reduce the naive product:

$$
\frac{a}{b} \cdot \frac{c}{d} = \frac{(a \cdot c) \div k}{(b \cdot d) \div k}, \qquad k = \gcd(a \cdot c,\ b \cdot d).
$$

```text
FUNCTION multiply(x, y)
    LET a = numerator(x)
    LET b = denominator(x)
    LET c = numerator(y)
    LET d = denominator(y)
    RETURN reduce(a · c, b · d)
END FUNCTION
```

*Example.* The naive formula gives $\frac{4}{9} \cdot \frac{3}{8} = \frac{12}{72}$, and $\gcd(12, 72) = 12$, so the result is $\frac{1}{6}$.

The cost is $O(n^2)$.

#### Dividing out first

Since $\frac{a}{b}$ is reduced, $a$ and $b$ share no factor, and neither do $c$ and $d$. So any factor that cancels in the product lies between $a$ and $d$, or between $c$ and $b$. Let $g = \gcd(a, d)$ and $h = \gcd(c, b)$, and divide them out before multiplying:

$$
\frac{a}{b} \cdot \frac{c}{d} = \frac{(a \div g) \cdot (c \div h)}{(b \div h) \cdot (d \div g)}.
$$

Nothing is left to cancel, so this result is already reduced, with no gcd at the end.

```text
FUNCTION multiply(x, y)
    LET a = numerator(x)
    LET b = denominator(x)
    LET c = numerator(y)
    LET d = denominator(y)
    LET g = gcd(a, d)
    LET h = gcd(c, b)
    RETURN ((a ÷ g) · (c ÷ h)) / ((b ÷ h) · (d ÷ g))
END FUNCTION
```

*Example.* In $\frac{4}{9} \cdot \frac{3}{8}$, $g = \gcd(4, 8) = 4$ and $h = \gcd(3, 9) = 3$, so the result is

$$
\frac{1 \cdot 1}{3 \cdot 2} = \frac{1}{6}.
$$

The two gcds run on the inputs, and the products are of smaller integers. The cost is $O(n^2)$, the same order.

#### Special cases

If either numerator is zero, the product is zero, and that factor, $\frac{0}{1}$, is the answer.

If the values are reciprocals, the product is $1$. In reduced form the reciprocal of $\frac{a}{b}$ is $\frac{b}{a}$ when $a > 0$ and $\frac{-b}{-a}$ when $a < 0$, so the condition is $c = \pm b$ and $d = \pm a$, with the same sign in both.

The rows for a factor of $\pm 1$ save a gcd: the general method would still compute $\gcd(a, d)$ and $\gcd(c, b)$, though both are known to be $1$. If one value is $\pm 1$, the product is the other value, with its numerator negated for $-1$. In reduced form the value $\pm 1$ is stored as $\frac{\pm 1}{1}$, so the condition $a = \pm b$ means $x = \pm 1$, as in section 1.

A cross match, $c = \pm b$ or $d = \pm a$, still cancels exactly, but the outer integers can now share a factor. Since $h = \gcd(c, b)$ is known to be $b$, only $g = \gcd(a, d)$ is left:

$$
\frac{a}{b} \cdot \frac{\pm b}{d} = \frac{\pm a}{d}, \text{ reduced}.
$$

*Example.* $\dfrac{2}{3} \cdot \dfrac{3}{4} = \dfrac{2}{4}$, which reduces to $\dfrac{1}{2}$.

The most useful new case is a shared part: a shared denominator, $d = b$, or a shared numerator up to sign, $c = \pm a$. In section 1 neither saved anything. Now both gcds of the general method are known to be $1$. For $d = b$, $\gcd(a, d) = \gcd(a, b) = 1$ and $\gcd(c, b) = \gcd(c, d) = 1$. For $c = \pm a$, $\gcd(a, d) = \gcd(c, d) = 1$ and $\gcd(c, b) = \gcd(a, b) = 1$. So the naive product is already reduced:

$$
\frac{a}{b} \cdot \frac{c}{b} = \frac{a \cdot c}{b \cdot b},
\qquad
\frac{a}{b} \cdot \frac{\pm a}{d} = \frac{\pm a \cdot a}{b \cdot d}.
$$

This needs no gcd at all.

*Example.* $\dfrac{2}{5} \cdot \dfrac{3}{5} = \dfrac{6}{25}$.

| Case | Condition | Result | Cost |
|---|---|---|---|
| General | always | $\dfrac{(a \div g) \cdot (c \div h)}{(b \div h) \cdot (d \div g)}$, with $g = \gcd(a, d)$ and $h = \gcd(c, b)$ | $O(n^2)$ |
| Zero numerator | $a = 0$ or $c = 0$ | the zero factor | $O(n)$ |
| Reciprocals | $c = \pm b$ and $d = \pm a$ | $\dfrac{1}{1}$ | $O(n)$ |
| Factor of $\pm 1$ | $a = \pm b$, or $c = \pm d$ | $\dfrac{\pm c}{d}$, or $\dfrac{\pm a}{b}$ | $O(n)$ |
| Cross match | $c = \pm b$, or $d = \pm a$ | $\dfrac{\pm a}{d}$, reduced, or $\dfrac{\pm c}{b}$, reduced | $O(n^2)$ |
| Shared part | $d = b$, or $c = \pm a$ | $\dfrac{a \cdot c}{b \cdot d}$ | $O(n^2)$ |

Reciprocals come before cross matches, as in section 1, so that they skip the gcd.

```text
FUNCTION multiply(x, y)
    LET a = numerator(x)
    LET b = denominator(x)
    LET c = numerator(y)
    LET d = denominator(y)
    IF a = 0 THEN RETURN x
    IF c = 0 THEN RETURN y
    IF (c = b AND d = a) OR (c = −b AND d = −a) THEN RETURN 1 / 1
    IF a = b THEN RETURN y
    IF a = −b THEN RETURN (−c) / d
    IF c = d THEN RETURN x
    IF c = −d THEN RETURN (−a) / b
    IF c = b THEN RETURN reduce(a, d)
    IF c = −b THEN RETURN reduce(−a, d)
    IF d = a THEN RETURN reduce(c, b)
    IF d = −a THEN RETURN reduce(−c, b)
    IF d = b OR c = a OR c = −a THEN RETURN (a · c) / (b · d)
    LET g = gcd(a, d)
    LET h = gcd(c, b)
    RETURN ((a ÷ g) · (c ÷ h)) / ((b ÷ h) · (d ÷ g))
END FUNCTION
```

### 2.7 Division

#### Reducing the naive result

The naive quotient is reduced after the zero-divisor check. Here `reduce` also settles the sign, since $b \cdot c$ is negative when $c$ is:

$$
\frac{a}{b} \div \frac{c}{d} = \frac{a \cdot d}{b \cdot c}, \text{ reduced}, \qquad c \neq 0.
$$

```text
FUNCTION divide(x, y)
    LET a = numerator(x)
    LET b = denominator(x)
    LET c = numerator(y)
    LET d = denominator(y)
    IF c = 0 THEN ERROR "division by zero"
    RETURN reduce(a · d, b · c)
END FUNCTION
```

The cost is $O(n^2)$.

#### Dividing out first

Dividing by $\frac{c}{d}$ is multiplying by $\frac{d}{c}$, so the method for multiplication applies with $d$ and $c$ in place of $c$ and $d$. The cross gcds become $g = \gcd(a, c)$ and $h = \gcd(b, d)$:

$$
\frac{a}{b} \div \frac{c}{d} = \frac{(a \div g) \cdot (d \div h)}{(b \div h) \cdot (c \div g)}, \text{ sign settled}.
$$

The sign needs settling because $c$, and so the denominator, can be negative.

```text
FUNCTION divide(x, y)
    LET a = numerator(x)
    LET b = denominator(x)
    LET c = numerator(y)
    LET d = denominator(y)
    IF c = 0 THEN ERROR "division by zero"
    LET g = gcd(a, c)
    LET h = gcd(b, d)
    LET p = (a ÷ g) · (d ÷ h)
    LET q = (b ÷ h) · (c ÷ g)
    IF q < 0 THEN RETURN (−p) / (−q)
    RETURN p / q
END FUNCTION
```

*Example.* In $\frac{4}{9} \div \frac{-8}{3}$, $g = \gcd(4, -8) = 4$ and $h = \gcd(9, 3) = 3$, so $p = 1 \cdot 1 = 1$ and $q = 3 \cdot (-2) = -6$. The result is $\frac{-1}{6}$.

The cost is $O(n^2)$, the same order.

#### Special cases

The cases mirror those of multiplication, with the divisor turned upside down.

If the dividend's numerator is zero, the quotient is zero, and the dividend $\frac{0}{1}$ is the answer.

Because every value has exactly one reduced form, two values are equal exactly when their stored integers are equal. So $b = d$ and $a = c$ catches every quotient of equal values, which is $1$. Likewise $b = d$ and $a = -c$ catches every quotient of opposite values, which is $-1$.

If the divisor is $\pm 1$, that is $c = \pm d$, the quotient is the dividend, with its numerator negated for $-1$. If the dividend is $\pm 1$, that is $a = \pm b$, the quotient is $\frac{\pm d}{c}$, the reciprocal of the divisor, negated for $-1$, with its sign settled.

A shared part, a shared numerator up to sign, $c = \pm a$, or a shared denominator, $d = b$, still cancels exactly, and leaves one reduction:

$$
\frac{a}{b} \div \frac{\pm a}{d} = \frac{\pm d}{b}, \text{ reduced},
\qquad
\frac{a}{b} \div \frac{c}{b} = \frac{a}{c}, \text{ reduced}.
$$

*Example.* $\dfrac{5}{6} \div \dfrac{5}{4} = \dfrac{4}{6}$, which reduces to $\dfrac{2}{3}$.

The most useful new case is a cross match, $c = \pm b$. Then $\gcd(a, c) = \gcd(a, b) = 1$ and $\gcd(b, d) = \gcd(c, d) = 1$, so both gcds of the general method are known to be $1$, and the naive quotient is already reduced once its sign is settled:

$$
\frac{a}{b} \div \frac{\pm b}{d} = \frac{\pm a \cdot d}{b \cdot b}.
$$

This needs no gcd at all.

*Example.* $\dfrac{2}{3} \div \dfrac{3}{5} = \dfrac{2 \cdot 5}{3 \cdot 3} = \dfrac{10}{9}$.

The cross match the other way round, $d = \pm a$, mirrors the shared numerator of multiplication: dividing by $\frac{c}{d}$ is multiplying by $\frac{d}{c}$, whose numerator $d$ is then shared with $a$ up to sign. Now $\gcd(a, c) = \gcd(d, c) = 1$ and $\gcd(b, d) = \gcd(b, a) = 1$, so again both gcds are known to be $1$, and the naive quotient is already reduced once its sign is settled:

$$
\frac{a}{b} \div \frac{c}{\pm a} = \frac{a \cdot d}{b \cdot c}, \text{ sign settled}.
$$

This needs no gcd either.

*Example.* $\dfrac{-3}{4} \div \dfrac{-5}{3} = \dfrac{(-3) \cdot 3}{4 \cdot (-5)} = \dfrac{-9}{-20}$, and settling the sign gives $\dfrac{9}{20}$.

| Case | Condition | Result | Cost |
|---|---|---|---|
| General | $c \neq 0$ | $\dfrac{(a \div g) \cdot (d \div h)}{(b \div h) \cdot (c \div g)}$, sign settled, with $g = \gcd(a, c)$ and $h = \gcd(b, d)$ | $O(n^2)$ |
| Zero dividend | $a = 0$ | $\dfrac{a}{b}$ | $O(n)$ |
| Equal or opposite values | $b = d$ and $a = \pm c$ | $\dfrac{\pm 1}{1}$ | $O(n)$ |
| Divisor $\pm 1$ | $c = \pm d$ | $\dfrac{\pm a}{b}$ | $O(n)$ |
| Dividend $\pm 1$ | $a = \pm b$ | $\dfrac{\pm d}{c}$, sign settled | $O(n)$ |
| Shared part | $c = \pm a$, or $d = b$ | $\dfrac{\pm d}{b}$, reduced, or $\dfrac{a}{c}$, reduced | $O(n^2)$ |
| Cross match | $c = \pm b$ | $\dfrac{\pm a \cdot d}{b \cdot b}$ | $O(n^2)$ |
| Cross match, other way | $d = \pm a$ | $\dfrac{a \cdot d}{b \cdot c}$, sign settled | $O(n^2)$ |

The zero-divisor check stays first. Equal and opposite values come before a shared numerator, which would otherwise catch them with a needless gcd.

```text
FUNCTION divide(x, y)
    LET a = numerator(x)
    LET b = denominator(x)
    LET c = numerator(y)
    LET d = denominator(y)
    IF c = 0 THEN ERROR "division by zero"
    IF a = 0 THEN RETURN x
    IF b = d AND a = c THEN RETURN 1 / 1
    IF b = d AND a = −c THEN RETURN (−1) / 1
    IF c = d THEN RETURN x
    IF c = −d THEN RETURN (−a) / b
    IF a = b AND c > 0 THEN RETURN d / c
    IF a = b THEN RETURN (−d) / (−c)
    IF a = −b AND c > 0 THEN RETURN (−d) / c
    IF a = −b THEN RETURN d / (−c)
    IF c = a THEN RETURN reduce(d, b)
    IF c = −a THEN RETURN reduce(−d, b)
    IF d = b THEN RETURN reduce(a, c)
    IF c = b THEN RETURN (a · d) / (b · b)
    IF c = −b THEN RETURN (−(a · d)) / (b · b)
    IF (d = a OR d = −a) AND c > 0 THEN RETURN (a · d) / (b · c)
    IF d = a OR d = −a THEN RETURN (−(a · d)) / (−(b · c))
    LET g = gcd(a, c)
    LET h = gcd(b, d)
    LET p = (a ÷ g) · (d ÷ h)
    LET q = (b ÷ h) · (c ÷ g)
    IF q < 0 THEN RETURN (−p) / (−q)
    RETURN p / q
END FUNCTION
```
