# Signed Integers with a Header: Specification v0.1

Nov 1, 2026, revised after review the same day · The author's decisions of that day; others marked **(coordinator's call)**. Reviewed in [`review-v0.1.md`](review-v0.1.md). Nothing is built or run.

## 1. Representation

A number is an **8-bit header** and a **64-bit word**, kept in two parallel lists so the header is never padded.

- **Header:** bits 0–4 class code $c$; bit 5 spare, 0; bits 6–7 direction $d$, a counter mod 4 for $1, i, -1, -i$ (paper v0.7, §2.3).
- **Word:** unsigned. For $c = 0$ it is the magnitude. For $c = 1..31$ it is a **slot index** into the pool of width $2^{c+6}$ bits, words lowest first.
- **Canonical:** the smallest class that holds the value; zero is header 0, word 0.
- **Scope:** CPU, $W = 64$; the little-endian layout reads as 32-bit halves, but nothing at $W = 32$ runs. No GPU (none to test on). Integers use only $d = 0, 2$; sums across axes are a later spec, reported as an error (zero has no axis).

## 2. Builds

Nim 2.2.14 with spec 12's flags.

1. **Control:** spec 12's **Growing** ([`../12-integers/v0.1.md`](../12-integers/v0.1.md) §1.4) with the same header list and direction rules. Its class bits are unused; its word points to Growing's block.
2. **Header:** §1.

**Shared routines.** Growing's routines are refactored once for both builds: each writes into a caller-given destination with room for one extra word; absolute difference returns its final borrow; gcd never writes past its destination. Control wraps them with `malloc`, Header with a slot.

## 3. Operations

Add, subtract, multiply, exact division, gcd and compare run on **every build and job, no exceptions**.

**Header arithmetic** on 8 bits, $D = \texttt{0xC0}$, then OR in the result class:
- multiply `(h1 and D) + (h2 and D)`; divide `(h1 and D) - (h2 and D)`; negate `h xor 0x80`;
- add, equal directions: $m_1 + m_2$, direction `h1 and D`;
- add, opposite: $\lvert m_1 - m_2 \rvert$ with borrow $b$ ($m_1 < m_2$), direction `(h1 and D) + (b shl 7)`;
- subtract adds the negation; gcd has direction 0; a zero result is header 0.

**Compare:** if directions differ, $d = 0$ is larger; both 0, compare magnitudes; both 2, compare magnitudes and reverse. Magnitudes compare by class, then words.

**Operands** are passed at their real length: the inline word (length 0 for zero), or the slot up to its top nonzero word. Growing's routines take unequal lengths; nothing is widened.

**Result class.** With $L = \max(c_1, c_2)$: equal-direction add $L+1$; opposite add $L$; multiply $L+1$; division $c_1$; gcd $\min(c_1, c_2)$, or the other's class if one is zero. Allocate that slot, compute, then move the result to the smallest class that holds it (possibly 0) and release the slot. A predicted class above 31 is an error.

**Pools.** Per class: base, capacity, next unused, free-list head. The owner releases explicitly (values are immutable): a slot goes onto the free list, linked through freed slots' first words, ended by all ones. Allocation pops the free list, else takes the next slot, else doubles the pool (one slot at first use) **(coordinator's call)**. Indices survive growth, pointers do not, so the result slot is allocated first. Pools never shrink.

**Structures** (rule 4): stored, the slot; temporary, the predicted slot on a move-down; local, Growing's buffer in division and gcd. The parallel lists count as one structure, pending the author (§6).

**Special cases**, named, not built: (a) a class-0 × class-0 result held in registers, taking a slot only if its high word is nonzero; (b) equal-direction add allocating class $L$ and moving up only on a carry.

## 4. Operands

One seeded generator, 1024 operations per operation and job.
- **Jobs:** $k \in \{1, 2, 4, 8, 16\}$ words, bit lengths uniform from $32k+1$ to $64k$, so rounding to the class width shows against Control.
- **Directions:** $\pm 1$, each 1/2.
- **Division and gcd:** as spec 12 ($a = bq$; $a = gx$, $b = gy$; factors at half size). Divisors are nonzero.
- **Growth workload** (not a job): 64 chains of 32 steps $x \leftarrow x y + z$ from a one-word $x$, with $y \ne 0$, $z$ signed one-word values; intermediates released; timed per step. It exercises pool growth, release and reuse **(coordinator's call)**.

## 5. Measures

For **every build × operation × job** and the workload: time per operation; bytes per value (accounted, heap beside); peak bytes per operation. Unused pool capacity, a doubling's copy included, is reported apart. Results are released outside the clock, except in the workload.

**Correctness:** every result against Python's exact value and against Control; each Header result also in canonical form (smallest class, zero as header 0 word 0, spare bit 0).

**Timing:** spec 12's method, unchanged. Comparisons are Header × Control only.

**Known costs**, from Header × Control and callgrind: rounding up (to 2× on add, 4× on multiply); pool management (callgrind's share in pool routines, move-downs per operation; job 1 uses pools too, for long products and carries); the extra memory read per pool number; the opposite-direction branches.
