# Signed Integers with a Header: Specification v0.1

Nov 1, 2026 · The author's decisions of that day; small calls marked **(coordinator's call)**. Reviewed in [`review-v0.1.md`](review-v0.1.md).

**Superseded by [v0.2](v0.2.md)** (one word, the notes' designs). This version's builds, tests and results are in [`archive/`](archive/).

Two designs, A and B, go through **round 1** (correctness) and, if it passes, **round 2** (speed and memory), each against Control.

## 1. Shared parts

- **Magnitudes:** unsigned. A 5-bit class code $c$: $c = 0$, the word is the magnitude; $c = 1..31$, the word is a **slot index** into the pool whose slots are $2^c$ words, lowest first. Little-endian (readable as 32-bit halves). Zero is class 0, word 0. Canonical: the smallest class that holds it.
- **Routines:** schoolbook, carries and borrows as values ($s < x$): add; multiply-accumulate ($r \mathrel{+}= xy$); absolute difference with its borrow; compare; Hensel exact division; binary gcd. Each reads operands at their real length $n$ (up to the top nonzero word), writes at most its bound, zeroes the rest of its slot, and returns the result's length. Bounds: add $\max + 1$; multiply-accumulate $\max(n_r, n_1 + n_2)$, plus a carry word only when nonzero; absolute difference $\max$; division exactly $n_1 - n_2 + 1$, the last possibly an extra zero word, reading dividend words past its current length as 0; gcd $\min(n_1, n_2)$, or the nonzero operand's length if one is zero; $\gcd(0, 0)$ is an error.
- **Result class:** the smallest class holding the bound; A multiply $n_1 + n_2$, each B part $\max(n_a + n_b, n_c + n_d) + 1$ for its $ab + cd$; class 0 is a one-word local that becomes the inline word. A result that fits a smaller class moves there (zero-filled) and the slot is released. A class above 31 is an error.
- **Pools:** the owner releases a value explicitly (values are immutable), pushing its slot onto the pool's free list, linked through freed slots' first words and ended by all ones; so a pool holds at most $2^W - 1$ slots. Allocation pops the free list, else takes the next slot, else doubles the pool, from one slot at first use **(coordinator's call)**. Result slots are allocated first, since growth moves pointers but not indices; a move-down allocates too, so pointers are taken again after one.
- **Operations:** add, subtract, negate, multiply, exact division, gcd, compare. Negate copies a pool number into a new slot, so no two numbers share one.

## 2. Design A: magnitude and direction

A number is an **8-bit header** (bits 0–4 class, bit 5 spare 0, bits 6–7 direction $d$ mod 4 for $1, i, -1, -i$) and a **word**, in two parallel lists. Its mathematics is in [`../../book/notes-designs-a-b.md`](../../book/notes-designs-a-b.md), Design A. **Canonical:** smallest class, spare bit 0; a zero keeps whatever direction its operation gives.

**Header arithmetic** on 8 bits, $D = \texttt{0xC0}$, then OR in the result class: multiply `(h1 and D) + (h2 and D)`; divide `(h1 and D) - (h2 and D)`; negate `h xor 0x80`; gcd direction 0.

**Add**, the notes' tree, with `t = (h1 xor h2) and D`: $t = 0$, $m_1 + m_2$ in direction `h1 and D`; $t = \texttt{0x80}$, absolute difference with borrow $b$, direction `(h1 and D) + (b shl 7)`; otherwise (different axes), a zero operand takes the other's direction and the add runs as same-direction, and two nonzero operands are an error (an expression). There is no other zero test. **Subtract** is add with `h2 xor 0x80`.

**Compare:** numbers are ordered along their shared axis, with 1 and $i$ positive; zero lies on both. Two zeros are equal; with one zero, the other's sign decides; otherwise opposite directions put the positive one first, and the same direction compares magnitudes, reversed when negative. Different axes are not ordered (an error).

## 3. Design B: one magnitude per direction

A number is a pair $(P, N)$ along $+1$ and $-1$, value $P - N$. **Header:** 16 bits, $P$'s class in the low byte and $N$'s in the high byte, 3 spare bits 0 in each; two words, $P$'s then $N$'s **(coordinator's call)**.

- **Negate:** swap $P$ and $N$. **Subtract:** $(P_1 + N_2, N_1 + P_2)$. **Add:** $(P_1 + P_2, N_1 + N_2)$.
- **Multiply:** $P = P_1P_2 + N_1N_2$, $N = P_1N_2 + N_1P_2$, by multiply-accumulate.
- **Compare:** $P_1 + N_2$ against $P_2 + N_1$.
- **Collapse**, the only subtraction: $\lvert P - N \rvert$ goes to $P$ when the borrow is 0, else to $N$; the other part is 0. Division and gcd collapse into their working buffer, then follow A's direction rules; output collapses only when a single value is needed. B is canonical only after collapse.

**Structures** (rule 4): stored, the slot (A) or up to two slots (B); temporary, a slot on a move-down; local, the one-word local, B's compare sums, or the working buffer in division and gcd.

**Special cases**, named, not built: (a) a class-0 × class-0 product in registers; (b) an add allocating the class that holds $\max$ words, moving up only on a carry.

## 4. Round 1: correctness

Proofs use Lean core only (no Mathlib) for now; builds use no outside libraries (rule 5).

- **Proved in Lean 4** ([`lean/`](lean/)), for all values: each rule of §2 and §3 gives the true result for every operation (A's value $m \cdot i^d$, any zero equal to any zero; B's $P - N$, and B's four-slot form against Gaussian integers, sums across axes included). Also, for any word size and any lengths: multi-word add with its carry, absolute difference with its borrow, and the write bounds.
- **Tested in Python** ([`test/`](test/), word by word at $W = 4$): Hensel division, binary gcd, and the bookkeeping (headers, classes, pools, free lists, canonical form). Sets: every pair of signed values below $2^8$, zero in directions 0 and 2; for B, every pair of uncollapsed values with parts below $2^4$; 100,000 random pairs per operation, up to 8 words, zeros and equal magnitudes at 1/16; division on $a = bq$, divisor nonzero **(coordinator's call)**. It passes when values match (zeros by value, not header), results are canonical, and after all releases every slot is free.

## 5. Round 2: speed and memory

Control (spec 12's Growing, [`../12-integers/v0.1.md`](../12-integers/v0.1.md) §1.4, with A's header list), A and B, written as portable pseudocode (algorithm design rule 6), then x86-64 machine code. Integers only.

- **(a) Counts, proved in Lean:** the pseudocode is a small instruction set defined in Lean, each step one instruction on every family. Per path through each operation: instructions, branches, loads and stores, as formulas in the operand lengths, with a proof that the paths cover every input. A table maps each step to its x86-64, ARM64 and RISC-V instructions, checked against the disassembly of the built code. Cycle predictions use uops.info's x86-64 latencies and throughputs, as claims about that model.
- **(b) Branch inventory** (written): every branch each design uses, its condition, and when it is predictable.
- **(c) Timed trials**, spec 12's method, against Control: every operation on every build at $k \in \{1, 2, 4, 8, 16\}$ words, 1024 operations each, under each sign mix (all positive, mostly one sign, random) and magnitude-order mix; division on $a = bq$, $b \ne 0$. One branch-free row, for A only: its sign and borrow branches replaced by masks (`0 - b`, AND, XOR), loops over lengths kept. Conditional moves are not used: RV64I, the base, lacks them (whether RVA23 counts is the author's call). Time beyond what the counts predict is branch and cache cost; a large or consistent residual is a finding. Bytes per value are measured beside.
- **Growth workload** (not a job): 64 chains of 32 steps of $x \leftarrow x \cdot y + z$, with intermediates released, timed against Control; it exercises pool growth, release and reuse, which the jobs alone do not.

## 6. Decided (author, Nov 1, 2026)

No Inline build; pools never shrink in this round (to revisit with garbage collection); A's parallel lists are one stored structure; no mixed job; B's two slots are allowed, for testing; B collapses only at the required points.
